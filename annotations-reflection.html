1. Tổng quan & cách học

Hay hỏi phỏng vấn Junior+ Production

Mức độ bắt buộc của chủ đề 2.9 (phỏng vấn: cao · production: bắt buộc):

  • Phải làm được — đọc hiểu annotation trong codebase Spring/Jackson/JPA; tự định nghĩa annotation với @Retention/@Target; dùng reflection đọc field, gọi method, tạo object; phân biệt getDeclared... và get...; tự viết validator mini đọc annotation lúc runtime.
  • Phải hiểu — annotation là dữ liệu thụ động, phải có reader (compiler, framework, tool); retention quyết định annotation sống tới đâu; reflection đi qua đối tượng Class; setAccessible(true) phá encapsulation và bị JPMS chặn với class của JDK; generic bị erasure nên runtime không giữ List<String>; reflection chậm hơn gọi trực tiếp.
  • Nhận biết — annotation processor chạy lúc compile (Lombok, MapStruct); dynamic proxy dùng cho AOP (@Transactional); bytecode manipulation (ASM, ByteBuddy); MethodHandle/VarHandle là lối thoát hiệu năng cho reflection; JEP 512 compact source file là cú pháp JDK 25 học ở 1.5 Methods.

Vì sao nói "annotation không tự làm gì"? Hãy tưởng tượng annotation như tờ giấy nhớ dán lên hộp hàng: tờ giấy không tự di chuyển hộp. Việc "đọc rồi xử lý" do người khác làm:

  • @Override — do compiler đọc; sai là báo lỗi ngay khi build.
  • @Deprecated — do javac và IDE đọc để cảnh báo/gạch ngang.
  • @Autowired, @Transactional — do Spring đọc bằng reflection lúc khởi động.
  • @JsonProperty — do Jackson đọc bằng reflection khi serialize/deserialize.
  • @Entity, @Column — do Hibernate/JPA đọc để sinh câu SQL.

2. Built-in annotations — annotation có sẵn của Java Junior+

JDK có sẵn một bộ annotation nhỏ dùng hằng ngày. Điểm đáng chú ý: retention khác nhau — @Override/@SuppressWarnings là SOURCE (chỉ compiler đọc), còn @Deprecated/@FunctionalInterface/@SafeVarargs là RUNTIME (đọc được cả lúc chạy). Đây là bằng chứng rõ nhất cho câu "annotation cần người đọc".

Ví dụ dùng @Override và @Deprecated. Lưu ý @Deprecated vẫn chạy được — nó chỉ là lời cảnh báo, không xóa code:

public class Order {
    @Override

    static void inKieuCu() {
        IO.println("ham cu van chay");
    }

    public static void main() {
        IO.println(new Order());
        inKieuCu();
    }
}

Đây là ví dụ hoàn hảo của "annotation không tự làm gì, nhưng cho người khác làm".

@FunctionalInterface — chốt hợp đồng cho lambda

Annotation này không bắt buộc (interface một abstract method vẫn dùng được với lambda), nhưng nó biến ý định thiết kế thành lỗi compile nếu ai đó vô tình thêm method thứ hai:

@SafeVarargs & @SuppressWarnings

@SafeVarargs dùng khi viết method nhận varargs có generic — compiler thường cảnh báo "Possible heap pollution". Bạn cam kết method không ghi sai kiểu vào mảng. Annotation này chỉ hợp lệ trên method static, final, private (từ Java 9) hoặc constructor:

import java.util.*;

@SafeVarargs
static <T> List<T> gop(T... items) {
    List<T> ketQua = new ArrayList<>();
    for (T item : items) {
        ketQua.add(item);
    }
    return ketQua;
}

void main() {
    IO.println(gop("a", "b", "c"));
    IO.println(gop(1, 2, 3));
}
[a, b, c]
[1, 2, 3]

@SuppressWarnings cũng chạy lúc compile: nó tắt một loại cảnh báo cụ thể ("unchecked", "deprecation", "rawtypes"...). Nguyên tắc production: đặt ở phạm vi hẹp nhất (biến local nếu được), luôn kèm comment lý do. Ví dụ thật ở mục 7 khi bị erasure buộc phải cast (List<String>).

3. Tự định nghĩa annotation với @interface Hay hỏi phỏng vấn

Annotation bạn dùng hằng ngày đều do người khác định nghĩa y như cách này: một interface đặc biệt khai báo bằng @interface. Mỗi "element" trông như method nhưng thực chất là một khóa dữ liệu, có thể kèm giá trị mặc định bằng default.

[public] @interface TenAnnotation { kieu tenElement() default giaTri; }

Ba dạng annotation bạn sẽ gặp:

  • Marker annotation — không có element nào, chỉ đánh dấu "có mặt": @NotEmpty.
  • Single-value annotation — chỉ có một element tên là value(), được viết tắt: nếu Range chỉ có int value() thì @Range(18) tương đương @Range(value = 18).
  • Multi-element annotation — nhiều element, có thể có default: @Range(min = 18, max = 120) (bỏ được max nếu nó có default).

Ví dụ đầu tiên — chú ý annotation phải có @Retention(RUNTIME) thì reflection mới thấy (giải thích ở mục 4):

import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotEmpty {}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Range {
    int min() default 0;
    int max() default 100;
}

record UserForm(@NotEmpty String email, @Range(min = 18) int age) {}

void main() throws Exception {
    IO.println("NotEmpty co mat: "
            + UserForm.class.getDeclaredField("email").isAnnotationPresent(NotEmpty.class));
    Range r = UserForm.class.getDeclaredField("age").getAnnotation(Range.class);
    IO.println("Range: min=" + r.min() + ", max=" + r.max() + " (max lay mac dinh)");
}
NotEmpty co mat: true
Range: min=18, max=100 (max lay mac dinh)

Element nhận những kiểu dữ liệu nào?

Chỉ được dùng: primitive (int, boolean...), String, Class, enum, annotation khác, và mảng của các kiểu đó. Không được để giá trị null, không dùng generic. Xem toàn bộ kiểu trong một annotation thật:

import java.lang.annotation.*;

enum OrderStatus { MOI, DANG_GIAO, XONG }

@Retention(RetentionPolicy.RUNTIME)
@interface Range {
    int min() default 0;
    int max() default 100;
    String donVi() default "tuoi";
    boolean batBuoc() default false;
    Class<?> kieu() default Integer.class;
    OrderStatus trangThai() default OrderStatus.MOI;
    String[] tags() default {};
}

@Range
class UserForm {}

void main() {
    Range r = UserForm.class.getAnnotation(Range.class);
    IO.println("min      : " + r.min());
    IO.println("donVi    : " + r.donVi());
    IO.println("kieu     : " + r.kieu().getSimpleName());
    IO.println("trangThai: " + r.trangThai());
    IO.println("tags     : " + r.tags().length);
    IO.println("batBuoc  : " + r.batBuoc());
}
min      : 0
donVi    : tuoi
kieu     : Integer
trangThai: MOI
tags     : 0
batBuoc  : false
Annotation type không được khai báo extends/implements — nó ngầm extends java.lang.annotation.Annotation; mọi element không có tham số và không throws. Nếu annotation chỉ để compiler/tool dùng (như @Override), đặt @Retention(SOURCE) cho gọn bytecode.

4. @Retention, @Target & các meta-annotation Hay hỏi phỏng vấn

Meta-annotation là annotation gắn lên chính annotation — quy định vòng đời và vị trí sử dụng của nó. Đây là phần bị hỏi nhiều nhất khi phỏng vấn về annotation.

@Retention — annotation sống tới đâu?

RetentionPolicyCompiler giữ ở đâuAi đọc đượcVí dụ
SOURCEChỉ trong source code, bị xóa khi biên dịchCompiler, annotation processor@Override, @SuppressWarnings, Lombok
CLASS (mặc định)Lưu trong file .class nhưng JVM không nạp cho reflectionBytecode tool (ASM, javap)Đa số annotation nội bộ không dùng reflection
RUNTIMELưu trong .class và JVM giữ lạiReflection, framework lúc chạySpring, Jackson, JPA, @Deprecated

Quên khai báo @Retention là mặc định CLASS — compiler thấy nhưng reflection không thấy. Đây là lỗi kinh điển khi tự viết annotation. Chạy thật để thấy:

import java.lang.annotation.*;

@interface NotEmpty {}          // khong khai bao @Retention -> mac dinh CLASS

@Retention(RetentionPolicy.RUNTIME)
@interface Range {
    int min() default 0;
}

@NotEmpty
@Range(min = 18)
class UserForm {}

void main() {
    IO.println("NotEmpty (CLASS) : " + (UserForm.class.getAnnotation(NotEmpty.class) != null));
    IO.println("Range (RUNTIME)  : " + (UserForm.class.getAnnotation(Range.class) != null));
}
NotEmpty (CLASS) : false
Range (RUNTIME)  : true

@Target — được gắn vào đâu?

@Target nhận danh sách ElementType. Không khai báo @Target thì mặc định gắn được ở mọi declaration context — kể cả type parameter, module, record component — nhưng không gắn được ở type context (chỗ cần TYPE_USE).

Đặt sai chỗ là lỗi compile ngay:

@Range(min = 18, max = 120)
^

Annotation TYPE_USE không đọc bằng element.getAnnotation(...) (sẽ trả null) mà phải đi qua getAnnotatedType(): ví dụ field.getAnnotatedType().getAnnotation(KhongNull.class) mới thấy annotation gắn trên kiểu.

@Inherited — kế thừa annotation

Mặc định annotation trên class cha không xuất hiện trên class con. Thêm @Inherited (chỉ dùng được với TYPE) để bật kế thừa — Spring rất thích cơ chế này:

import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
@Inherited
@interface Range {
    int min() default 0;
    int max() default 100;
}

@Range(min = 18, max = 120)
class Order {}

class UserForm extends Order {}

void main() {
    IO.println("Order    : " + (Order.class.getAnnotation(Range.class) != null));
    IO.println("UserForm : " + (UserForm.class.getAnnotation(Range.class) != null));
}
Order    : true
UserForm : true
Phân biệt với API "declared": getAnnotations()/getAnnotation() gồm cả annotation kế thừa qua @Inherited, còn getDeclaredAnnotations()/getDeclaredAnnotation() chỉ trả annotation khai báo trực tiếp trên element đó.

@Repeatable — gắn nhiều lần (Java 8)

Trước Java 8, mỗi annotation chỉ gắn một lần. Từ Java 8, khai báo @Repeatable trỏ tới một annotation "container" chứa mảng. Compiler tự bọc khi bạn gắn nhiều lần:

import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@Repeatable(Ranges.class)
@interface Range {
    int min() default 0;
    int max() default 100;
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Ranges {
    Range[] value();
}

@Range(min = 0, max = 10)
@Range(min = 100, max = 200)
class Order {}

void main() {
    Range[] ds = Order.class.getAnnotationsByType(Range.class);
    IO.println("so Range tren Order: " + ds.length);
    for (Range r : ds) {
        IO.println("khoang: " + r.min() + "-" + r.max());
    }
}
so Range tren Order: 2
khoang: 0-10
khoang: 100-200

Nhớ dùng getAnnotationsByType(Range.class) — còn getAnnotation(Range.class) sẽ trả null vì trên class thật ra chỉ có container @Ranges.

@Documented là meta-annotation còn lại đáng biết: nó chỉ yêu cầu Javadoc hiển thị annotation này trong tài liệu API. Không ảnh hưởng runtime.

5. Reflection API cơ bản — soi class lúc runtime Hay hỏi phỏng vấn

Reflection là khả năng của chương trình Java tự nhìn vào chính mình lúc đang chạy: biết class nào có field gì, method gì, gọi chúng, tạo object mới — kể cả khi mọi thứ chỉ được quyết định lúc runtime. Điểm vào của toàn bộ API là đối tượng java.lang.Class.

Có ba cách lấy Class, cả ba trả về cùng một object (JVM chỉ có một Class cho mỗi class loader):

public class UserForm {
    private String email = "an@example.com";

    public static void main() throws Exception {
        Class<?> c1 = UserForm.class;                 // tu class literal
        Class<?> c2 = new UserForm().getClass();      // tu object dang song
        Class<?> c3 = Class.forName("UserForm");      // tu ten day du (binary name)

        IO.println("c1 == c2: " + (c1 == c2));
        IO.println("c2 == c3: " + (c2 == c3));
        IO.println("getName   : " + c1.getName());
        IO.println("simpleName: " + c1.getSimpleName());
        IO.println("package   : [" + c1.getPackageName() + "]");
    }
}

Chi tiết hay hỏi: Class.forName("X") tương đương forName("X", true, loader) — khởi tạo class (chạy static initializer) nếu chưa; muốn chỉ load mà không khởi tạo, dùng Class.forName("X", false, loader) hoặc ClassLoader.loadClass(...).

Khi đã có Class, bạn liệt kê được mọi thành phần khai báo bên trong. Vì thứ tự field/method do JVM trả về không được đảm bảo, ví dụ sort theo tên để output ổn định:

import java.lang.reflect.*;
import java.util.*;

public class UserForm {
    private String email;
    private int age;

    public UserForm(String email, int age) {
        this.email = email;
        this.age = age;
    }

    public String moTa() {
        return email + " (" + age + ")";
    }

    private String biMat() {
        return "goi duoc method private!";
    }

    public static void main() throws Exception {
        UserForm form = new UserForm("an@example.com", 25);
        Class<?> c = form.getClass();

        Field[] fields = c.getDeclaredFields();
        Arrays.sort(fields, Comparator.comparing(Field::getName));
        IO.println("-- fields khai bao trong class --");
        for (Field f : fields) {
            IO.println(f.getType().getSimpleName() + " " + f.getName()
                    + " (" + Modifier.toString(f.getModifiers()) + ")");
        }

        Method[] methods = c.getDeclaredMethods();
        Arrays.sort(methods, Comparator.comparing(Method::getName));
        IO.println("-- methods khai bao trong class --");
        for (Method m : methods) {
            IO.println(m.getReturnType().getSimpleName() + " " + m.getName());
        }

        Method biMat = c.getDeclaredMethod("biMat");
        biMat.setAccessible(true);
        IO.println("invoke: " + biMat.invoke(form));
    }
}

getDeclared... vs get...: getDeclaredFields() trả mọi mức truy cập (private, protected, package, public) nhưng chỉ của class hiện tại — không gồm field kế thừa. getFields() chỉ trả field public nhưng gồm cả của class cha và interface. Quy tắc y hệt cho getDeclaredMethods()/getMethods(), constructor cũng vậy. Muốn soi trọn vẹn một class, hãy đi ngược cây kế thừa với getDeclaredFields() ở từng cấp.

6. Đọc annotation lúc runtime — validator đầu tiên Junior+

Giờ ghép hai mảnh: annotation cung cấp luật (@Range(min = 18, max = 120)), reflection là người đọc luật và kiểm tra dữ liệu. Đây chính là cách Hibernate Validator (@NotNull, @Min, @Size) hoạt động — bạn sẽ tự viết bản mini:

import java.lang.annotation.*;
import java.lang.reflect.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Range {
    int min() default 0;
    int max() default 100;
}

record UserForm(String email, @Range(min = 18, max = 120) int age) {}

void main() throws Exception {
    kiemTra(new UserForm("an@example.com", 15));
    kiemTra(new UserForm("binh@example.com", 25));
}

static void kiemTra(Object obj) throws Exception {
    for (Field f : obj.getClass().getDeclaredFields()) {
        Range r = f.getAnnotation(Range.class);
        if (r == null) {
            continue;
        }
        f.setAccessible(true);
        int value = f.getInt(obj);
        if (value < r.min() || value > r.max()) {
            IO.println("LOI " + f.getName() + " = " + value
                    + " ngoai khoang [" + r.min() + ", " + r.max() + "]");
        } else {
            IO.println("OK  " + f.getName() + " = " + value);
        }
    }
}
LOI age = 15 ngoai khoang [18, 120]
OK  age = 25

Bốn bước của mọi validator kiểu này:

  1. obj.getClass().getDeclaredFields() — quét toàn bộ field cần kiểm tra.
  2. f.getAnnotation(Range.class) — hỏi "field này có luật gì?". Annotation thiếu @Retention(RUNTIME) sẽ trả null ở bước này.
  3. f.setAccessible(true) rồi f.getInt(obj) — đọc giá trị field private.
  4. So với r.min()/r.max() và báo lỗi kèm ngữ cảnh.
Nếu bạn gọi f.getAnnotation(...) mà nhận null dù rõ ràng đã gắn annotation: kiểm tra @Retention(RUNTIME) trước tiên (mục 4), sau đó kiểm tra @Target và đúng field/method đang soi (annotation trên record component có thể nằm ở field, accessor hoặc parameter tuỳ @Target).

7. Reflection nâng cao — private, constructor, record Junior+

Constructor private & sửa field private

Class.newInstance() đã bị deprecate từ Java 9 (nó che mất exception thật). Cách đúng hiện nay là lấy constructor tường minh rồi gọi newInstance(). Với thành viên private, gọi setAccessible(true) trước:

import java.lang.reflect.*;

public class UserForm {
    private String email = "an@example.com";
    private int age = 25;

    private UserForm() {
    }

    public static void main() throws Exception {
        Constructor<UserForm> ctor = UserForm.class.getDeclaredConstructor();
        ctor.setAccessible(true);              // constructor dang private
        UserForm form = ctor.newInstance();
        IO.println("tao object: " + form.email);

        Field f = UserForm.class.getDeclaredField("age");
        f.setAccessible(true);                 // field dang private
        IO.println("truoc: " + f.getInt(form));
        f.setInt(form, 30);
        IO.println("sau  : " + f.getInt(form));
    }
}
tao object: an@example.com
truoc: 25
sau  : 30

Reflection cho phép bạn làm được những việc mà bình thường compiler cấm — đó là sức mạnh, và cũng là lý do phải dùng hết sức tiết chế. setAccessible(true) phá encapsulation: field final của instance cũng có thể bị ghi đè trong nhiều trường hợp, invariant của class bị phá vỡ. Từ Java 17+ có ngoại lệ: field final của record (trusted final) và hidden class vẫn ném IllegalAccessException dù đã gọi setAccessible(true). Chỉ dùng trong framework, thư viện serialize/deserialize, test utility — không dùng trong logic nghiệp vụ.

Record — getRecordComponents()

Record sinh ra để reflection "sạch" hơn hẳn: thay vì đoán field nào là component, JDK 16+ cung cấp metadata chính thức gồm tên, kiểu, accessor và cả generic type:

import java.lang.reflect.*;

record UserForm(String email, int age) {}

void main() {
    IO.println("la record: " + UserForm.class.isRecord());
    for (RecordComponent rc : UserForm.class.getRecordComponents()) {
        IO.println(rc.getName() + " : " + rc.getType().getSimpleName()
                + " | accessor: " + rc.getAccessor().getName());
    }
}
la record: true
email : String | accessor: email
age : int | accessor: age

Modifier & erasure của generic

Generic trong Java chỉ tồn tại lúc compile — javac xóa thông tin kiểu khi biên dịch (type erasure), nên JVM và reflection không thể ngăn ai đó nhét Integer vào List<String>. Đây vừa là giới hạn, vừa là cách để hiểu vì sao @SuppressWarnings("unchecked") tồn tại:

import java.lang.reflect.*;
import java.util.*;

public class Order {
    private final List<String> tags = new ArrayList<>();

    @SuppressWarnings("unchecked")
    public static void main() throws Exception {
        Field f = Order.class.getDeclaredField("tags");
        IO.println("getType()       : " + f.getType().getName());
        IO.println("getGenericType(): " + f.getGenericType().getTypeName());
        IO.println("modifier cua tags: " + Modifier.toString(f.getModifiers()));

        f.setAccessible(true);
        List<String> tags = (List<String>) f.get(new Order());
        Method add = List.class.getMethod("add", Object.class);
        IO.println("chen Integer duoc: " + add.invoke(tags, 123));
        IO.println("noi dung: " + tags);
    }
}
getType()       : java.util.List
getGenericType(): java.util.List<java.lang.String>
modifier cua tags: private final
chen Integer duoc: true
noi dung: [123]

Chú ý: getGenericType() vẫn đọc được java.util.List<java.lang.String> vì đó là thông tin ghi trong chữ ký field. Nhưng một object ArrayList đang sống không biết nó từng được khai báo với String hay Integer. Erasure được học đầy đủ ở 3.2 Generics.

JPMS — vì sao mở private của JDK bị chặn

Từ Java 9, module system (JPMS) đóng gói nội bộ JDK. Bạn vẫn mở được private field của class do mình viết (chạy trong unnamed module), nhưng mở ruột class của JDK như String sẽ bị chặn:

import java.lang.reflect.*;

public class UserForm {
    public static void main() throws Exception {
        try {
            Field f = String.class.getDeclaredField("value");
            f.setAccessible(true);
            IO.println("mo duoc");
        } catch (InaccessibleObjectException e) {
            IO.println("loai loi: " + e.getClass().getSimpleName());
            IO.println("bi chan boi JPMS: " + e.getMessage().contains("\"opens java.lang\""));
        }
    }
}
loai loi: InaccessibleObjectException
bi chan boi JPMS: true

Message thật có dạng: Unable to make field private final byte[] java.lang.String.value accessible: module java.base does not "opens java.lang" to unnamed module @... (phần hash @... đổi mỗi lần chạy). Nếu thực sự cần (ví dụ thư viện cũ), mở tường minh bằng cờ JVM — chạy thật sẽ in ra mo duoc:

java --add-opens java.base/java.lang=ALL-UNNAMED UserForm.java
Đừng lạm dụng --add-opens để "chữa cháy". Nó phá vỡ đóng gói của JDK, dễ vỡ khi nâng version, và thường là dấu hiệu thư viện đã cũ. Chỉ dùng khi không còn lựa chọn và ghi rõ lý do trong cấu hình build.

8. Mini framework — validator, DI & JSON serializer Production

Từ validator một annotation, nâng lên nhiều annotation. Điểm đáng học: vòng lặp xử lý trung tâm không cần biết nghiệp vụ cụ thể — nó chỉ hỏi "field này có annotation nào?" và áp luật tương ứng:

import java.lang.annotation.*;
import java.lang.reflect.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotEmpty {}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Range {
    int min();
    int max();
}

record UserForm(@NotEmpty String email, @Range(min = 18, max = 120) int age) {}

void main() throws Exception {
    kiemTra(new UserForm("", 15));
    kiemTra(new UserForm("an@example.com", 25));
}

static void kiemTra(Object obj) throws Exception {
    int loi = 0;
    for (Field f : obj.getClass().getDeclaredFields()) {
        f.setAccessible(true);
        Object value = f.get(obj);
        if (f.isAnnotationPresent(NotEmpty.class)
                && value instanceof String s && s.isBlank()) {
            IO.println("LOI " + f.getName() + ": khong duoc rong");
            loi++;
        }
        Range r = f.getAnnotation(Range.class);
        if (r != null && value instanceof Integer i
                && (i < r.min() || i > r.max())) {
            IO.println("LOI " + f.getName() + ": " + i
                    + " ngoai [" + r.min() + ", " + r.max() + "]");
            loi++;
        }
    }
    IO.println("ket qua: " + (loi == 0 ? "HOP LE" : loi + " loi"));
}
LOI email: khong duoc rong
LOI age: 15 ngoai [18, 120]
ket qua: 2 loi
ket qua: HOP LE

Hạn chế của cách viết "if từng annotation": mỗi annotation mới phải sửa vòng lặp trung tâm. Framework thật (Hibernate Validator) giải quyết bằng interface kiểu ConstraintValidator<A, T> — mỗi annotation có một validator riêng, framework chỉ dispatch. Đó là bước từ "mini" lên "framework".

Mini JSON serializer bằng record component

Cùng ý tưởng, áp cho serialize: quét component, gọi accessor, in ra JSON. Jackson làm đúng việc này nhưng tối ưu và cache cực kỹ:

import java.lang.reflect.*;

public class Order {
    record UserForm(String email, int age) {}

    public static void main() {
        IO.println(toJson(new UserForm("an@example.com", 25)));
    }

    static String toJson(Object obj) {
        StringBuilder sb = new StringBuilder("{");
        RecordComponent[] comps = obj.getClass().getRecordComponents();
        try {
            for (int i = 0; i < comps.length; i++) {
                if (i > 0) {
                    sb.append(", ");
                }
                Object value = comps[i].getAccessor().invoke(obj);
                sb.append('"').append(comps[i].getName()).append("\": ");
                if (value instanceof String s) {
                    sb.append('"').append(s).append('"');
                } else {
                    sb.append(value);
                }
            }
        } catch (ReflectiveOperationException e) {
            throw new RuntimeException(e);
        }
        return sb.append('}').toString();
    }
}
{"email": "an@example.com", "age": 25}

Ý tưởng mini-DI (dependency injection)

Spring khởi động theo trình tự mà bạn có thể tự mô phỏng: quét classpath tìm class có annotation @Component; với mỗi class, tìm constructor (hoặc field) đánh dấu cần inject; đệ quy tạo các dependency trước; gọi newInstance() truyền dependency vào. Spring thêm hàng trăm thứ quanh đó — vòng đời bean, proxy AOP, scope, circular dependency, lazy init — nhưng lõi vẫn là annotation + reflection + Constructor.newInstance.

Đừng tự viết framework. Reflection dễ làm cho "chạy được" nhưng rất khó làm cho đúng: xử lý exception, generic, proxy, thread-safety, hiệu năng, bảo mật. Hãy viết validator/serializer nhỏ cho bài tập học, còn production dùng thư viện đã được kiểm chứng.

9. Hiệu năng reflection Production

Reflection chậm hơn gọi method trực tiếp vì JIT khó tối ưu: phải kiểm tra quyền truy cập mỗi lần gọi, boxing tham số, không inline được, tra cứu metadata. Benchmark nhỏ — gọi 10 triệu lần qua Method.invoke so với gọi thẳng (sau khi đã warm up JIT):

import java.lang.reflect.*;

public class UserForm {
    static int dem = 0;

    static void tang() {
        dem++;
    }

    public static void main() throws Exception {
        Method m = UserForm.class.getDeclaredMethod("tang");
        m.setAccessible(true);

        for (int i = 0; i < 1_000_000; i++) {   // khoi dong JIT
            tang();
            m.invoke(null);
        }

        long t1 = System.nanoTime();
        for (int i = 0; i < 10_000_000; i++) {
            tang();
        }
        long t2 = System.nanoTime();
        for (int i = 0; i < 10_000_000; i++) {
            m.invoke(null);
        }
        long t3 = System.nanoTime();

        IO.println("goi truc tiep : " + (t2 - t1) / 1_000_000 + " ms");
        IO.println("qua reflection: " + (t3 - t2) / 1_000_000 + " ms");
        IO.println("cham hon 5 lan: " + ((t3 - t2) > 5 * (t2 - t1)));
        IO.println("dem = " + dem);
    }
}

Một lần chạy thật trên máy này (JDK 25) — con số thay đổi theo máy và tải hệ thống, nhưng tỉ lệ thì luôn đáng kể:

goi truc tiep : 1 ms
qua reflection: 23 ms
cham hon 5 lan: true
dem = 22000000

Chi phí đến từ: kiểm tra accessibility, boxing/unboxing tham số, không được JIT inline, tra cứu và tạo mảng argument. Kinh nghiệm production:

  • Cache Field/Method/Constructor — đừng getDeclaredMethod(...) mỗi request; gọi setAccessible(true) một lần rồi tái sử dụng.
  • Dùng ở startup, không dùng ở hot path: Spring quét bean, Jackson dựng mapper, JPA dựng metadata một lần lúc khởi động. Logic nghiệp vụ sau đó chạy trên object thường.
  • Trường hợp buộc phải gọi động với tần suất cao, tìm hiểu MethodHandle/LambdaMetafactory (nhanh hơn gần bằng gọi trực tiếp) — thuộc mức "nhận biết", không cần cho Junior+.
  • Trước khi tối ưu, đo đạc: reflection trên vài nghìn lần gọi mỗi request là quá đủ nhanh; chỉ đáng lo khi nằm trong vòng lặp hàng triệu lần.

13. Interview Q&A Hay hỏi phỏng vấn

Cơ bản

Câu 1. Annotation là gì? Vì sao nói nó "không tự làm gì"?
Annotation là metadata (dữ liệu mô tả) gắn lên class, field, method, parameter... Nó không chứa hành vi và không tự thực thi. Phải có "reader": compiler đọc @Override, javac/IDE đọc @Deprecated, Spring đọc @Autowired bằng reflection lúc khởi động, Jackson đọc @JsonProperty khi serialize. Bỏ reader đi thì annotation chỉ là dữ liệu vô hình.
Câu 2. Annotation khác comment thường ở điểm nào?
Comment bị compiler bỏ hoàn toàn, chỉ con người đọc. Annotation được compiler parse, kiểm tra hợp lệ theo @Target, lưu vào bytecode theo @Retention, và có thể đọc bằng reflection/framework/tool (IDE gạch ngang, javac warning, build tool xử lý forRemoval). Nói ngắn: annotation là comment mà máy đọc được.
Câu 3. @Override có tác dụng gì? Vì sao nó có retention SOURCE?
Nó bắt compiler xác nhận method thật sự override method từ cha/interface; gõ sai tên hoặc sai chữ ký sẽ là lỗi compile thay vì lỗi logic âm thầm. Retention SOURCE vì sau khi compiler kiểm tra xong thông tin này vô dụng — không cần lưu vào .class, tiết kiệm bytecode.
Câu 4. SOURCE, CLASS, RUNTIME khác nhau thế nào? Mặc định là gì?
SOURCE chỉ tồn tại trong source, compiler/tool đọc rồi bỏ; CLASS được ghi vào .class nhưng JVM không giữ cho reflection (chỉ bytecode tool đọc); RUNTIME giữ tới lúc chạy để reflection đọc. Mặc định khi không khai báo @Retention là CLASS — đây là lý do phổ biến nhất khiến getAnnotation() trả null.
Câu 5. Làm sao tự định nghĩa một annotation?
Khai báo bằng @interface, các "element" viết như method không tham số, có thể kèm default. Ví dụ: @Retention(RUNTIME) @Target(FIELD) @interface Range { int min() default 0; int max() default 100; }. Annotation type không được khai báo extends/implements (ngầm extends java.lang.annotation.Annotation), element không nhận null, không generic, không throws.
Câu 6. Marker, single-value và multi-element annotation khác nhau ra sao?
Marker: không có element nào, chỉ đánh dấu có mặt (@NotEmpty). Single-value: chỉ có duy nhất element tên value() nên viết tắt được — @Range(18) nghĩa là @Range(value = 18). Multi-element: nhiều element, có thể có default; khi dùng chỉ cần truyền element không có default hoặc muốn ghi đè (@Range(min = 18), bỏ qua max nếu có default).
Câu 7. Element của annotation nhận những kiểu dữ liệu nào?
Primitive, String, Class (class literal), enum, annotation khác, và mảng của các kiểu trên. Không được dùng null, generic, hay kiểu tự định nghĩa thông thường. Nếu cần giá trị đặc biệt, dùng giá trị sentinel (chuỗi rỗng, số âm) quy ước trong tài liệu annotation.
Câu 8. Reflection là gì? Ứng dụng thực tế ở đâu?
Là API (java.lang.reflect) cho phép chương trình Java kiểm tra và thao tác class/field/method/constructor lúc runtime: liệt kê thành viên, tạo object, gọi method, đọc/ghi field, đọc annotation. Ứng dụng: DI container (Spring), serialize JSON (Jackson), ORM (Hibernate), testing/mock (JUnit, Mockito), IDE/tool phân tích code, plugin loader.
Câu 9. Có mấy cách lấy đối tượng Class? Chúng khác gì nhau?
Ba cách: UserForm.class (class literal — biết class lúc compile), obj.getClass() (từ object đang sống), Class.forName("ten.binary") (từ chuỗi, dùng khi tên chỉ biết lúc runtime). Với cùng class loader, cả ba trả về cùng một object nên so sánh == được. forName ném ClassNotFoundException (checked) nếu sai tên/không có trên classpath.
Câu 10. getDeclaredFields() khác getFields() thế nào?
getDeclaredFields() trả mọi field khai báo trực tiếp trong class hiện tại bất kể mức truy cập (private/protected/package/public), nhưng không gồm field kế thừa. getFields() chỉ trả field public, kể cả public kế thừa từ cha/interface. Quy tắc y hệt cho getDeclaredMethods()/getMethods() và getDeclaredConstructors()/getConstructors().

Nâng cao (Junior+)

Câu 11. Đọc/ghi field private bằng reflection thế nào? Tạo object với constructor private?
Lấy field bằng getDeclaredField("ten"), gọi setAccessible(true), rồi get(obj)/set(obj, value). Với constructor private: getDeclaredConstructor(...), setAccessible(true), newInstance(args). Lưu ý setAccessible phá encapsulation — chỉ dùng trong framework/thư viện/test, không dùng trong logic nghiệp vụ.
Câu 12. Vì sao String.class.getDeclaredField("value").setAccessible(true) bị chặn?
Từ Java 9, JPMS đóng gói nội bộ JDK: module java.base không mở package java.lang cho module vô danh (nơi code của bạn chạy), nên reflection từ bên ngoài bị chặn bằng InaccessibleObjectException. Class của bạn chạy trong unnamed module vốn mở nên vẫn setAccessible bình thường. Cần thiết thì thêm cờ --add-opens java.base/java.lang=ALL-UNNAMED, nhưng nên coi đó là giải pháp tạm.
Câu 13. @Inherited hoạt động thế nào? Có áp dụng cho interface không?
@Inherited chỉ dùng cho annotation trên class (hoặc annotation type). Khi class cha có annotation được đánh dấu @Inherited, class con gọi getAnnotation() cũng thấy nó (như thừa kế qua getAnnotations()). Nó không áp dụng cho interface và cũng không lan qua interface implementation — đây là bẫy khi thiết kế annotation cho framework.
Câu 14. @Repeatable giải quyết vấn đề gì? Container annotation là gì?
Trước Java 8, một annotation chỉ gắn một lần trên cùng vị trí. @Repeatable cho phép gắn nhiều lần; compiler tự bọc các lần gắn vào một annotation container có element mảng (ví dụ @Ranges({@Range(...), @Range(...)})). Lúc đọc dùng getAnnotationsByType(Range.class); getAnnotation(Range.class) trả null vì trên class thật ra chỉ có container.
Câu 15. getRecordComponents() là gì? Dùng làm gì?
API từ Java 16 trả về mảng RecordComponent cho record: tên, kiểu, generic type, accessor, annotation của từng component. Nó "chính danh" hơn getDeclaredFields() vì phản ánh đúng khai báo record, dùng nhiều trong serializer/mapper (Jackson dùng để serialize record) và trong framework cần metadata sạch. Ngoài ra còn isRecord() để kiểm tra.
Câu 16. Vì sao reflection chậm hơn gọi trực tiếp? Có cách nào giảm?
Vì mỗi lần gọi phải kiểm tra quyền truy cập, boxing tham số, đóng gói mảng argument, không được JIT inline, và tra cứu metadata — benchmark nhỏ cho thấy chậm hơn hàng chục lần. Giảm bằng: cache Field/Method (không lookup lại), gọi setAccessible(true) một lần, dùng ở startup thay vì hot path, và với trường hợp khắt khe dùng MethodHandle/LambdaMetafactory.
Câu 17. Spring "thần kỳ" nhờ annotation + reflection cụ thể thế nào?
Spring quét classpath tìm class có @Component/@Service... — đọc annotation bằng reflection; tạo bean bằng constructor (reflection) và tiêm dependency khớp kiểu cho @Autowired; bọc bean bằng dynamic proxy để thực hiện AOP cho @Transactional, @Cacheable... Tất cả "phép thuật" chỉ diễn ra một lần lúc khởi động; sau đó code chạy gần như gọi trực tiếp qua proxy.
Câu 18. Jackson đọc annotation và serialize record thế nào?
Jackson đọc metadata class một lần (cache lại), ánh xạ tên field/accessor theo @JsonProperty, bỏ qua field theo @JsonIgnore. Với record, nó dùng canonical constructor và tên component (không cần getter truyền thống); với class thường, cần getter/setter hoặc bật module đọc tên parameter (-parameters). Việc nặng diễn ra lúc khởi tạo mapper, không phải mỗi lần serialize.
Câu 19. JPA/Hibernate dùng annotation gì để map object xuống bảng?
Quét @Entity, @Table, @Id, @Column, @ManyToOne... bằng reflection, dựng metadata ánh xạ, sinh SQL và tạo object/đọc ghi field bằng reflection. Vì tạo instance qua reflection (và proxy cho lazy loading), entity thường phải có constructor không tham số (có thể để protected) — đó là lý do Hibernate yêu cầu điều này.
Câu 20. Vì sao không kiểm tra được List<String> bằng reflection?
Vì type erasure: generic chỉ tồn tại lúc compile, JVM xóa thông tin kiểu khi biên dịch nên runtime chỉ còn java.util.List. Reflection vẫn đọc được khai báo getGenericType() trên field/method (metadata trong chữ ký), nhưng object đang sống không biết mình từng được khai báo với kiểu gì — nên nhét Integer vào List<String> bằng reflection vẫn "thành công" cho tới khi đọc ra dùng.
Câu 21. Khi nào KHÔNG nên dùng reflection? Ví dụ production?
Không dùng trong logic nghiệp vụ, vòng lặp hiệu năng cao, hoặc khi có thể giải quyết bằng interface/DI/generic. Ví dụ: cần tính tiền đơn hàng thì gọi method trực tiếp, không lookup getDeclaredMethod; cần thay đổi hành vi theo loại đối tượng thì dùng đa hình thay vì kiểm tra class bằng reflection. Reflection hợp lý ở tầng framework/mapper/tool/test — nơi cái giá "mất kiểm tra compile" được bù bằng tính linh hoạt.
Câu 22. @Deprecated(since, forRemoval) có gì hơn comment @deprecated trong Javadoc?
Nó là dữ liệu máy đọc được: IDE gạch ngang, javac in warning, tool phân tích dùng; since ghi phiên bản bắt đầu deprecated, forRemoval = true báo API sẽ bị xóa hẳn để công cụ build đánh dấu nguy hiểm (kể cả warning [removal] như ở mục 2). Comment Javadoc chỉ hiển thị cho người đọc, không tác động gì tới compiler/tool.

Bài 6. Viết annotation @NotEmpty và validator đọc nó 
import java.lang.annotation.*;
import java.lang.reflect.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotEmpty {}

record UserForm(@NotEmpty String email) {}

void main() throws Exception {
    UserForm form = new UserForm("");
    Field f = UserForm.class.getDeclaredField("email");
    f.setAccessible(true);
    if (f.isAnnotationPresent(NotEmpty.class) && ((String) f.get(form)).isBlank()) {
        IO.println("LOI email: khong duoc rong");
    } else {
        IO.println("email hop le");
    }
}
In ra LOI email: khong duoc rong. Bắt buộc có @Retention(RUNTIME) nếu không isAnnotationPresent trả false; @Target(FIELD) để annotation gắn đúng chỗ; setAccessible(true) cần cho field private của record. Thử đổi email thành "an@example.com" — in ra email hop le.
Bài 7. Viết toString bằng reflection 
import java.lang.reflect.*;
import java.util.*;

public class UserForm {
    private String email = "an@example.com";
    private int age = 25;

    public static void main() throws Exception {
        IO.println(moTa(new UserForm()));
    }

    static String moTa(Object obj) throws Exception {
        StringBuilder sb = new StringBuilder(obj.getClass().getSimpleName()).append("[");
        Field[] fields = obj.getClass().getDeclaredFields();
        Arrays.sort(fields, Comparator.comparing(Field::getName));
        for (int i = 0; i < fields.length; i++) {
            fields[i].setAccessible(true);
            if (i > 0) {
                sb.append(", ");
            }
            sb.append(fields[i].getName()).append("=").append(fields[i].get(obj));
        }
        return sb.append("]").toString();
    }
}
In ra UserForm[age=25, email=an@example.com]. Sort theo tên vì thứ tự field do JVM trả về không đảm bảo. Đây là ý tưởng lõi của các thư viện sinh toString/JSON tự động: quét field, đọc giá trị, in ra.

Bài 9. @Range validation — đoán output 
import java.lang.annotation.*;
import java.lang.reflect.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Range {
    int min() default 0;
    int max() default 100;
}

record UserForm(String email, @Range(min = 18, max = 120) int age) {}

void main() throws Exception {
    for (Field f : UserForm.class.getDeclaredFields()) {
        Range r = f.getAnnotation(Range.class);
        if (r == null) {
            continue;
        }
        f.setAccessible(true);
        int value = f.getInt(new UserForm("an@example.com", 15));
        IO.println(f.getName() + ": " + (value >= r.min() && value <= r.max() ? "OK" : "LOI"));
    }
}
In ra age: LOI. Field email bị bỏ qua vì không có @Range (continue); age = 15 nhỏ hơn min = 18. Đổi tuổi thành 25 sẽ in age: OK.

Checklist tự đánh giá trước phỏng vấn

  • Giải thích được "annotation là metadata thụ động" kèm ví dụ compiler đọc vs framework đọc.

  • Viết được annotation tùy biến có element + default, chọn đúng @Retention/@Target.

  • Nêu được reflection chậm hơn và 2-3 cách giảm chi phí (cache, startup, MethodHandle).
  • Trình bày Spring dùng annotation + reflection + proxy thế nào, và bẫy self-invocation.
  • Nói rõ khi nào KHÔNG nên dùng reflection trong production.
