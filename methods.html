Methods — phương thức trong Java

Method (phương thức) là một khối code có tên, nhận đầu vào, xử lý và trả kết quả — đơn vị tổ chức code cơ bản nhất của Java. Khác JavaScript, Java không có hàm tự do: mọi method phải nằm trong class, interface, enum hoặc record. Trang này học từ khai báo, overloading, đệ quy, static tới cách kiểm thử method ngay khi viết.

2. Khai báo method

Đầy đủ một method gồm 6 phần, theo đúng thứ tự:

[access modifier] [static] returnType tenMethod(kieuThamSo tenThamSo, ...) { }
  • Access modifier — public, private, protected hoặc bỏ trống (package-private). Chọn sai mức truy cập là lỗi thiết kế; học sâu ở 2.2 Encapsulation & Immutability. Trong ví dụ dưới dùng static để gọi được từ main mà chưa cần tạo object.
  • Return type — kiểu dữ liệu trả về, hoặc void nếu không trả gì. Một method chỉ trả về một giá trị duy nhất.
  • Tên method — quy ước camelCase và bắt đầu bằng động từ.
  • Danh sách tham số — cặp kiểu tên, có thể rỗng.
  • Body — khối { } chứa code xử lý.
  • Thứ tự khai báo không quan trọng — method gọi method khác khai báo sau nó vẫn chạy, vì Java biên dịch cả file rồi mới gọi. Đây là điểm khác function expression trong JavaScript.
import java.math.BigDecimal;

public class MethodDemo {
    static final double VAT_RATE = 0.1;

    static BigDecimal tongTien(BigDecimal donGia, int soLuong) {
        BigDecimal tamTinh = donGia.multiply(BigDecimal.valueOf(soLuong));
        BigDecimal thue = tamTinh.multiply(BigDecimal.valueOf(VAT_RATE));
        return tamTinh.add(thue);
    }

    static void inKetQua(String nhan, BigDecimal tien) {
        IO.println(nhan + ": " + tien);
    }

    public static void main() {
        BigDecimal donGia = new BigDecimal("120000");
        inKetQua("Tong tien", tongTien(donGia, 3));
    }
}
Tong tien: 396000.0

Parameter vs argument

Tiếng Việt hay gọi chung là "tham số", nhưng tài liệu tiếng Anh phân biệt rõ:

Parameter (tham số hình thức)Argument (đối số)
Nằm ở đâuTrong khai báo methodTrong lời gọi method
Ví dụdonGia, soLuongnew BigDecimal("120000"), 3
Bản chấtBiến local nhận giá trị khi method chạyGiá trị/địa chỉ được truyền vào

Trong lời gọi tongTien(donGia, 3): donGia và 3 là argument; chúng được gán cho parameter donGia, soLuong theo đúng thứ tự, không theo tên. Java không có named arguments (mục 4).

Quy ước đặt tên

  • Tên method là động từ hoặc cụm động từ, camelCase: tinhTong, sendEmail, findById.
  • Method trả boolean đặt câu hỏi: isValid, hasPermission, canRetry.
  • Accessor theo cặp getX/setX; riêng boolean dùng isX. Record không cần: tự sinh amount(), currency().
  • Tránh tên vô nghĩa: doStuff, handle, process1. Người đọc phải hiểu method làm gì mà không cần mở body.

Thứ tự khai báo không ảnh hưởng — đoạn sau in ra bình thường:

public class DeclarationOrderDemo {
    static void goi() {
        IO.println("goi() chay truoc khi duoc khai bao");
    }

    public static void main() {
        goi();
    }
}
goi() chay truoc khi duoc khai bao

3. return sớm & guard clause

return kết thúc method ngay lập tức. Trong method void, viết return; không kèm giá trị để thoát sớm. Trong method có kiểu trả về, mọi nhánh code phải chắc chắn trả về một giá trị — compiler kiểm tra điều này.

Guard clause (mệnh đề gác cổng) là pattern: kiểm tra các điều kiện xấu/edge case trước và thoát sớm, để phần logic chính nằm thẳng hàng, không bị lồng sâu trong if:

public class EarlyReturnVoidDemo {
    static void inThongBao(String ten) {
        if (ten == null || ten.isBlank()) {
            return;
        }
        IO.println("Xin chao " + ten);
    }

    static int tinhPhi(int tongTien) {
        if (tongTien < 0) {
            throw new IllegalArgumentException("tongTien khong duoc am: " + tongTien);
        }
        if (tongTien >= 500_000) {
            return 0;
        }
        return 30_000;
    }

    public static void main() {
        inThongBao("An");
        inThongBao(null);
        inThongBao("  ");
        IO.println("phi 600000 = " + tinhPhi(600_000));
        IO.println("phi 100000 = " + tinhPhi(100_000));
        try {
            tinhPhi(-1);
        } catch (IllegalArgumentException e) {
            IO.println("loi: " + e.getMessage());
        }
    }
}
Xin chao An
phi 600000 = 0
phi 100000 = 30000
loi: tongTien khong duoc am: -1

So sánh hai cách viết cùng logic — guard clause giúp ít lồng nhau hơn, đọc từ trên xuống không cần nhớ ngữ cảnh:

// Khong dung guard clause: logic chinh bi day vao trong
static String xepLoaiCu(double diem) {
    String ketQua;
    if (diem >= 0 && diem <= 10) {
        if (diem >= 8) {
            ketQua = "Gioi";
        } else {
            ketQua = "Trung binh";
        }
    } else {
        ketQua = "khong hop le";
    }
    return ketQua;
}

// Dung guard clause
static String xepLoai(double diem) {
    if (diem < 0 || diem > 10) {
        return "khong hop le";
    }
    if (diem >= 8) {
        return "Gioi";
    }
    return "Trung binh";
}

public static void main() {
    IO.println(xepLoaiCu(9.0) + " / " + xepLoai(9.0));
    IO.println(xepLoaiCu(5.0) + " / " + xepLoai(5.0));
    IO.println(xepLoaiCu(-1) + " / " + xepLoai(-1));
}
Gioi / Gioi
Trung binh / Trung binh
khong hop le / khong hop le

Trả về nhiều giá trị bằng record

Java không có tuple như nhiều ngôn ngữ, cũng không tiện return { ok, reason } như JavaScript. Cách sạch nhất là gói kết quả vào một record — DTO bất biến, tự sinh constructor/getter/equals/toString:

public class GuardClauseDemo {
    record KyLuan(boolean dat, String lyDo) {}

    static KyLuan xepLoai(double diem) {
        if (diem < 0 || diem > 10) {
            return new KyLuan(false, "diem khong hop le: " + diem);
        }
        if (diem >= 8) {
            return new KyLuan(true, "Gioi");
        }
        if (diem >= 6.5) {
            return new KyLuan(true, "Kha");
        }
        return new KyLuan(true, "Trung binh");
    }

    public static void main() {
        IO.println(xepLoai(9.0));
        IO.println(xepLoai(7.0));
        IO.println(xepLoai(-1));
    }
}
KyLuan[dat=true, lyDo=Gioi]
KyLuan[dat=true, lyDo=Kha]
KyLuan[dat=false, lyDo=diem khong hop le: -1.0]
Nếu ý nghĩa là "có thể không có kết quả", đừng trả null — dùng Optional (học ở 3.7 Optional). Record và DTO được đào sâu ở 2.2 Encapsulation & Immutability.

4. Java không có tham số mặc định / named arguments

JavaScript có giá trị mặc định cho tham số (chạy thật bằng Node v22: in ra 6 rồi 15):

// JavaScript - chi de so sanh, KHONG phai Java
function tang(a, b = 1) { return a + b; }

console.log(tang(5));       // 6  - dung gia tri mac dinh
console.log(tang(5, 10));   // 15

Java không có tham số mặc định. Named arguments thì cả JS lẫn Java đều không có thật — JS muốn "gọi theo tên" phải truyền một object rồi destructure (tang({ a: 5, b: 10 })). Viết theo kiểu JavaScript sẽ lỗi ngay khi compile:

DefaultParamsErr.java:2: error: ',', ')', or '[' expected
    static int tang(int a, int b = 1) {
                                ^
1 error

Cách 1 — overload

Viết nhiều phiên bản cùng tên, bản ít tham số gọi bản đầy đủ với giá trị mặc định. Đây là cách JDK tự làm khắp nơi:

public class OverloadDemo {
    static int tang(int a) {
        return tang(a, 1);
    }

    static int tang(int a, int b) {
        return a + b;
    }

    static int tang(int a, int b, int c) {
        return a + b + c;
    }

    public static void main() {
        IO.println(tang(5));
        IO.println(tang(5, 10));
        IO.println(tang(1, 2, 3));
    }
}

15

Cách 2 — builder cho nhiều tham số tùy chọn

Khi có 4-5 tham số mà phần lớn là tùy chọn, overload sẽ bùng nổ tổ hợp. Builder giải quyết bằng chuỗi method có tên — vừa "named arguments" vừa có giá trị mặc định:

public class BuilderDemo {
    record SearchRequest(String keyword, int page, int size, String sort) {
        static final class Builder {
            private String keyword = "";
            private int page = 0;
            private int size = 20;
            private String sort = "id";

            Builder keyword(String keyword) {
                this.keyword = keyword;
                return this;
            }

            Builder page(int page) {
                this.page = page;
                return this;
            }

            Builder size(int size) {
                this.size = size;
                return this;
            }

            Builder sort(String sort) {
                this.sort = sort;
                return this;
            }

            SearchRequest build() {
                return new SearchRequest(keyword, page, size, sort);
            }
        }
    }

    public static void main() {
        SearchRequest macDinh = new SearchRequest.Builder().build();
        IO.println(macDinh);

        SearchRequest timKiem = new SearchRequest.Builder()
                .keyword("ao thun")
                .page(2)
                .size(50)
                .build();
        IO.println(timKiem);
    }
}
SearchRequest[keyword=, page=0, size=20, sort=id]
SearchRequest[keyword=ao thun, page=2, size=50, sort=id]
Chọn cách nào? 1-2 tham số tùy chọn đơn giản thì overload; 3+ tùy chọn, nhiều tổ hợp, hoặc tham số boolean khó đọc thì builder. Đừng trộn cả hai cho cùng một API. Thư viện lớn trong JDK dùng đủ cả hai: List.of() (overload 0..10 phần tử + varargs), StringBuilder, các builder của Jackson/OkHttp.

5. Overloading — cùng tên, khác tham số Hay hỏi phỏng vấn

Overload là nhiều method cùng tên trong cùng class nhưng khác danh sách tham số. Khác nhau có thể là: số lượng tham số, kiểu tham số, hoặc thứ tự kiểu tham số.

Khác return type là không đủ — Java phân biệt method bằng tên + kiểu tham số (method descriptor), không dùng return type. Đoạn sau lỗi compile vì tinh(int) đã được định nghĩa:

DuplicateMethodErr.java:6: error: method tinh(int) is already defined in class DuplicateMethodErr
    static long tinh(int a) {
                ^
1 error

Trong bytecode, tên method được gắn kèm kiểu tham số nên mới phân biệt được. Chạy javap trên OverloadDemo ở mục 4 ta thấy rõ:

static int tang(int);
static int tang(int, int);
static int tang(int, int, int);

Đổi tên parameter mà giữ nguyên kiểu thì vẫn là cùng một method — tên parameter không tính vào chữ ký.

Overload resolution — chọn bản nào?

Khi nhiều bản cùng "vừa" với một lời gọi, compiler chọn theo 3 phase, phase trước thắng phase sau: (1) chỉ widening, không boxing; (2) cho phép boxing/unboxing; (3) cho phép varargs. Toàn bộ luật kèm ví dụ nằm ở Data Types — mục 9; ở đây tập trung vào hai bẫy thực chiến.

Bẫy 1 — null chọn bản "cụ thể nhất"

public class OverloadNullDemo {
    static void gui(String s) {
        IO.println("gui(String) - cu the hon");
    }

    static void gui(Object o) {
        IO.println("gui(Object)");
    }

    public static void main() {
        gui("abc");
        gui(null);
    }
}
gui(String) - cu the hon
gui(String) - cu the hon

null hợp với mọi kiểu reference, nên compiler chọn bản most specific: String là subtype của Object. Nhưng nếu hai bản không có quan hệ cha-con, chương trình không compile:

OverloadAmbiguousErr.java:11: error: reference to xuLy is ambiguous
        xuLy(null);
        ^
  both method xuLy(Integer) in OverloadAmbiguousErr and method xuLy(Long) in OverloadAmbiguousErr match
1 error
Bẫy boxing: nếu class có cả m(long) lẫn m(Integer), lời gọi m(1) sẽ chọn bản long — widening thuộc phase 1 thắng boxing phase 2. Minh hoạ chi tiết ở Data Types — mục 9.

Bẫy 2 — chọn nhầm overload có sẵn của JDK

Ví dụ production thật: List có hai bản remove — remove(int index) và remove(Object o). Truyền số nguyên vào sẽ chọn bản xóa theo vị trí, không phải xóa theo giá trị:

import java.util.ArrayList;
import java.util.List;

public class ListRemoveTrap {
    public static void main() {
        List<Integer> nums = new ArrayList<>(List.of(10, 20, 30));
        IO.println("remove(1)           : " + nums.remove(1));
        IO.println("sau remove(1)       : " + nums);
        IO.println("remove(Integer 30)  : " + nums.remove(Integer.valueOf(30)));
        IO.println("sau remove(value 30): " + nums);
    }
}
remove(1)           : 20
sau remove(1)       : [10, 30]
remove(Integer 30)  : true
sau remove(value 30): [10]

nums.remove(1) gọi remove(int) → xóa phần tử ở index 1 (giá trị 20) và trả về phần tử bị xóa. Muốn xóa theo giá trị phải ép boxing rõ ràng: nums.remove(Integer.valueOf(30)) → gọi remove(Object), trả về boolean. List sẽ học ở 3.3 Collections; bẫy này thì phải nhớ ngay.

Hệ quả maintain API: thêm một overload mới có thể đổi method được chọn ở những call site cũ mà không ai sửa gì (ví dụ thêm bản nhận long trong khi call site đang truyền int). Vì vậy overload phải khác nhau rõ ràng về ngữ nghĩa, không chỉ để tiện.

6. Pass-by-value (nhắc lại ngắn)

Cơ chế stack/heap và vì sao Java luôn pass-by-value đã được giải thích đầy đủ ở Biến trong Java — mục 7. Ghi nhớ 3 dòng:

  • Primitive (int, double...) truyền bản sao giá trị — sửa trong method không ảnh hưởng ngoài.
  • Object truyền bản sao địa chỉ (reference copy) — cả hai cùng trỏ tới một object trên heap.
  • Vì là bản sao, gán lại parameter sb = new StringBuilder(...) bên trong method không đổi biến bên ngoài; nhưng gọi method làm thay đổi nội dung object (sb.append(...)) thì bên ngoài thấy.
public class PassByValueDemo {
    static void themDauCham(StringBuilder sb) {
        sb.append("!");
    }

    static void thayThe(StringBuilder sb) {
        sb = new StringBuilder("moi");
        sb.append("?");
    }

    public static void main() {
        StringBuilder sb = new StringBuilder("hello");
        themDauCham(sb);
        IO.println("sau themDauCham : " + sb);
        thayThe(sb);
        IO.println("sau thayThe     : " + sb);
    }
}
sau themDauCham : hello!
sau thayThe     : hello!

Record, String, BigDecimal... đều bất biến nên không bao giờ bị method "sửa lén" — đó là lý do production ưu tiên chúng cho DTO và tiền tệ.

7. Recursion — đệ quy Hay hỏi phỏng vấn

Recursion là method gọi chính nó. Mọi hàm đệ quy đúng phải có:

  • Base case — điều kiện dừng, trả kết quả trực tiếp, không gọi lại.
  • Recursive case — gọi lại chính nó với bài toán nhỏ hơn, tiến dần về base case.
public class RecursionDemo {
    static long giaiThua(int n) {
        if (n < 0) {
            throw new IllegalArgumentException("n phai >= 0: " + n);
        }
        if (n <= 1) {
            return 1;
        }
        return n * giaiThua(n - 1);
    }

    static long fib(int n) {
        if (n <= 1) {
            return n;
        }
        return fib(n - 1) + fib(n - 2);
    }

    static long fibVongLap(int n) {
        long a = 0;
        long b = 1;
        for (int i = 0; i < n; i++) {
            long tiep = a + b;
            a = b;
            b = tiep;
        }
        return a;
    }

    public static void main() {
        IO.println("giaiThua(5)    = " + giaiThua(5));
        IO.println("giaiThua(0)    = " + giaiThua(0));
        IO.println("fib(10)        = " + fib(10));
        IO.println("fibVongLap(50) = " + fibVongLap(50));
    }
}
giaiThua(5)    = 120
giaiThua(0)    = 1
fib(10)        = 55
fibVongLap(50) = 12586269025

fib bản đệ quy ngây thơ có độ phức tạp hàm mũ vì tính lại cùng giá trị rất nhiều lần; fibVongLap chỉ O(n). Cùng kết quả nhưng chi phí khác hẳn — chọn công cụ theo bài toán, không theo sở thích.

Cần fib lớn (n > 92) thì long tràn — dùng BigInteger (xem Data Types — mục 12) hoặc quy hoạch động với mảng.

Vì sao thiếu base case lại ném StackOverflowError?

Mỗi lời gọi method tạo một stack frame (biến local, tham số, địa chỉ quay về) đặt lên stack của thread. Đệ quy vô hạn làm stack đầy — JVM ném lỗi thay vì treo máy:

public class StackOverflowDemo {
    static int soLanGoi = 0;

    static void deQuyVoHan(int n) {
        soLanGoi++;
        deQuyVoHan(n + 1);
    }

    public static void main() {
        try {
            deQuyVoHan(0);
        } catch (StackOverflowError e) {
            IO.println("class  : " + e.getClass().getSimpleName());
            IO.println("message: " + e.getMessage());
            IO.println("so lan goi: " + soLanGoi);
        }
    }
}

Một lần chạy thật trên máy này (JDK 25):

class  : StackOverflowError
message: null
so lan goi: 44249
  • StackOverflowError là Error, không phải Exception — đừng bắt trong code production, chỉ bắt ở đây để demo. Chạy lại nhiều lần cho các số khác nhau (khoảng 17.000-45.000 trên máy này) tùy trạng thái JVM.
  • deQuyVoHan(n + 1) là tail call — lời gọi ở vị trí cuối cùng. Nhiều bạn tưởng nó được tối ưu thành vòng lặp; Java không có tail-call optimization, nên vẫn nổ (V8/Node.js cũng không hỗ trợ TCO).
  • Giới hạn ~44.000 frame cho thấy mỗi frame tốn kha khá bộ nhớ stack; đệ quy sâu với dữ liệu lớn có thể nổ dù có base case.

8. static vs instance Junior+

Hai loại method:

  • Instance method — thuộc về object, gọi qua obj.method(), truy cập được cả field instance lẫn field static, và có this trỏ tới object hiện tại.
  • Static method — thuộc về class, gọi qua TenClass.method(), không có this, chỉ truy cập được field/method static. Vì vậy JVM gọi được main mà không cần tạo object.

Vi phạm điều này bị chặn ngay khi compile — cả hai lỗi thường gặp:

StaticErr.java:9: error: non-static variable count cannot be referenced from a static context
        count++;
        ^
StaticErr.java:10: error: non-static method tangInstance() cannot be referenced from a static context
        tangInstance();
        ^
2 errors

Static factory method

Static method hay dùng nhất là static factory method: method static trả về object, thay cho constructor. Tên method nói rõ ý nghĩa, có thể cache, có thể trả subtype:

import java.math.BigDecimal;

public class StaticFactoryDemo {
    record Money(BigDecimal amount, String currency) {
        static Money vnd(long amount) {
            return new Money(BigDecimal.valueOf(amount), "VND");
        }

        static Money usd(String amount) {
            return new Money(new BigDecimal(amount), "USD");
        }
    }

    public static void main() {
        IO.println(Money.vnd(250_000));
        IO.println(Money.usd("19.99"));
        IO.println(BigDecimal.valueOf(0.1));
    }
}
Money[amount=250000, currency=VND]
Money[amount=19.99, currency=USD]
0.1

JDK đầy ví dụ: BigDecimal.valueOf(...), List.of(...), LocalDate.of(...), Integer.parseInt(...), Optional.empty(). So với constructor, static factory: có tên gọi rõ nghĩa, không bắt buộc trả object mới mỗi lần, và có thể trả về subtype ẩn — chi tiết ở 2.1 Classes & Objects.

Khi nào dùng static?

Nên staticKhông nên static
Hàm tiện ích thuần túy: Math.max, Objects.requireNonNullState dùng chung: static mutable field là nguồn race condition (xem Biến trong Java — mục 15)
Factory method, hằng số static finalService/Repository trong Spring: là bean instance, không phải static (giai đoạn 5)

9. main method & JVM args Hay hỏi phỏng vấn

Entry point chuẩn mà mọi tài liệu/phỏng vấn dùng:

public static void main(String[] args)
  • public — JVM (ở package khác) phải gọi được.
  • static — JVM gọi trước khi có object nào.
  • void — JVM không nhận giá trị trả về; muốn báo mã thoát dùng System.exit(code).
  • String[] args — mảng tham số dòng lệnh (mảng học ở 1.6 Arrays).

Thí nghiệm: java File.java a b c có truyền được args không?

Nhiều bạn tưởng chế độ chạy file đơn không nhận tham số. Thực tế nhận bình thường — mọi thứ sau tên file là argument của chương trình (các option của chính lệnh java mới phải đặt trước tên file):

public class MainArgsDemo {
    public static void main(String[] args) {
        IO.println("args.length = " + args.length);
        for (int i = 0; i < args.length; i++) {
            IO.println("args[" + i + "] = " + args[i]);
        }
    }
}

Chạy thật java MainArgsDemo.java a b c:

args.length = 3
args[0] = a
args[1] = b
args[2] = c

Chạy java MainArgsDemo.java không truyền gì: args.length = 0 — args là mảng rỗng, không bao giờ null, nên cứ args.length thoải mái. Chương trình thật thường kiểm tra và in hướng dẫn:

public class MainArgsSum {
    public static void main(String[] args) {
        if (args.length < 2) {
            IO.println("Dung: java MainArgsSum.java <so1> <so2>");
            return;
        }
        int a = Integer.parseInt(args[0]);
        int b = Integer.parseInt(args[1]);
        IO.println(a + " + " + b + " = " + (a + b));
    }
}
$ java MainArgsSum.java 3 4
3 + 4 = 7
$ java MainArgsSum.java
Dung: java MainArgsSum.java <so1> <so2>

JDK 25 — JEP 512: compact source file & instance main

Từ JDK 25 (JEP 512), với file đơn bạn không cần khai báo class, có thể viết instance main và bỏ luôn phần lớn boilerplate. Đây là các dạng đã chạy thật trên máy:

// File 1 - main khong tham so: JVM tu tao object roi goi
void main() {
    IO.println("instance main() (khong static) chay duoc");
}

// File 2 - main nhan args nhu thuong
void main(String[] args) {
    IO.println("args.length = " + args.length);
}

Kết quả chạy thật của file 1 (dạng không tham số):

instance main() (khong static) chay duoc

File 2 nhận args bình thường — chạy java MainInstanceArgsDemo.java x y in ra:

args.length = 2

Và nếu file chỉ có static void main() không tham số, chạy kèm args cũng không lỗi — args đơn giản bị bỏ qua:

$ java MainNoArgsDemo.java a b c
main() khong tham so van chay
Học gì để đi làm: dạng compact/instance main rất tiện để học và viết script nhỏ. Nhưng codebase production (đặc biệt Spring Boot) vẫn dùng public static void main(String[] args) + System.out.println trong tài liệu cũ. JEP 512 còn tự import mọi package của module java.base cho file compact (nên BigDecimal, List dùng được không cần import) — còn class có tên đầy đủ thì không có đặc ân đó.

10. Method chaining & fluent API Production

Method chaining là gọi liên tiếp a().b().c() vì mỗi method trả về một object để gọi tiếp. Có hai kiểu trả về:

  • Trả về chính object (return this) — kiểu StringBuilder, builder pattern. Object bị thay đổi tại chỗ (mutable).
  • Trả về object mới — kiểu String bất biến: mỗi method trả chuỗi mới, chuỗi gốc không đổi.
public class ChainingDemo {
    public static void main() {
        String maDon = new StringBuilder()
                .append("DH")
                .append('-')
                .append(2026)
                .append('-')
                .append(String.format("%05d", 42))
                .toString();
        IO.println(maDon);

        String s = "hello";
        String s2 = s.toUpperCase().trim().concat("!");
        IO.println(s2);
        IO.println(s);
    }
}
DH-2026-00042
HELLO!
hello

Vì sao StringBuilder chain được? Mỗi append trả về this — cùng một object. String cũng chain được nhưng tạo object mới mỗi bước; trong vòng lặp nối chuỗi nhiều lần thì StringBuilder nhanh hơn hẳn (xem Biến trong Java — mục 14, đào sâu ở 1.7 Strings).

Builder ở mục 4 chính là fluent API: .keyword(...).page(2).size(50).build(). Các API java.time cũng theo phong cách này: ngay.plusDays(3).withYear(2027) trả về object mới (bất biến). Stream ở 3.8 là fluent API mạnh nhất của Java.

Chuỗi quá dài khó debug vì breakpoint khó đặt giữa các bước. Nếu chain quá 5-7 bước hoặc cần log trung gian, tách thành biến trung gian có tên.

11. Kiểm thử method ngay khi viết Production

Thói quen quan trọng nhất của người viết method nghiêm túc: nghĩ ngay tới 3 loại đầu vào trước khi tự tin method đúng.

Loại đầu vàoCâu hỏiVí dụ với chia(int a, int b)
Bình thườngCa dùng phổ biến nhấtchia(10, 2) → 5
Biên (boundary)Giá trị nhỏ nhất/lớn nhất, 0, âm, làm trònchia(7, 2) → 3; chia(Integer.MIN_VALUE, -1) → tràn
Sai (invalid)Dữ liệu không hợp lệ, chia 0, nullchia(1, 0) → phải ném lỗi rõ ràng

Khi chưa có JUnit, tự kiểm thử bằng so sánh kết quả và in PASS/FAIL — cùng tinh thần với assert:

public class ManualTestDemo {
    static int chia(int a, int b) {
        if (b == 0) {
            throw new ArithmeticException("chia cho 0");
        }
        return a / b;
    }

    static void check(String ten, int mongDoi, int thucTe) {
        String ketQua = mongDoi == thucTe ? "PASS" : "FAIL";
        IO.println(ketQua + " " + ten + " -> " + thucTe);
    }

    static void checkNemLoi(String ten, int a, int b) {
        try {
            int ketQua = chia(a, b);
            IO.println("FAIL " + ten + " -> khong nem loi, tra ve " + ketQua);
        } catch (ArithmeticException e) {
            IO.println("PASS " + ten + " -> " + e.getMessage());
        }
    }

    public static void main() {
        check("binh thuong: 10 / 2", 5, chia(10, 2));
        check("lam tron xuong: 7 / 2", 3, chia(7, 2));
        check("bien: MIN_VALUE / -1", Integer.MIN_VALUE, chia(Integer.MIN_VALUE, -1));
        checkNemLoi("sai: chia cho 0", 1, 0);
    }
}
PASS binh thuong: 10 / 2 -> 5
PASS lam tron xuong: 7 / 2 -> 3
PASS bien: MIN_VALUE / -1 -> -2147483648
PASS sai: chia cho 0 -> chia cho 0

Ca biên MIN_VALUE / -1 không ném lỗi mà trả về chính MIN_VALUE — tràn số nguyên quay vòng âm thầm (xem Biến trong Java — mục 9). Đây chính là ca mà người mới hay bỏ sót; nếu nghiệp vụ không cho phép, phải tự kiểm tra a == Integer.MIN_VALUE && b == -1 và ném lỗi.

Dẫn tới JUnit: check(...) thủ công chính là tiền thân của assertEquals, checkNemLoi(...) là tiền thân của assertThrows. Sang 4.4 Testing bạn sẽ viết đúng những ca này bằng JUnit, chạy tự động trong build. Không dùng IO.println làm test trong code production.

14. Interview Q&A Hay hỏi phỏng vấn

Cơ bản

Câu 1. Method trong Java là gì? Khác gì function trong JavaScript?
Method là khối code có tên, nhận tham số và trả kết quả, thuộc về một class/interface/enum/record. Khác JavaScript, Java không cho phép hàm tự do đứng ngoài class. Trước Java 8, muốn truyền hàm phải dùng anonymous class; từ Java 8 có lambda/method reference nhưng vẫn phải gắn với functional interface.
Câu 2. Parameter và argument khác nhau thế nào?
Parameter là biến trong khai báo method (BigDecimal donGia); argument là giá trị thực tế trong lời gọi (tongTien(gia, 3)). Chúng khớp theo thứ tự, không theo tên — Java không có named arguments.
Câu 3. Vì sao main phải là public static void?
public để JVM từ ngoài package gọi được; static vì JVM gọi trước khi tạo object nào; void vì JVM không dùng giá trị trả về. JDK 25 (JEP 512) nới lỏng cho file đơn: instance void main() cũng chạy, nhưng public static void main(String[] args) vẫn là dạng phải thuộc lòng.
Câu 4. void nghĩa là gì? Làm sao thoát sớm khỏi method void?
void nghĩa là method không trả về giá trị. Dùng return; (không kèm giá trị) để thoát sớm — thường gặp trong guard clause: kiểm tra dữ liệu xấu rồi return ngay.
Câu 5. Java có tham số mặc định không? Muốn có hành vi tương tự thì làm sao?
Không có default parameter và không có named argument. Cách thay thế: overload (bản ít tham số gọi bản đầy đủ với giá trị mặc định) hoặc builder (mỗi tham số tùy chọn một method, có giá trị mặc định trong builder).
Câu 6. Overloading là gì? Hai method là overload của nhau khi nào?
Cùng tên trong cùng class nhưng khác danh sách tham số: khác số lượng, khác kiểu, hoặc khác thứ tự kiểu. Tên parameter không tính — đổi tên parameter giữ nguyên kiểu là vẫn trùng method.
Câu 7. Hai method chỉ khác return type có phải overload không? Vì sao?
Không, đó là lỗi compile "method ... is already defined". Trình biên dịch dùng method descriptor gồm tên + kiểu tham số (không có return type) để phân biệt. Nhìn bytecode qua javap: tang(int) và tang(int, int) là hai method khác nhau.
Câu 8. static method khác instance method thế nào?
Static thuộc class, gọi qua tên class, không có this, chỉ truy cập được thành phần static — nên không đọc được field instance. Instance thuộc object, gọi qua object, có this, truy cập mọi thành phần. JVM cần main static chính vì lý do đầu tiên.
Câu 9. Java truyền tham số theo giá trị hay tham chiếu?
Luôn theo giá trị (pass-by-value). Với object, giá trị được truyền là bản sao của địa chỉ, nên method sửa được nội dung object nhưng gán lại parameter (trỏ sang object khác) thì bên ngoài không đổi. Chi tiết stack/heap ở Biến trong Java — mục 7.
Câu 10. Một hàm đệ quy đúng cần gì? Khi nào dùng thay vòng lặp?
Cần base case (điều kiện dừng) và bước đệ quy tiến dần về base case. Dùng khi cấu trúc dữ liệu/bài toán mang tính đệ quy: cây, đồ thị, thư mục, JSON lồng nhau, backtracking, chia để trị. Dãy số/tính toán tuyến tính thì vòng lặp nhanh và an toàn hơn.

Nâng cao (Junior+)

Câu 11. Overload resolution chọn method theo thứ tự nào?
3 phase theo thứ tự, phase trước thắng: (1) chỉ widening, không boxing/unboxing; (2) cho phép boxing/unboxing; (3) cho phép varargs. Ví dụ có m(long) và m(Integer), gọi m(1) chọn bản long vì widening thuộc phase 1. Chi tiết ở Data Types — mục 9.
Câu 12. Có gui(String) và gui(Object), gọi gui(null) chọn bản nào?
Bản gui(String). null hợp lệ với mọi kiểu reference nên compiler chọn bản "cụ thể nhất" (most specific); String là subtype của Object. Nếu hai bản không có quan hệ cha-con (ví dụ Integer và Long), gọi xuLy(null) là lỗi compile "reference to xuLy is ambiguous".
Câu 13. Vì sao có cả m(long) và m(Integer), gọi m(1) lại vào bản long?
Vì overload resolution ưu tiên phase 1 (widening int → long, không boxing) trước phase 2 (boxing int → Integer). Đây là bẫy production: hai bản xử lý khác nhau, đặc biệt nếu bản Integer chấp nhận null, thì call site truyền số sẽ đi vào bản long.
Câu 14. List.remove(1) xóa gì? Muốn xóa theo giá trị thì viết thế nào?
remove(1) gọi remove(int index) — xóa phần tử ở vị trí 1 và trả về phần tử bị xóa. Muốn xóa theo giá trị phải ép boxing: remove(Integer.valueOf(1)) — gọi remove(Object), trả về boolean. Đây là ví dụ điển hình của việc chọn nhầm overload.
Câu 15. Vì sao đệ quy thiếu base case ném StackOverflowError mà không treo máy?
Mỗi lời gọi method tạo một stack frame trên stack của thread. Đệ quy vô hạn làm stack đầy; JVM phát hiện và ném StackOverflowError (là Error, message thường là null) để thread chết thay vì treo cả tiến trình. Vì vậy trong production không catch Error — hãy sửa thuật toán.
Câu 16. Java có tối ưu tail recursion (TCO) không?
Không. Tail call vẫn tạo stack frame mới và vẫn StackOverflowError — có thể kiểm chứng bằng hàm deQuyVoHan(n + 1). V8/Node.js cũng không hỗ trợ TCO. Muốn an toàn với độ sâu lớn, chuyển sang vòng lặp hoặc dùng cấu trúc dữ liệu ngăn xếp thủ công.
Câu 17. String[] args có bao giờ null không? Chạy java File.java a b có nhận args không?
args không bao giờ null; không truyền gì thì là mảng rỗng (length == 0). Chế độ chạy file đơn vẫn nhận đầy đủ args: java MainArgsDemo.java a b c cho args = [a, b, c]. Chỉ các option của chính lệnh java (ví dụ --enable-preview) mới phải đứng trước tên file.
Câu 18. JEP 512 (JDK 25) có gì liên quan tới method?
Compact source files cho phép bỏ khai báo class bao ngoài và dùng instance main method: void main() hoặc void main(String[] args) chạy trực tiếp bằng java File.java. Mục đích là giảm boilerplate cho người mới và script nhỏ; code production với build tool vẫn dùng dạng public static void main như trước. File compact cũng được tự động import các package của java.base.
Câu 19. Static factory method có lợi gì so với constructor? Cho ví dụ trong JDK.
Có tên rõ nghĩa (BigDecimal.valueOf thay vì new BigDecimal mơ hồ), có thể cache object (không bắt buộc tạo mới), có thể trả subtype ẩn, và có thể thực hiện logic trước khi tạo object. Ví dụ JDK: List.of, LocalDate.of, Integer.parseInt, Optional.empty.
Câu 20. Method chaining hoạt động thế nào? Vì sao StringBuilder chain được?
Mỗi method trả về đối tượng cho method kế tiếp gọi. StringBuilder.append trả về this nên chuỗi gọi tiếp trên cùng object. String cũng chain được nhưng mỗi bước trả về object mới (bất biến). Chaining là nền tảng của fluent API/builder; nếu quá dài thì khó debug nên tách ra.

15. Bài tập đoán output

Bài 1 
static void pick(long x)    { IO.println("long"); }
static void pick(Integer x) { IO.println("Integer"); }

pick(1);
pick(1L);
pick(Integer.valueOf(1));
In ra long, long, Integer. pick(1) và pick(1L) khớp bản long ngay phase 1 (widening). pick(Integer.valueOf(1)) là Integer — phase 1 khớp chính xác bản Integer nhờ identity, nên không cần unbox.
Bài 2 
static void gui(String s) { IO.println("String"); }
static void gui(Object o) { IO.println("Object"); }

gui(null);
In ra String. null khớp cả hai, compiler chọn bản cụ thể nhất — String là subtype của Object.
Bài 3 
List<Integer> nums = new ArrayList<>(List.of(10, 20, 30));
IO.println(nums.remove(1));
IO.println(nums);
IO.println(nums.remove(Integer.valueOf(30)));
IO.println(nums);
In ra 20, [10, 30], true, [10]. Bản đầu gọi remove(int index) (xóa theo vị trí, trả về phần tử); bản sau gọi remove(Object) (xóa theo giá trị, trả về boolean).
Bài 4 
static int tang(int a, int b = 1) {
    return a + b;
}

IO.println(tang(5));
Không chạy được. Java không có tham số mặc định; compile lỗi tại b = 1: "error: ',', ')', or '[' expected". Sửa bằng overload: thêm tang(int a) gọi tang(a, 1).
Bài 5 
static long giaiThua(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * giaiThua(n - 1);
}

IO.println(giaiThua(5));
IO.println(giaiThua(0));
In ra 120 rồi 1. giaiThua(5) = 5*4*3*2*1 = 120; base case n <= 1 trả 1 nên giaiThua(0) = 1.
Bài 6 
static int f(int n) {
    return f(n + 1);
}

IO.println(f(0));
Ném StackOverflowError (Exception in thread "main" java.lang.StackOverflowError), không phải treo máy vô hạn. Thiếu base case nên mỗi lời gọi đẩy thêm một stack frame tới khi đầy.
Bài 7 
public class Exercise07 {
    int count = 0;

    static void tang() {
        count++;
    }
}
Không compile. Lỗi: "non-static variable count cannot be referenced from a static context". Static method không có this nên không truy cập được field instance. Sửa: cho count thành static, hoặc biến tang() thành instance method.
Bài 8 
static void themDauCham(StringBuilder sb) {
    sb.append("!");
}

static void thayThe(StringBuilder sb) {
    sb = new StringBuilder("moi");
}

StringBuilder sb = new StringBuilder("hello");
themDauCham(sb);
IO.println(sb);
thayThe(sb);
IO.println(sb);
In ra hello! rồi hello!. append sửa nội dung object nên thấy thay đổi; gán lại parameter sb chỉ đổi bản sao reference, không ảnh hưởng biến ngoài.
Bài 9 
String s = new StringBuilder()
        .append("A")
        .append(1)
        .append(true)
        .toString();
IO.println(s);
In ra A1true. Mỗi append trả về this nên chain được; append nhận mọi kiểu dữ liệu và chuyển thành chuỗi.
Bài 10 
static int phiVanChuyen(int tongTien) {
    if (tongTien >= 500_000) {
        return 0;
    }
    return 30_000;
}

IO.println(phiVanChuyen(500_000));
IO.println(phiVanChuyen(499_999));
In ra 0 rồi 30000. Guard clause: đủ 500.000 thì miễn phí; ngược lại 30.000. Chú ý điều kiện dùng >= nên đúng mốc 500.000 được miễn.
Bài 11 
static String loai(int x)    { return "int"; }

IO.println(loai('a'));

In ra int, double, int, double. 5.0f (float) widening lên double; 'a' (char) widening lên int; 5L (long) chỉ còn đường widening lên double.

Checklist tự đánh giá trước phỏng vấn

  • Khai báo và gọi được method có tham số, return, void mà không cần tra cứu.
  • Phân biệt parameter và argument, kể cả khi phỏng vấn hỏi bằng tiếng Anh.
  • Giải thích được vì sao Java không có default param và hai cách thay thế.
  • Viết được 3 phiên bản overload của cùng một method và giải thích vì sao chúng hợp lệ.
  • Giải thích vì sao đổi return type / tên parameter không tạo overload mới.
  • Dự đoán đúng kết quả gui(null), pick(1) khi có pick(long)/pick(Integer).
  • Nhớ bẫy List.remove(1) và cách xóa theo giá trị.
  • Trả lời trôi chảy "Java pass-by-value hay pass-by-reference" kèm ví dụ.
  • Viết được hàm đệ quy có base case và giải thích StackOverflowError.
  • Phân biệt static/instance và biết khi nào không nên dùng static.
  • Biết args của main nhận từ dòng lệnh thế nào, kể cả chạy file đơn.
  • Nêu được 3 loại đầu vào cần test cho một method bất kỳ.
