Stream API — xử lý dữ liệu dạng dòng chảy

Stream API (Java 8+) biến việc xử lý tập dữ liệu thành một dây chuyền: khai báo nguồn, nối các bước biến đổi, rồi kết thúc bằng một thao tác cho ra kết quả. Bạn mô tả làm gì, Java lo làm thế nào. Đây là chủ đề phỏng vấn nặng thứ hai sau Collections — và cũng là nơi nhiều người viết code chạy được nhưng sai (one-shot, duplicate key, dùng peek làm logic).

1.1 Stream là gì

Stream là một view tính toán (view = góc nhìn) trên một nguồn dữ liệu: nó không phải cấu trúc lưu trữ, không chứa phần tử, không sửa nguồn. Hãy hình dung băng chuyền trong nhà máy: nguyên liệu nằm ở kho (Collection/mảng/file), băng chuyền (stream) chở từng món qua các trạm (filter, map, sorted), cuối băng chuyền có thùng hứng kết quả (collect/reduce/count).

  • Không lưu dữ liệu: stream chỉ giữ con trỏ tới nguồn và mô tả các bước xử lý.
  • Không sửa nguồn: list.stream().map(...) trả về dữ liệu mới; list vẫn nguyên vẹn. Muốn thay đổi nguồn, bạn tự gán kết quả trở lại.
  • Chỉ chạy một lần: mỗi stream gắn với đúng một lần duyệt; gọi terminal lần thứ hai ném IllegalStateException (mục 1.4).
  • Lazy: chưa gọi thao tác kết thúc thì chưa có gì chạy — kể cả khi bạn đã viết 10 bước biến đổi.
  • Duyệt nội bộ: bạn không tự viết i++; thư viện quyết định thứ tự và cách chia việc (điều kiện tiên quyết để chạy song song).

1.3 Pipeline 3 phần: source → intermediate → terminal

Mọi stream pipeline có đúng ba phần, theo thứ tự:

  1. Source — nguồn tạo stream: list.stream(), Arrays.stream(arr), Stream.of(...), Files.lines(path), IntStream.range(...).
  2. Intermediate operations — các bước biến đổi, trả về stream mới nên nối chuỗi được: filter, map, flatMap, sorted, distinct, limit, peek... Tất cả đều lười (lazy).
  3. Terminal operation — thao tác kết thúc, "bấm nút chạy" pipeline và cho kết quả hoặc side effect: collect, reduce, count, forEach, findFirst, anyMatch... Sau terminal, stream đã dùng hết.
import java.util.stream.Stream;

public class LazyDemo {
    public static void main() {
        Stream<String> s = Stream.of("an", "binh", "cuong")
                .filter(x -> {
                    IO.println("filter chay voi " + x);
                    return x.length() > 2;
                });
        IO.println("Da tao pipeline, chua co terminal nen chua in gi");
        long n = s.count();
        IO.println("count = " + n);
    }
}

  • Filter chạy qua từng phần tử theo thứ tự nguồn, không chạy "cả danh sách một lượt".
  • Kết quả count = 2 vì "an" dài 2 không thỏa length() > 2; "binh" và "cuong" thì thỏa.

1.4 Lazy evaluation & stream chỉ chạy một lần

Vì intermediate lười, không có terminal thì pipeline không chạy gì cả. Đây là lỗi im lặng hay gặp: viết một pipeline đẹp rồi quên collect/forEach/count — chương trình không báo lỗi, chỉ đơn giản là không làm gì. Ngược lại, terminal "đốt" stream: không thể tái sử dụng.

import java.util.List;
import java.util.stream.Stream;

public class OneShotDemo {
    public static void main() {
        Stream<String> s = List.of("an", "binh").stream();
        IO.println("lan 1: " + s.count());
        try {
            IO.println("lan 2: " + s.count());
        } catch (IllegalStateException e) {
            IO.println("IllegalStateException: " + e.getMessage());
        }
    }
}

2. Tạo Stream Junior+

Stream có thể sinh ra từ hầu hết nguồn dữ liệu trong JDK. Nắm chắc các cách tạo để không phải viết vòng lặp trung gian vô ích.

2.1 Từ Collection, mảng, giá trị — và builder/empty/concat

Ví dụ dưới đi qua các nguồn phổ biến nhất: Collection.stream(), Arrays.stream, Stream.of, IntStream.range/rangeClosed, Stream.builder, Stream.empty, Stream.concat.

import java.util.Arrays;
import java.util.List;
import java.util.stream.Collectors;
import java.util.stream.IntStream;
import java.util.stream.Stream;

public class StreamSourcesDemo {
    public static void main() {
        List<String> list = List.of("a", "b", "c");
        IO.println(list.stream().collect(Collectors.joining("-")));

        int[] nums = {3, 1, 2};
        IO.println(Arrays.stream(nums).sum());

        IO.println(Stream.of("x", "y").count());

        IO.println(IntStream.range(1, 4).boxed().toList());
        IO.println(IntStream.rangeClosed(1, 4).boxed().toList());

        Stream.Builder<String> b = Stream.builder();
        b.add("m");
        b.add("n");
        IO.println(b.build().collect(Collectors.joining(",")));

        IO.println(Stream.empty().count());
        IO.println(Stream.concat(Stream.of("1"), Stream.of("2")).collect(Collectors.joining("+")));
    }
}

  • Collection nào cũng có .stream(): List, Set, Queue, kể cả Map.entrySet().stream() (xem Collections).
  • IntStream.range(1, 4) là nửa mở — chứa 1, 2, 3; rangeClosed(1, 4) chứa 1, 2, 3, 4.

  • Stream.builder() hữu ích khi số lượng phần tử biết lúc chạy; Stream.concat nối đúng hai stream.

2.2 Primitive streams & boxing

Ngoài Stream<T>, JDK có ba stream chuyên cho kiểu nguyên thủy: IntStream, LongStream, DoubleStream. Chúng có sẵn sum(), average(), min(), max(), summaryStatistics() mà không cần boxing.

import java.util.List;
import java.util.stream.IntStream;

public class PrimitiveVsBoxedDemo {
    public static void main() {
        IO.println(IntStream.rangeClosed(1, 5).sum());
        IO.println(IntStream.rangeClosed(1, 5).average().orElse(0));
        IO.println(IntStream.range(1, 5).mapToObj(i -> i * i).toList());

        List<Integer> boxed = List.of(1, 2, 3);
        IO.println(boxed.stream().mapToInt(Integer::intValue).sum());
    }
}

2.3 Files.lines — đọc file theo dòng

Files.lines(path) trả về Stream<String>, mỗi dòng là một phần tử — cực hợp cho xử lý log/CSV. Stream này giữ tài nguyên file nên phải đóng bằng try-with-resources:

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.stream.Collectors;

public class FilesLinesDemo {
    public static void main() throws IOException {
        Path p = Files.createTempFile("stream-demo-", ".txt");
        Files.writeString(p, "cam\nxoai\nchuoi\n");
        try (var lines = Files.lines(p)) {
            IO.println(lines.filter(s -> s.length() > 3).collect(Collectors.joining(", ")));
        }
        Files.deleteIfExists(p);
    }
}
xoai, chuoi

Lưu ý: main ở đây khai báo throws IOException vì createTempFile/writeString/deleteIfExists đều là checked exception. Đọc/ghi file chi tiết ở I/O & Files; các nguồn tương tự gồm Files.list (liệt kê thư mục) và BufferedReader.lines.

Hai nguồn stream hữu ích khác của java.nio.file là Files.walk(dir) (duyệt đệ quy cả cây thư mục) và Files.find(dir, maxDepth, matcher) (duyệt có giới hạn độ sâu kèm lọc theo thuộc tính file). Cả hai trả Stream<Path>, cũng phải đóng bằng try-with-resources; chi tiết về Path/attribute xem I/O & Files:

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

public class FilesWalkDemo {
    public static void main() throws IOException {

            IO.println("find regular: " + find.count());

2.4 Stream vô hạn: generate & iterate

Stream.generate và Stream.iterate tạo stream vô hạn; bắt buộc ghép với limit, takeWhile hoặc một terminal có short-circuit, nếu không chương trình sẽ chạy mãi.

import java.util.stream.Collectors;
import java.util.stream.Stream;

public class InfiniteStreamDemo {
    public static void main() {
        IO.println(Stream.generate(() -> "x").limit(3).collect(Collectors.joining()));
        IO.println(Stream.iterate(1, n -> n * 2).limit(5).collect(Collectors.toList()));
        IO.println(Stream.iterate(1, n -> n <= 100, n -> n * 3).collect(Collectors.toList()));
    }
}

2.5 Bẫy nguồn dữ liệu: Stream.of(mảng nguyên thủy)

Stream.of nhận varargs T.... Khi truyền một mảng int[], Java không bung mảng ra thành các phần tử mà coi cả mảng là một phần tử duy nhất. Đây là bẫy kinh điển:

import java.util.Arrays;
import java.util.stream.Stream;

public class SourceTrapDemo {
    public static void main() {
        int[] arr = {1, 2, 3};
        IO.println("Stream.of(arr).count() = " + Stream.of(arr).count());
        IO.println("Arrays.stream(arr).count() = " + Arrays.stream(arr).count());

        var l = Stream.of("a", "b").toList();
        try {
            l.add("c");
        } catch (UnsupportedOperationException e) {
            IO.println("toList() khong sua duoc");
        }
    }
}

Arrays.stream(arr).count() = 3

Với mảng String[] thì Stream.of(arr) lại hoạt động đúng (vì String[] là T[]), nhưng để thống nhất và an toàn, hãy luôn dùng Arrays.stream(arr) khi nguồn là mảng. So sánh thêm cách tạo mảng ở Arrays. Còn Stream.toList() (Java 16) trả về list bất biến — thao tác add ném UnsupportedOperationException.

3. Intermediate operations Hay hỏi phỏng vấn

Intermediate operation nhận một stream, trả về một stream mới nên nối chuỗi được. Tất cả đều lười: chỉ mô tả công việc, chưa chạy. Có thể chia thành hai nhóm — nhóm không trạng thái (stateless) xử lý từng phần tử độc lập, và nhóm có trạng thái (stateful) phải nhớ dữ liệu để làm việc (chi tiết ở 3.7).

3.1 filter & map

filter(Predicate) giữ phần tử trả về true; map(Function) biến đổi mỗi phần tử thành một giá trị mới (có thể khác kiểu). Hai thao tác này là xương sống của gần như mọi pipeline.

import java.util.List;

public class FilterMapDemo {
    public static void main() {
        List<String> names = List.of("an", "binh", "cuong", "dung");
        List<String> kq = names.stream()
                .filter(s -> s.length() >= 4)
                .map(String::toUpperCase)
                .toList();
        IO.println(kq);

        List<Integer> nums = List.of(1, 2, 3, 4, 5);
        int tongBinhPhuong = nums.stream().mapToInt(n -> n * n).sum();
        IO.println(tongBinhPhuong);
    }
}

  • map là ánh xạ 1-1; không được trả về nhiều hơn một giá trị cho mỗi phần tử → muốn "một thành nhiều" hãy dùng flatMap (3.2).
  • Thứ tự đề xuất: filter trước map khi có thể, để biến đổi ít phần tử hơn. Nhưng nếu biến đổi là điều kiện để lọc (ví dụ trim rồi mới xét rỗng) thì phải map trước.
  • Integer::intValue, String::toUpperCase... là method reference — cú pháp gọn của lambda, học ở Lambda & Functional.

3.2 flatMap — làm phẳng cấu trúc lồng nhau

map biến mỗi phần tử thành một giá trị; flatMap biến mỗi phần tử thành một stream rồi nối tất cả lại. Dùng để làm phẳng List<List<T>> hoặc tách chuỗi.

import java.util.Arrays;
import java.util.List;

public class FlatMapDemo {
    public static void main() {
        List<List<String>> lop = List.of(
                List.of("an", "binh"),
                List.of("cuong"),
                List.of("dung", "em", "giang"));

        List<String> tatCa = lop.stream()
                .flatMap(List::stream)
                .toList();
        IO.println(tatCa);

        List<String> cau = List.of("xin chao", "java stream");
        IO.println(cau.stream()
                .flatMap(s -> Arrays.stream(s.split(" ")))
                .toList());
    }
}
[an, binh, cuong, dung, em, giang]
[xin, chao, java, stream]

Hình dung dễ nhớ: map(list -> list) cho Stream<List<String>>; flatMap(List::stream) "xả" mỗi list bên trong thành các phần tử rời rồi gộp lại thành Stream<String>. Biến thể primitive là flatMapToInt, flatMapToLong, flatMapToDouble.

3.3 distinct & sorted

  • sorted() sắp theo Comparable tự nhiên; sorted(Comparator) sắp tùy ý. Comparator học ở Collections — mục 8.

3.4 peek — chỉ để debug

3.6 takeWhile & dropWhile (Java 9)

Khác filter (duyệt hết và giữ mọi phần tử thỏa điều kiện rải rác), takeWhile/dropWhile hành xử theo tiền tố và dừng ngay khi điều kiện đổi:

import java.util.List;

public class TakeDropWhileDemo {
    public static void main() {
        List<Integer> nums = List.of(2, 4, 6, 7, 8, 10);
        IO.println(nums.stream().takeWhile(n -> n % 2 == 0).toList());
        IO.println(nums.stream().dropWhile(n -> n % 2 == 0).toList());
        IO.println(nums.stream().filter(n -> n % 2 == 0).toList());
    }
}
[2, 4, 6]
[7, 8, 10]
[2, 4, 6, 8, 10]
  • takeWhile lấy tiền tố dài nhất thỏa điều kiện, gặp 7 là dừng — dù 8, 10 vẫn chẵn.
  • dropWhile bỏ tiền tố đó, giữ phần còn lại nguyên vẹn (8, 10 vẫn nằm trong).
  • Trên stream song song, hai thao tác này chỉ nên dùng khi thứ tự gặp (encounter order) có ý nghĩa — nhớ điều này khi đọc code người khác.

3.9 mapMulti — thay thế flatMap khi cần hiệu quả (Java 16)

mapMulti(BiConsumer<T, Consumer<R>>) làm được việc 1-n giống flatMap, nhưng thay vì tạo một stream cho mỗi phần tử, hàm mapper đẩy trực tiếp từng kết quả vào Consumer mà JDK đưa cho. Nhờ vậy giảm object trung gian khi mỗi phần tử chỉ cho ra vài kết quả (đặc biệt là 0 hoặc 1).

mapMulti(BiConsumer<T, Consumer<R>>) → Stream<R>  ·  mapMultiToInt(BiConsumer<T, IntConsumer>) → IntStream 
import java.util.List;
import java.util.stream.Stream;

public class MapMultiDemo {
    public static void main() {
        List<List<String>> lop = List.of(List.of("an", "binh"), List.of("cuong"));

        IO.println(lop.stream().flatMap(List::stream).toList());
        IO.println(lop.stream()
                .<String>mapMulti((list, out) -> list.forEach(out))
                .toList());

        IO.println(Stream.of("a1", "b2", "c3")
                .mapMultiToInt((s, out) -> out.accept(s.charAt(1) - '0'))
                .sum());

        IO.println(Stream.of("a1", "b2", "c3")
                .mapMulti((s, out) -> {
                    out.accept(s.toUpperCase());
                    out.accept(s);
                })
                .toList());
    }
}
[an, binh, cuong]
[an, binh, cuong]
6
[A1, a1, B2, b2, C3, c3]
  • mapMulti phát huy lợi thế khi hàm biến đổi đơn giản và bạn muốn giảm allocation: không sinh Stream phụ cho từng phần tử như flatMap.
  • Đôi khi phải chỉ định kiểu kết quả tường minh, ví dụ .<String>mapMulti(...) như dòng thứ hai của ví dụ — dấu hiệu suy luận kiểu không đủ ngữ cảnh.
  • Biến thể primitive: mapMultiToInt, mapMultiToLong, mapMultiToDouble — tránh cả boxing lẫn stream phụ.
  • flatMap vẫn hợp lý khi hàm đã trả sẵn collection/stream (List::stream, tách chuỗi bằng Arrays.stream(s.split(" "))).

3.10 Gatherers — thao tác trung gian tuỳ biến (JDK 24+)

Stream.gather(Gatherer) là "khe cắm" cho intermediate operation tự viết hoặc tái sử dụng. JDK 24 đóng gói sẵn một số gatherer hữu ích trong java.util.stream.Gatherers: cửa sổ, gộp, quét luỹ tiến, map song song có giới hạn.

windowSliding(n)Cửa sổ trượt từng bước 1, các cửa sổ chồng lấn nhau
fold(supplier, fn)Gộp toàn bộ thành một kết quả duy nhất

import java.util.List;
import java.util.stream.Gatherers;
import java.util.stream.Stream;

public class GatherersDemo {
    public static void main() {
        IO.println(Stream.of(1, 2, 3, 4, 5)
                .gather(Gatherers.windowFixed(2)).toList());
        IO.println(Stream.of(1, 2, 3, 4, 5)
                .gather(Gatherers.windowSliding(2)).toList());
        IO.println(Stream.of(1, 2, 3, 4)
                .gather(Gatherers.fold(() -> 0, Integer::sum)).toList());
        IO.println(Stream.of(1, 2, 3, 4)
                .gather(Gatherers.scan(() -> 0, Integer::sum)).toList());
        IO.println(Stream.of(1, 2, 3, 4)
                .gather(Gatherers.mapConcurrent(4, n -> n * 10)).toList());

Gatherers.mapConcurrent gọi mapper trên nhiều virtual thread cùng lúc — chỉ dùng khi hàm thuần tuý, không side effect. Với stream có thứ tự, kết quả vẫn được phát theo encounter order; với nguồn unordered() thì không cam kết. Khác parallel(), gatherer này gom kết quả theo thứ tự và chỉ chạy tối đa n tác vụ đồng thời.

5.2 groupingBy — gom nhóm

6. Optional & flatMap trong pipeline Hay hỏi phỏng vấn

Dữ liệu thật thường có null (email chưa nhập, mã giảm giá không có...). Nếu map trả về Optional, pipeline sẽ thành Stream<Optional<T>> — gom lại sẽ đầy Optional.empty(). Cách xử lý gọn nhất từ Java 9 là flatMap(Optional::stream):

import java.util.List;
import java.util.Optional;

record Khach(String ten, String email) {}

public class OptionalStreamDemo {
    public static void main() {

                new Khach("An", "an@x.com"),
                new Khach("Binh", null),
                new Khach("Cuong", "cuong@x.com"));

                .map(k -> Optional.ofNullable(k.email()))
                .flatMap(Optional::stream)

                .map(Khach::email)
                .filter(e -> e != null)
                .findFirst()
                .orElse("khong co");
        IO.println(dauTien);

        Optional<String> tenNgan = ds.stream()
                .map(Khach::ten)
                .filter(t -> t.length() <= 2)
                .findFirst();

Parallel stream không tự tạo thread pool; nó dùng ForkJoinPool.commonPool() — pool dùng chung toàn tiến trình cho cả parallel stream, CompletableFuture, parallel()...

import java.util.concurrent.ForkJoinPool;

public class CommonPoolDemo {
    public static void main() {

        IO.println("so core: " + Runtime.getRuntime().availableProcessors());

Mặc định độ song song thường là số core − 1 (máy soạn tài liệu 10 core nên ra 9; tối thiểu là 1), có thể đổi bằng system property java.util.concurrent.ForkJoinPool.common.parallelism. Vì là pool chung, một tác vụ block (chờ I/O, khóa) sẽ chiếm mất một slot của tất cả mọi người trong JVM — đó là lý do tác vụ I/O không nên dùng parallel stream. Cần pool riêng thì tạo ForkJoinPool và gọi pool.submit(() -> stream.parallel()...).get(), nhưng đó là chủ đề concurrency nâng cao.

Như demo ở mục 4.1: forEach trên parallel in ra thứ tự lộn xộn (8 9 7 11 12 10 1 5 3 4 6 2 — khác nhau mỗi lần chạy), còn forEachOrdered luôn 1 2 3 ... 12. 7.5 Collectors cho parallel: groupingByConcurrent & toConcurrentMap

Với parallel stream, groupingBy/toMap thường vẫn chạy đúng nhưng phải ghép nhiều map con ở bước cuối. Hai collector "concurrent" cho phép các thread ghi thẳng vào một ConcurrentHashMap dùng chung — nhận biết để đọc code thư viện, không phải mặc định nên dùng.

import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

public class ConcurrentCollectorsDemo {
    public static void main() {
        List<String> ds = List.of("an", "binh", "an", "cuong", "binh", "an");

        Map<String, Long> dem = ds.parallelStream()
                .collect(Collectors.groupingByConcurrent(s -> s, Collectors.counting()));
        IO.println(dem.getClass().getSimpleName());
        IO.println(dem.get("an"));

        Map<String, Integer> doDai = ds.parallelStream()
                .collect(Collectors.toConcurrentMap(s -> s, String::length, Integer::max));
        String s = doDai.entrySet().stream()
                .sorted(Map.Entry.comparingByKey())
                .map(e -> e.getKey() + "=" + e.getValue())
                .collect(Collectors.joining(", "));
        IO.println(s);
    }
}

9.2 count() có thể "nuốt" cả pipeline

Vì count() không cần giá trị từng phần tử, JDK có quyền bỏ qua các bước trung gian chỉ khi nguồn có kích thước xác định (SIZED) và không có thao tác làm mất/đổi kích thước (filter, flatMap, distinct...). 10. Project: quản lý đơn hàng end-to-end Production

Ghép mọi thứ đã học vào một chương trình self-contained: record DonHang, danh sách mẫu, thống kê doanh thu, top sản phẩm, lọc + sort + top N và báo cáo dạng chuỗi. Chạy bằng java QuanLyDonHang.java.

import java.util.Comparator;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Collectors;

record DonHang(String ma, String khach, String trangThai, String sanPham, int soLuong, long donGia) {
    long thanhTien() {
        return soLuong * donGia;
    }

    boolean daHoanThanh() {
        return "HOAN_THANH".equals(trangThai);
    }
}

public class QuanLyDonHang {
    static final List<DonHang> DON_HANG = List.of(
            new DonHang("DH-001", "An", "HOAN_THANH", "Ban phim", 2, 350_000),
            new DonHang("DH-002", "Binh", "HOAN_THANH", "Chuot", 3, 150_000),
            new DonHang("DH-003", "An", "CHO_XU_LY", "Man hinh", 1, 2_400_000),
            new DonHang("DH-004", "Cuong", "HOAN_THANH", "Ban phim", 1, 350_000),
            new DonHang("DH-005", "Binh", "DA_HUY", "Tai nghe", 2, 550_000),
            new DonHang("DH-006", "Dung", "CHO_XU_LY", "Chuot", 5, 150_000),
            new DonHang("DH-007", "An", "HOAN_THANH", "Tai nghe", 1, 550_000),
            new DonHang("DH-008", "Cuong", "HOAN_THANH", "Man hinh", 1, 2_400_000),
            new DonHang("DH-009", "Dung", "HOAN_THANH", "Ban phim", 3, 350_000));

    public static void main() {
        IO.println("== 1. Tong doanh thu don hoan thanh ==");
        long tongDoanhThu = DON_HANG.stream()
                .filter(DonHang::daHoanThanh)
                .mapToLong(DonHang::thanhTien)
                .sum();
        IO.println(tongDoanhThu);

        IO.println("== 2. Doanh thu theo khach (chi hoan thanh) ==");
        Map<String, Long> theoKhach = DON_HANG.stream()
                .filter(DonHang::daHoanThanh)
                .collect(Collectors.groupingBy(DonHang::khach, TreeMap::new,
                        Collectors.summingLong(DonHang::thanhTien)));
        theoKhach.forEach((khach, tien) -> IO.println(khach + " -> " + tien));

        IO.println("== 3. So don & doanh thu theo trang thai ==");
        Map<String, String> theoTrangThai = DON_HANG.stream()
                .collect(Collectors.groupingBy(DonHang::trangThai, LinkedHashMap::new,
                        Collectors.teeing(
                                Collectors.counting(),
                                Collectors.summingLong(DonHang::thanhTien),
                                (dem, tien) -> dem + " don, " + tien + " d")));
        theoTrangThai.forEach((tt, mo) -> IO.println(tt + ": " + mo));

        IO.println("== 4. San pham ban chay (theo so luong, top 3) ==");
        String top3 = DON_HANG.stream()
                .collect(Collectors.groupingBy(DonHang::sanPham,
                        Collectors.summingInt(DonHang::soLuong)))
                .entrySet().stream()
                .sorted(Map.Entry.<String, Integer>comparingByValue().reversed()
                        .thenComparing(Map.Entry.comparingByKey()))
                .limit(3)
                .map(e -> e.getKey() + " x" + e.getValue())
                .collect(Collectors.joining(", "));
        IO.println(top3);

        IO.println("== 5. Top 3 don hoan thanh gia tri cao nhat ==");
        DON_HANG.stream()
                .filter(DonHang::daHoanThanh)
                .sorted(Comparator.comparingLong(DonHang::thanhTien).reversed())
                .limit(3)
                .forEach(d -> IO.println(d.ma() + " " + d.khach() + " " + d.thanhTien()));

        IO.println("== 6. Bao cao gop chuoi ==");
        String baoCao = DON_HANG.stream()
                .filter(DonHang::daHoanThanh)
                .sorted(Comparator.comparing(DonHang::ma))
                .map(d -> d.ma() + "(" + d.khach() + ":" + d.thanhTien() + ")")
                .collect(Collectors.joining(" | "));
        IO.println(baoCao);

        IO.println("== 7. Khach da mua san pham 'Ban phim' ==");
        String khachBanPhim = DON_HANG.stream()
                .filter(d -> d.sanPham().equals("Ban phim"))
                .map(DonHang::khach)
                .distinct()
                .sorted()
                .collect(Collectors.joining(", "));
        IO.println(khachBanPhim);
    }

  • JS không có parallel array built-in; muốn song song phải dùng worker_threads (tốn thiết lập, dữ liệu truyền qua structured clone). Java cho parallelStream() miễn phí nhưng kèm cạm bẫy mục 7.
  • Lodash chain có cơ chế LazyWrapper (gộp bước và short-circuit cho chuỗi dài) nên không hẳn eager, nhưng mức lazy không đầy đủ/không bao quát như Stream: nhiều thao tác vẫn tạo mảng trung gian, ngữ nghĩa one-shot và short-circuit khác. Hãy coi _.chain là "bản gần đúng", không phải tương đương.
  • for...of + break/continue là lựa chọn tốt cho logic phức tạp — tương tự lời khuyên "khi nào không nên dùng stream" ở mục 8.

12. Interview Q&A Hay hỏi phỏng vấn

Cơ bản

Câu 1. Stream là gì? Khác Collection ở điểm nào?
Stream là view tính toán trên một nguồn dữ liệu, không lưu trữ phần tử và không sửa nguồn. Collection là nơi chứa dữ liệu (eager, duyệt lại tùy ý, thêm/xóa được); Stream là cách xử lý dữ liệu (lazy, one-shot, bất biến về cấu trúc, có thể vô hạn, duyệt nội bộ). Câu chốt khi phỏng vấn: "Collection là nơi lưu, Stream là cách xử lý".
Câu 2. Một stream pipeline gồm những phần nào?
Ba phần: (1) source tạo stream — stream(), Arrays.stream, Stream.of, Files.lines...; (2) các intermediate operation lười, trả về stream mới — filter, map, flatMap, sorted...; (3) terminal operation kích hoạt toàn bộ pipeline và tiêu thụ stream — collect, reduce, count, forEach, findFirst...
Câu 3. Lazy evaluation là gì? Vì sao thiếu terminal thì pipeline không chạy?
Intermediate operation không thực thi ngay mà chỉ ghi lại "công thức"; chúng chỉ chạy khi terminal bắt đầu duyệt nguồn. Nhờ vậy JDK có thể gộp nhiều bước stateless vào một lượt duyệt, bỏ qua bước không cần (ví dụ count() có thể không chạy peek), và dừng sớm với short-circuit. Hệ quả: quên terminal = chương trình không làm gì nhưng cũng không lỗi.
Câu 4. Một stream dùng được mấy lần? Gọi terminal lần hai thì sao?
Đúng một lần. Sau terminal, stream bị đánh dấu đã tiêu thụ; gọi thêm thao tác ném IllegalStateException: stream has already been operated upon or closed. Muốn xử lý lại, hãy mở stream mới từ nguồn (list.stream() hai lần). Lưu ý ngay cả intermediate cũng tiêu thụ stream cũ để tạo stream mới.
Câu 5. Intermediate khác terminal thế nào? Kể vài ví dụ mỗi loại.
Intermediate trả về Stream nên nối chuỗi được, lười: filter, map, flatMap, distinct, sorted, limit, skip, peek, takeWhile. Terminal trả về kết quả hoặc void và kết thúc stream: collect, reduce, count, min/max, findFirst/findAny, anyMatch/allMatch/noneMatch, forEach/forEachOrdered, toArray.
Câu 6. filter và map khác nhau thế nào?
filter(Predicate) giữ lại phần tử thỏa điều kiện (quyết định giữ/bỏ, không đổi giá trị); map(Function) biến đổi mỗi phần tử thành giá trị mới (có thể đổi kiểu), luôn giữ nguyên số lượng phần tử. Muốn lọc thì filter; muốn chuyển đổi thì map; cả hai thường đi cặp.
Câu 7. flatMap khác map thế nào? Cho ví dụ.
map là ánh xạ 1-1; flatMap là 1-n: hàm trả về một stream cho mỗi phần tử, rồi tất cả được nối phẳng. Ví dụ List<List<String>>.stream().flatMap(List::stream) cho Stream<String>; hoặc tách câu thành từ: flatMap(s -> Arrays.stream(s.split(" "))). Nếu dùng map(List::stream) sẽ ra Stream<Stream<String>> — sai kiểu mong muốn.
Câu 8. reduce có mấy dạng? Vì sao bản không có identity trả Optional?
Ba dạng: reduce(identity, accumulator) trả về giá trị (stream rỗng → identity); reduce(accumulator) trả Optional<T>; reduce(identity, accumulator, combiner) cho stream song song. Bản không identity trả Optional vì stream rỗng không có phần tử nào để gộp — không có giá trị hợp lệ nào để trả, buộc caller xử lý trường hợp rỗng tường minh.
Câu 9. findFirst khác findAny thế nào? Dùng cái nào?
findFirst luôn trả phần tử đầu tiên theo encounter order; findAny được phép trả bất kỳ phần tử nào (trên stream song song thường nhanh hơn vì không cần đồng bộ thứ tự). Trên stream tuần tự kết quả thường giống nhau nhưng không được đảm bảo. Cần ổn định/test được → findFirst; chỉ cần "một phần tử bất kỳ" và tối ưu song song → findAny.
Câu 10. forEach khác forEachOrdered thế nào?
forEach không cam kết thứ tự, đặc biệt trên stream song song (output có thể đảo lộn mỗi lần chạy). forEachOrdered luôn chạy theo encounter order kể cả khi song song, nhưng phải đồng bộ nên giảm/khử lợi ích song song. Cần side effect đúng thứ tự thì dùng forEachOrdered.

Nâng cao (Junior+)

Câu 11. Stateless và stateful intermediate khác nhau? Ảnh hưởng gì?
Stateless (filter, map, flatMap, peek) xử lý từng phần tử độc lập, tốn O(1) bộ nhớ, gộp một lượt duyệt. Stateful (distinct, sorted, limit, skip, takeWhile) phải nhớ trạng thái/dữ liệu: sorted gom toàn bộ phần tử rồi mới sort (O(n) bộ nhớ), distinct giữ tập đã gặp. Vì vậy nên filter/map trước rồi mới sorted/distinct.
Câu 12. Short-circuit là gì? Những thao tác nào hỗ trợ?
Short-circuit là dừng xử lý ngay khi đã đủ kết quả, không cần duyệt hết nguồn. Intermediate hỗ trợ: limit, takeWhile. Terminal hỗ trợ: findFirst, findAny, anyMatch, allMatch, noneMatch. Nhờ short-circuit mà stream vô hạn + limit/findFirst chạy hữu hạn.
Câu 13. Bẫy của Collectors.toMap là gì? Cách sửa?
Nếu hai phần tử cho cùng khóa, toMap(keyMapper, valueMapper) ném IllegalStateException: Duplicate key ... (attempted merging values ...). Cách sửa: thêm merge function toMap(key, value, (a, b) -> ...) (cộng gộp, giữ a, giữ b...); hoặc dùng groupingBy nếu muốn giữ nhiều giá trị mỗi khóa; hoặc thêm map factory toMap(key, value, merge, TreeMap::new) để ổn định thứ tự.
Câu 14. Vì sao thứ tự Map của groupingBy không nên tin? Làm sao ổn định?
groupingBy mặc định trả HashMap — thứ tự khóa phụ thuộc hash, không theo thứ tự dữ liệu. Truyền map factory vào bản 3 tham số để kiểm soát: LinkedHashMap::new giữ thứ tự lần gặp đầu tiên, TreeMap::new sắp theo khóa. Tương tự với toSet()/toMap() — dùng LinkedHashSet/TreeMap khi cần thứ tự.
Câu 15. Primitive stream để làm gì? Bẫy Stream.of(int[]) ra sao?
IntStream/LongStream/DoubleStream tránh boxing, có sẵn sum/average/min/max/summaryStatistics, dùng cho dữ liệu số lớn. Đổi qua lại bằng mapToInt/boxed/mapToObj. Bẫy: Stream.of(arr) với int[] arr cho Stream<int[]> 1 phần tử (count = 1) vì varargs không bung mảng nguyên thủy — phải dùng Arrays.stream(arr).
Câu 16. Khi nào nên và không nên dùng parallel stream? Common ForkJoinPool là gì?
Nên: dữ liệu lớn, CPU-bound, hàm thuần túy độc lập, nguồn chia rẻ (ArrayList, mảng, IntStream.range). Tránh: I/O/blocking, dữ liệu nhỏ, thao tác phụ thuộc thứ tự (limit, findFirst), sửa shared state, nguồn chia đắt (LinkedList). Parallel stream dùng ForkJoinPool.commonPool() chung cho cả JVM (mặc định parallelism ≈ số core − 1); tác vụ block sẽ chiếm slot của mọi thành phần khác.
Câu 17. Vì sao lambda trong stream không ném được checked exception? Cách xử lý?
Vì Function, Predicate, Consumer... không khai báo throws checked exception, nên lời gọi hàm ném checked exception bên trong lambda là lỗi compile unreported exception. Cách xử lý: bọc thành UncheckedIOException/RuntimeException ngay trong lambda (giữ cause), hoặc viết helper wrap, hoặc chuyển sang vòng lặp nếu logic lỗi phức tạp.
Câu 18. Khi nào KHÔNG nên dùng stream thay vòng lặp?
Khi logic có nhiều nhánh/biến trung gian phức tạp; khi cần index hoặc phần tử lân cận; khi cần break/continue phức tạp; khi thân vòng lặp có checked exception hoặc side effect nghiệp vụ quan trọng; khi làm việc với mảng primitive nhỏ cần hiệu năng tối đa. Stream giúp code khai báo rõ ràng, không phải để thay thế mọi vòng lặp.
Câu 19. Optional::stream và Stream.ofNullable dùng khi nào?
Optional.stream() (Java 9) biến Optional có giá trị thành stream 1 phần tử, rỗng thành stream 0 phần tử — dùng flatMap(Optional::stream) để vừa map vừa loại bỏ empty trong một bước. Stream.ofNullable(t) (Java 9) tạo stream 0/1 phần tử tùy t có null — tránh NPE của Stream.of(null).
Câu 20. teeing và summarizingInt khác nhau thế nào?
Cùng là "một lượt duyệt ra nhiều số liệu". summarizingInt/Long/Double (Java 8) cho bộ thống kê cố định cùng kiểu: count/sum/min/average/max. teeing (Java 12) chạy hai collector bất kỳ — có thể khác kiểu, khác kết quả — rồi gộp bằng hàm thứ ba. Dùng summarizing khi đủ 5 chỉ số; dùng teeing khi cần hai kết quả khác loại, ví dụ vừa lấy danh sách vừa đếm.

13. Bài tập đoán output

Các đoạn dưới là thân chương trình của những file đã chạy thật bằng JDK 25. Hãy đoán output trước khi mở đáp án.

Bài 1 — Lazy và thứ tự chạy 
import java.util.stream.Stream;

Stream<String> s1 = Stream.of("a", "bb", "ccc")
        .peek(x -> IO.println("peek " + x));
IO.println("truoc terminal");
IO.println(s1.toList());
In ra: 
truoc terminal
peek a
peek bb
peek ccc
[a, bb, ccc]
peek là intermediate lười — chỉ chạy khi toList() (terminal) duyệt nguồn. Vì vậy dòng "truoc terminal" in trước, rồi từng phần tử đi qua peek theo thứ tự.
Bài 2 — Dùng lại stream 
var s2 = List.of(1, 2, 3).stream();
IO.println(s2.findFirst().orElse(0));
IO.println(s2.findFirst().orElse(0));
In ra 1 rồi ném IllegalStateException: stream has already been operated upon or closed. findFirst() là terminal, tiêu thụ stream ngay lần gọi đầu. Muốn lấy lại, phải gọi List.of(1, 2, 3).stream() lần nữa.
Bài 3 — filter rồi map 
IO.println(List.of(1, 2, 3, 4, 5, 6).stream()
        .filter(n -> n % 2 == 0)
        .map(n -> n / 2)
        .toList());
In ra [1, 2, 3]. Lọc được 2, 4, 6 rồi chia đôi thành 1, 2, 3. Thứ tự filter trước map giúp map chỉ chạy trên 3 phần tử thay vì 6.
Bài 4 — distinct và sorted 
IO.println(Stream.of("b", "a", "b", "c", "a").distinct().sorted().toList());
In ra [a, b, c]. distinct còn lại b, a, c (giữ lần gặp đầu) rồi sorted xếp thành a, b, c.
Bài 5 — Ba kiểu reduce 
IO.println(List.of("j", "a", "v", "a").stream().reduce("", String::concat));
IO.println(List.of(1, 2, 3).stream().reduce((a, b) -> a + b).orElse(-1));
IO.println(List.of(1, 2, 3).stream().reduce(10, Integer::sum));
In ra java, 6, 16. Dòng 1 ghép chuỗi từ identity "": j+a+v+a = "java". Dòng 2 không identity nên trả Optional, cộng 1+2+3 = 6. Dòng 3 bắt đầu từ 10: 10+1+2+3 = 16.
Bài 6 — groupingBy giữ thứ tự 
record Don(String khach, long tien) {}

Map<String, Long> m6 = List.of(
        new Don("Binh", 100), new Don("An", 200), new Don("Binh", 300))
        .stream()
        .collect(Collectors.groupingBy(Don::khach, LinkedHashMap::new,
                Collectors.summingLong(Don::tien)));
IO.println(m6);
In ra {Binh=400, An=200}. LinkedHashMap giữ thứ tự khách xuất hiện lần đầu: Binh rồi An; Binh có hai đơn 100 + 300 = 400. Nếu để mặc định HashMap, thứ tự in có thể khác — đừng dựa vào.
Bài 7 — Stream vô hạn + limit 
IO.println(Stream.iterate(2, n -> n * 3).limit(4).toList());
IO.println(Stream.iterate(1, n -> n + 1)
        .filter(n -> n % 10 == 0).limit(2).toList());
In ra [2, 6, 18, 54] rồi [10, 20]. Dòng đầu lấy 4 số đầu của dãy nhân 3. Dòng sau lọc bội số của 10 rồi lấy 2 số đầu. Đổi thứ tự thành limit(2).filter(n -> n % 10 == 0) thì kết quả là [], không phải [10, 20]: limit lấy 2 phần tử đầu tiên (1, 2) rồi mới lọc — không phần tử nào là bội của 10. Đây chính là minh chứng thứ tự của thao tác stateful (limit chặn dòng dữ liệu) quyết định kết quả, không chỉ hiệu năng.
Bài 8 — peek và short-circuit 
IO.println(Stream.of("an", "binh", "cuong")
        .peek(x -> IO.println("kiem tra " + x))
        .filter(x -> x.startsWith("c"))
        .findFirst()
        .orElse("khong co"));
In ra: 
kiem tra an
kiem tra binh
kiem tra cuong
cuong
findFirst short-circuit: nó phải chạy peek qua "an", "binh" (không thỏa filter) rồi dừng ngay tại "cuong". Không có dòng nào cho "dung" vì không có phần tử đó.
Bài 9 — toMap và merge function 
Map<String, Integer> m9 = List.of("a", "b", "a").stream()
        .collect(Collectors.toMap(s -> s, s -> 1, Integer::sum));
IO.println(m9);
In ra {a=2, b=1}. Không có merge function thì khóa "a" trùng sẽ ném IllegalStateException: Duplicate key a (attempted merging values 1 and 1). Ở đây merge bằng tổng nên a = 2.
Bài 10 — flatMap + mapToInt 
IO.println(List.of(List.of(1, 2), List.of(3)).stream()
        .flatMap(List::stream)
        .mapToInt(Integer::intValue)
        .sum());
In ra 6. flatMap làm phẳng thành 1, 2, 3; mapToInt tạo IntStream; sum() = 6. Lưu ý mapToInt ở đây không bắt buộc (Stream<Integer> cũng sum được nếu qua reduce), nhưng nó là cách "chuẩn" để dùng API primitive.
Bài 11 — count có nuốt peek không? 
long n = Stream.of("a", "bb", "ccc")
        .peek(x -> IO.println("peek " + x))
        .count();
IO.println("count = " + n);
Chỉ in ra count = 3 — không có dòng peek nào! Vì nguồn Stream.of(...) có kích thước xác định (SIZED) và pipeline không có thao tác làm mất/đổi kích thước (chỉ có peek), JDK biết ngay kết quả đếm nên bỏ qua intermediate. Chỉ cần thêm filter/flatMap/distinct, kích thước không còn xác định thì peek bắt buộc chạy — như minh hoạ ở mục 9.2. Đây là bằng chứng mạnh nhất cho quy tắc: không bao giờ đặt logic vào peek.

Checklist tự đánh giá trước phỏng vấn

  • Giải thích được "Collection là nơi lưu, Stream là cách xử lý" kèm bảng so sánh.

  • Nói được khi nào nên quay về vòng lặp for thay vì stream.
