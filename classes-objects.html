Classes & Objects — class và object trong Java

Class (lớp) là bản thiết kế; object (đối tượng) là thực thể cụ thể được tạo ra từ bản thiết kế đó bằng từ khóa new. Đây là bước ngoặt của khóa học: thay vì các biến rời rạc, bạn gom dữ liệu (field) và hành vi (method) vào cùng một class. Trang này đi từ class đầu tiên, constructor, this, static, thứ tự khởi tạo, access modifier, package, JavaBean tới các bẫy phỏng vấn và production.

1. Tổng quan & cách học

Hay hỏi phỏng vấn Junior+ Production

Hãy hình dung xây nhà: bản thiết kế (bản vẽ) quy định căn nhà có mấy phòng, cửa mở thế nào; còn ngôi nhà thật là thực thể được xây từ bản vẽ đó. Từ một bản thiết kế bạn xây được nhiều ngôi nhà, mỗi ngôi nhà có màu sơn, đồ đạc riêng. Class và object y hệt:

  • Class — bản thiết kế: khai báo class có những field (trạng thái) và method (hành vi) nào. Ví dụ: BankAccount có owner, balance, deposit(), withdraw().
  • Object — một thực thể cụ thể tạo bằng new BankAccount(): tài khoản của An, tài khoản của Bình... Mỗi object có dữ liệu riêng nhưng dùng chung code của class.

Vì sao Java gom mọi thứ vào class? Vì Java không có hàm tự do như JavaScript: mọi field, method — kể cả main — đều phải nằm trong class, interface, enum hoặc record. Ngay cả file compact của JDK 25 (mục 11) cũng chỉ là cách viết tắt cho một class ẩn. Đây chính là điều làm Java nghiêm ngặt hơn JS nhưng cũng rõ ràng hơn khi codebase lớn.

Mức độ bắt buộc của chủ đề 2.1 (phỏng vấn: rất cao · production: bắt buộc):

  • Phải làm được — khai báo class với field/method; tạo object bằng new; viết constructor (mặc định, có tham số, overload, chaining this(...)); phân biệt this và static; đọc thành thạo bảng access modifier; đặt package/import đúng.
  • Phải hiểu — object nằm trên heap còn biến reference nằm trên stack (ôn lại Biến trong Java — mục 7); thứ tự static → instance initializer → constructor; default constructor chỉ được sinh khi bạn không khai báo constructor nào; static field dùng chung giữa mọi object nên rất dễ thành bẫy.
  • Nhận biết — JEP 512 (file compact, instance main, IO.println) và JEP 513 (linh hoạt vị trí this()/super()) của JDK 25; record thay thế JavaBean cho DTO bất biến (2.2 Encapsulation); Singleton dùng private constructor (2.8 SOLID & patterns).

Cách học hiệu quả nhất:

  1. Đoán output của ví dụ trước khi nhìn comment kết quả.
  2. Làm mục Bài tập đoán output trước, chỉ mở đáp án sau khi đã đoán.
  3. Ôn nhanh bằng Cheat sheet & checklist trước buổi phỏng vấn.
  4. Gặp câu lạ, tra ở mục Interview Q&A.

Góc Node.js — nhìn nhanh

JavaScript tạo object "tức thì" bằng object literal: const acc = { owner: "An", balance: 0 }; — không cần class nào cả. Java thì ngược lại: phải khai báo class trước, rồi mới new ra object. Ngoài ra this trong JS thay đổi theo cách gọi hàm, còn this trong Java cố định là object hiện tại. Bảng so sánh đầy đủ ở mục 12.

Ví dụ dùng IO.println(...) — cách viết gọn của JDK 25 (JEP 512), tương đương System.out.println(...) mà bạn sẽ thấy trong đề phỏng vấn và tài liệu cũ. Các ví dụ chạy bằng java TenFile.java (không cần javac).

2. Class & object đầu tiên

Một class tối thiểu gồm field (dữ liệu của object) và method (hành vi xử lý dữ liệu đó):

[access modifier] class TenClass { field...; method...; }

Ví dụ đầy đủ đầu tiên — tài khoản ngân hàng:

public class BankAccount {
    String owner;
    long balance;

    void deposit(long amount) {
        balance += amount;
    }

    void withdraw(long amount) {
        if (amount > balance) {
            IO.println("So du khong du");           // So du khong du
            return;
        }
        balance -= amount;
    }

    public static void main() {
        BankAccount acc = new BankAccount();
        acc.owner = "An";
        acc.balance = 500_000;
        acc.deposit(200_000);
        IO.println(acc.owner + ": " + acc.balance); // An: 700000
        acc.withdraw(1_000_000);
        acc.withdraw(300_000);
        IO.println(acc.owner + ": " + acc.balance); // An: 400000
    }
}

Đọc từng phần:

  • String owner; long balance; — hai field (còn gọi là instance variable). Mỗi object có bản riêng. Field chưa gán vẫn có giá trị mặc định: null cho reference, 0 cho số, false cho boolean.
  • deposit(), withdraw() — method thao tác trên chính field của object đang gọi (ngầm hiểu là this.balance).
  • new BankAccount() — cấp phát object mới trên heap, gọi constructor (ở ví dụ này là default constructor vì chưa khai báo constructor nào), rồi trả về địa chỉ của object.
  • BankAccount acc — biến reference nằm trên stack, chứa địa chỉ trỏ tới object trên heap. Gán acc = null nghĩa là không trỏ tới đâu cả.

Một class tạo được vô số object độc lập — sửa object này không ảnh hưởng object kia:

BankAccount a = new BankAccount();
BankAccount b = new BankAccount();
a.owner = "An";
b.owner = "Binh";
IO.println(a.owner);   // An
IO.println(b.owner);   // Binh
Truyền object vào method cũng là pass-by-value với reference copy — đã học kỹ ở Biến trong Java — mục 7. Cả hai biến cùng trỏ một object thì sửa nội dung thấy nhau, nhưng gán lại biến này không đổi biến kia.

3. Constructor Hay hỏi phỏng vấn

Constructor là khối code chạy đúng một lần khi object được tạo bằng new, dùng để đưa object về trạng thái hợp lệ ban đầu. Cú pháp:

[access modifier] TenClass(kieuThamSo tenThamSo, ...) { }
  • Tên constructor trùng tên class, không có kiểu trả về — viết void BankAccount() là biến nó thành method thường, không phải constructor.
  • Không được kế thừa, không gọi trực tiếp như method thường; chỉ chạy qua new hoặc qua this(...)/super(...).
  • Default constructor (constructor mặc định, không tham số, thân rỗng) chỉ được compiler sinh ra khi class không khai báo constructor nào. Nó có cùng access modifier với class.

Class không khai báo constructor nào vẫn tạo được object — field nhận giá trị mặc định:

public class BankAccount {
    String owner;
    long balance;

    public static void main() {
        BankAccount acc = new BankAccount();   // dung default constructor
        IO.println(acc.owner);                 // null
        IO.println(acc.balance);               // 0
    }
}
Bẫy kinh điển: chỉ cần bạn khai báo một constructor có tham số, default constructor biến mất. Gọi new BankAccount() lúc đó là lỗi compile:
BankAccount.java:9: error: constructor BankAccount in class BankAccount cannot be applied to given types;
        new BankAccount();
        ^
  required: String
  found:    no arguments
  reason: actual and formal argument lists differ in length
1 error

Constructor có tham số & overload

Constructor cũng overload được như method: cùng tên class, khác danh sách tham số. Các constructor có thể gọi nhau bằng this(...) — gọi là constructor chaining — để tránh lặp code khởi tạo:

public class BankAccount {
    String owner;
    long balance;

    BankAccount() {
        this("Chua ro");               // goi BankAccount(String)
    }

    BankAccount(String owner) {
        this(owner, 0);                // goi BankAccount(String, long)
    }

    BankAccount(String owner, long balance) {
        this.owner = owner;
        this.balance = balance;
    }

    public static void main() {
        BankAccount a = new BankAccount();
        BankAccount b = new BankAccount("Binh");
        BankAccount c = new BankAccount("Cuong", 1_000_000);
        IO.println(a.owner + " / " + a.balance);   // Chua ro / 0
        IO.println(b.owner + " / " + b.balance);   // Binh / 0
        IO.println(c.owner + " / " + c.balance);   // Cuong / 1000000
    }
}

new BankAccount() chạy constructor 0 tham số → nó gọi this("Chua ro") → constructor 1 tham số lại gọi this("Chua ro", 0) → constructor đầy đủ gán field. Chuỗi this(...) luôn kết thúc ở constructor "đầy đủ nhất".

JDK 25 — JEP 513: this(...) không còn buộc phải đứng đầu

Quy tắc cổ điển (mọi tài liệu và đề phỏng vấn trước đây): this(...)/super(...) phải là câu lệnh đầu tiên. Từ JDK 25, JEP 513 (Flexible Constructor Bodies) cho phép đặt một số câu lệnh trước, miễn là chúng không đọc object đang được tạo (được phép gán field của chính class đó, tính toán, validate). Đọc field hoặc gọi instance method trước this(...) vẫn là lỗi compile:

BankAccount() {
    IO.println(this.owner);   // loi compile: chua duoc doc instance
    this("An");
}
BankAccount.java:9: error: cannot reference this before supertype constructor has been called
        IO.println(this.owner);
                   ^
1 error
Khi phỏng vấn, hãy trả lời theo cách cổ điển ("phải là câu lệnh đầu tiên") rồi bổ sung: từ JDK 25 (JEP 513) quy tắc được nới lỏng cho các câu lệnh không chạm vào object đang tạo. Khi viết code, cứ đặt this(...) đầu tiên cho dễ đọc — đó vẫn là style phổ biến.

Constructor private

Constructor có thể mang access modifier. private nghĩa là chỉ class đó gọi được — bên ngoài không tạo được object trực tiếp. Đây là nền tảng của Singleton (học ở 2.8 SOLID & design patterns) và của static factory method:

// BankAccount.java
public class BankAccount {
    private BankAccount() {
    }
}

// SavingsAccount.java
public class SavingsAccount {
    void moTaiKhoan() {
        new BankAccount();
    }
}
SavingsAccount.java:3: error: BankAccount() has private access in BankAccount
        new BankAccount();
        ^
1 error

4. this

this là reference trỏ tới object hiện tại — object đang gọi instance method hoặc đang được constructor tạo. Bốn công dụng chính:

  • Phân biệt field với tham số/local trùng tên (shadowing): this.owner = owner; — bên trái là field, bên phải là tham số.
  • Gọi method của chính object: this.log(...) — thường viết gọn log(...) là đủ, dùng this. khi cần nhấn mạnh.
  • Gọi constructor khác: this(...) (đã học ở mục 3).
  • Truyền chính object này đi nơi khác: other.receive(this, amount), hoặc return this; để nối chuỗi method (fluent API).
public class BankAccount {
    String owner;
    long balance;

    BankAccount(String owner, long balance) {
        this.owner = owner;                    // this.owner la field
        this.balance = balance;                // owner/balance ben phai la tham so
    }

    void withdraw(long amount) {
        if (amount > balance) {
            IO.println("Khong du tien");       // in khi rut qua so du
            return;
        }
        balance -= amount;
        this.log("rut " + amount);             // goi method qua this
    }

    void log(String giaoDich) {
        IO.println(this.owner + ": " + giaoDich);   // An: rut 200000
    }

    void transfer(BankAccount other, long amount) {
        this.withdraw(amount);
        other.receive(this, amount);           // truyen chinh object nay
    }

    void receive(BankAccount from, long amount) {
        balance += amount;
        IO.println(owner + " nhan " + amount + " tu " + from.owner);
        // Binh nhan 200000 tu An
    }

    BankAccount deposit(long amount) {          // tra ve this -> chain duoc
        balance += amount;
        return this;
    }

    public static void main() {
        BankAccount an = new BankAccount("An", 500_000);
        BankAccount binh = new BankAccount("Binh", 100_000);
        an.transfer(binh, 200_000);
        an.deposit(50_000).deposit(30_000);     // fluent API
        IO.println("An: " + an.balance);        // An: 380000
        IO.println("Binh: " + binh.balance);    // Binh: 300000
    }
}

Nhờ deposit trả về this, ta gọi được an.deposit(50_000).deposit(30_000) — kết quả cộng dồn 80.000. Đây là cách StringBuilder và mọi builder/fluent API hoạt động (đã gặp ở Methods — mục 10).

this chỉ tồn tại trong instance context. Trong static method không có object nào gắn với lời gọi, nên this không tồn tại — xem mục 5.

5. static Hay hỏi phỏng vấn Junior+

static nghĩa là "thuộc về class, không thuộc về object nào". Có 3 dạng bạn cần nắm: static field, static method, static block (và biến thể static final cho hằng số).

5.1 Static field — dữ liệu dùng chung

Field thường: mỗi object một bản. Static field: một bản duy nhất cho cả class, mọi object cùng đọc/ghi. Ví dụ đếm số tài khoản đã tạo:

public class BankAccount {
    static int soTaiKhoan = 0;      // cua class, dung chung
    String owner;                   // cua tung object

    BankAccount(String owner) {
        this.owner = owner;
        soTaiKhoan++;               // moi object tao ra tang bien chung
    }

    static int tongSoTaiKhoan() {
        return soTaiKhoan;
    }

    public static void main() {
        new BankAccount("An");
        new BankAccount("Binh");
        new BankAccount("Cuong");
        IO.println(BankAccount.tongSoTaiKhoan());    // 3
        IO.println("soTaiKhoan = " + soTaiKhoan);    // soTaiKhoan = 3
    }
}

5.2 Static method — không có this

Static method thuộc class, gọi qua TenClass.method(), không có this, nên không đọc/ghi được field instance một cách trực tiếp. Vi phạm bị chặn ngay khi compile:

BankAccount.java:5: error: non-static variable balance cannot be referenced from a static context
        balance = 0;
        ^
1 error

Vì sao main phải static? JVM gọi main trước khi có object nào — không thể gọi instance method khi chưa có object. Tương tự, các hàm tiện ích thuần túy như Math.max, Objects.requireNonNull, Integer.parseInt đều là static.

5.3 Static block — chạy một lần khi class được nạp

Static block chạy một lần duy nhất khi class được khởi tạo lần đầu (lười — chỉ khi class thật sự được dùng, không phải lúc mở chương trình). Dùng để khởi tạo static final phức tạp:

public class BankAccount {
    static final String BANK_NAME = "Java Bank";
    static final long MIN_BALANCE;

    static {                                     // chay 1 lan khi class duoc nap
        MIN_BALANCE = 50_000;
        IO.println("static block chay 1 lan khi class duoc nap");
    }

    String owner;

    BankAccount(String owner) {
        this.owner = owner;
    }

    public static void main() {
        new BankAccount("An");
        new BankAccount("Binh");
        IO.println(BANK_NAME + " / MIN_BALANCE = " + MIN_BALANCE);
        // Ket qua 2 dong:
        // static block chay 1 lan khi class duoc nap
        // Java Bank / MIN_BALANCE = 50000
    }
}

Hai object được tạo nhưng dòng trong static block chỉ in một lần. static final là hằng số: quy ước đặt tên UPPER_SNAKE_CASE.

5.4 Static import

Static import cho phép gọi thành viên static mà không cần tên class:

import static java.lang.Math.PI;
import static java.lang.Math.max;

public class BankAccount {
    public static void main() {
        IO.println(PI);             // 3.141592653589793
        IO.println(max(100, 200));  // 200
    }
}

Nhưng lạm dụng dễ gây trùng tên — hai static import cùng tên làm lời gọi mơ hồ, lỗi compile:

import static java.lang.Math.min;
import static java.lang.StrictMath.min;

public class BankAccount {
    public static void main() {
        IO.println(min(1, 2));   // loi compile: min mo ho
    }
}
BankAccount.java:6: error: reference to min is ambiguous
        IO.println(min(1, 2));
                   ^
  both method min(int,int) in StrictMath and method min(int,int) in Math match
1 error
Chỉ static import khi thật rõ nghĩa (Math.PI, hằng số của chính dự án). Tránh import static ...* vì khó biết tên nào đến từ đâu.
Static mutable là bẫy production lớn nhất: static field dùng chung giữa mọi thread; count++ không nguyên tử nên nhiều thread xen kẽ sẽ mất cập nhật (race condition). Nguyên tắc: hạn chế tối đa static mutable, cần đếm thì dùng AtomicLong — chi tiết ở Biến trong Java — mục 15.3.

6. Thứ tự khởi tạo đầy đủ Hay hỏi phỏng vấn

Đây là câu hỏi phỏng vấn kinh điển. Khi bạn new BankAccount(), thứ tự diễn ra như sau:

  1. Class initialization (một lần cho mỗi class loader, khi class được dùng lần đầu): static field initializer và static block chạy theo đúng thứ tự khai báo trong source.
  2. Cấp phát object trên heap: mọi field instance nhận giá trị mặc định (0, false, null).
  3. Gọi constructor. Nếu constructor gọi this(...) thì chạy constructor được trỏ tới; nếu không, compiler chèn super() ngầm (class cha chạy trước — học ở 2.3 Inheritance).
  4. Instance field initializer và instance initializer block chạy theo thứ tự khai báo (chỉ một lần, ở constructor được gọi cuối cùng trong chuỗi).
  5. Phần đầu constructor thực thi — nơi bạn thấy các dòng IO.println.
public class BankAccount {
    static int soTaiKhoan = dem("1. static field");

    static {
        IO.println("2. static block");              // 2. static block
    }

    String owner = datTen("3. instance field");
    long balance;

    {
        IO.println("4. instance initializer");      // 4. instance initializer
    }

    BankAccount() {
        IO.println("5. constructor");               // 5. constructor
    }

    static int dem(String nhan) {
        IO.println(nhan);                           // 1. static field
        return 0;
    }

    static String datTen(String nhan) {
        IO.println(nhan);                           // 3. instance field
        return "An";
    }

    public static void main() {
        IO.println("--- new lan 1 ---");
        new BankAccount();
        IO.println("--- new lan 2 ---");
        new BankAccount();
    }
}

Kết quả chạy thật (JDK 25):

1. static field
2. static block
--- new lan 1 ---
3. instance field
4. instance initializer
5. constructor
--- new lan 2 ---
3. instance field
4. instance initializer
5. constructor
  • Phần static chạy trước cả dòng đầu tiên của main vì gọi main đã kích hoạt class initialization của BankAccount.
  • Instance field initializer + instance initializer block chạy lại mỗi lần new, nhưng luôn trước thân constructor.
  • Nếu class được dùng từ một class khác, static block chỉ chạy ở lần dùng đầu tiên, có thể muộn hơn thời điểm chương trình bắt đầu.
Class cha khởi tạo trước class con, và constructor cha chạy trước constructor con. Chủ đề này sẽ học kỹ ở 2.3 Inheritance; ở đây chỉ cần nhớ thứ tự static → instance init → constructor.

7. Access modifiers Junior+

Java có 4 mức truy cập, xếp từ hẹp tới rộng: private < default (package-private) < protected < public. Bảng dưới là thứ bạn phải nhớ chính xác:

  • Top-level class chỉ được là public hoặc không viết gì (package-private). Không được private/protected — vì "riêng tư với ai?" không có nghĩa ở cấp file. Class lồng nhau (nested) mới dùng được đủ 4 mức (học ở 2.7 Enum, nested & sealed).
  • Best practice: field luôn để private; chỉ mở method cần thiết. Đây chính là encapsulation — học sâu ở 2.2 Encapsulation & Immutability.
  • protected có "điều kiện": subclass ở package khác chỉ truy cập được qua reference có kiểu là chính subclass đó (hoặc con của nó), không truy cập qua reference kiểu class cha.

Kiểm chứng điều kiện của protected — cùng đoạn code, một dòng lỗi một dòng hợp lệ:

8. Package & import

Package là cách Java tổ chức class thành namespace: tránh trùng tên, phân quyền truy cập, và nhóm code theo nghiệp vụ. Khai báo package phải là dòng đầu tiên của file, và đường dẫn thư mục phải khớp tên package:

package com.shop.bank; // file nằm ở com/shop/bank/TenFile.java

Ví dụ hai class cùng package shop truy cập được thành viên package-private của nhau:

// File: shop/BankAccount.java
package shop;

public class BankAccount {
    String owner = "An";            // package-private

    void inThongTin() {             // package-private
        IO.println("Tai khoan cua " + owner);
    }

    public static void main() {
        new SavingsAccount().moTaiKhoan();
    }
}

// File: shop/SavingsAccount.java
package shop;

public class SavingsAccount {
    void moTaiKhoan() {
        BankAccount acc = new BankAccount();
        acc.inThongTin();           // cung package -> truy cap duoc
    }
}

Chạy từ thư mục cha: java shop/BankAccount.java — kết quả một dòng Tai khoan cua An. Nếu đặt file sai chỗ so với package, launcher báo lỗi ngay:

error: end of path to source file does not match its package name shop: BankAccount.java

Về import:

  • import java.util.List; — import một class cụ thể; import java.util.*; — import cả package (on-demand). Trong code production nên import cụ thể để thấy rõ phụ thuộc.
  • Không import gì thì vẫn dùng được fully-qualified name: java.math.BigDecimal x = new java.math.BigDecimal("10.5");.
  • Package java.lang được tự động import trong mọi file: String, Math, System, và cả IO của JDK 25.
  • Static import đã học ở mục 5.4.
Quy ước đặt tên package: chữ thường, tên miền đảo ngược — com.shop.bank cho shop.com. Dự án học tập không có tên miền thì dùng com.example hoặc shop như ví dụ trên. Package ảnh hưởng trực tiếp tới access modifier — xem lại bảng ở mục 7.

9. JavaBean & POJO Production

Hai thuật ngữ bạn gặp liên tục trong tài liệu Spring/JPA/Jackson:

  • POJO (Plain Old Java Object) — class Java "thuần": chỉ có field, constructor, method, không kế thừa class framework, không implement interface đặc biệt. Nghĩa rộng, gần như mọi class bạn tự viết.
  • JavaBean — POJO theo bộ quy ước chặt: (1) constructor không tham số, (2) field private, (3) truy cập qua cặp getter/setter theo tên property, (4) thường implements Serializable.
public class BankAccount {
    private String owner;
    private long balance;

    public BankAccount() {
    }

    public String getOwner() {
        return owner;
    }

    public void setOwner(String owner) {
        this.owner = owner;
    }

    public long getBalance() {
        return balance;
    }

    public void setBalance(long balance) {
        this.balance = balance;
    }

    public static void main() {
        BankAccount acc = new BankAccount();
        acc.setOwner("An");
        acc.setBalance(500_000);
        IO.println(acc.getOwner() + ": " + acc.getBalance());   // An: 500000
    }
}

Vì sao phải đúng quy ước? Vì framework dùng reflection (học ở 2.9 Annotations & Reflection) để đọc/ghi property theo tên method: Jackson cần no-arg constructor + getter/setter để chuyển object sang JSON và ngược lại; JPA/Hibernate cần no-arg constructor + field không final để tạo entity từ DB. Quy ước getter boolean là isActive() chứ không phải getActive().

Với DTO bất biến, record gọn và an toàn hơn JavaBean: chỉ một dòng record BankAccount(String owner, long balance) {} là có constructor, accessor, equals/hashCode/toString. Khi nào dùng record thay JavaBean — xem 2.2 Encapsulation & Immutability. JPA entity thì không dùng record được vì cần no-arg constructor.

10. Pitfalls thường gặp Production

Bảng tổng hợp các bẫy hay gặp nhất, kèm cách phòng tránh:

BẫyVí dụ / biểu hiệnHậu quả & cách tránh
Quên new BankAccount acc = null; acc.deposit(100); NullPointerException khi gọi method. Compiler không bắt được vì kiểu vẫn đúng — luôn khởi tạo trước khi dùng.
So object bằng == a == b với hai object cùng nội dung == so địa chỉ, không so nội dung → false. Dùng equals() — đào sâu ở 2.6 equals / hashCode / toString.
Shadowing khi gán trong constructor BankAccount(String owner) { owner = owner; } Gán tham số cho chính nó, field giữ null. Luôn viết this.owner = owner;.
Static field mutable static int count; rồi count++ từ nhiều thread Race condition, kết quả mỗi lần chạy một khác. Dùng AtomicLong hoặc tránh static mutable (Biến — 15.3).
Constructor gọi method overridable Constructor gọi method mà class con có thể override Method của class con chạy khi field class con chưa được khởi tạo → thấy 0/null. Chỉ gọi phương thức private/final/static trong constructor (2.3 Inheritance).
Hai class public trong một file public class BankAccount {} + public class SavingsAccount {} chung file Lỗi compile; mỗi file chỉ tối đa một top-level class public, tên file phải trùng tên class đó.

Quên new — lỗi runtime phổ biến nhất của người mới học, JDK 25 cho message khá rõ:

public class BankAccount {
    static BankAccount acc;        // mac dinh null - quen new
    long balance;

    void deposit(long amount) {
        balance += amount;
    }

    public static void main() {
        try {
            acc.deposit(100);
        } catch (NullPointerException e) {
            IO.println(e.getMessage());
            // Cannot invoke "BankAccount.deposit(long)" because "BankAccount.acc" is null
        }
    }
}

Hai object cùng nội dung vẫn là hai thực thể khác nhau trên heap:

public class BankAccount {
    String owner;

    BankAccount(String owner) {
        this.owner = owner;
    }

    public static void main() {
        BankAccount a = new BankAccount("An");
        BankAccount b = new BankAccount("An");
        BankAccount c = a;
        IO.println(a == b);                   // false
        IO.println(a == c);                   // true
        IO.println(a.owner.equals(b.owner));  // true
    }
}

11. Ghi chú JDK 25

Ba điểm mới của JDK 25 ảnh hưởng trực tiếp tới chủ đề này:

  • IO.println (JEP 512) — class java.lang.IO nằm trong java.lang nên được import tự động ở mọi file. Đây là cách viết gọn thay System.out.println trong tài liệu cũ; bản chất IO vẫn ghi ra System.out.
  • Compact source file & instance main (JEP 512) — file đơn không bắt buộc khai báo class, có thể dùng void main() (không static):
void main() {
    IO.println("compact source file: khong can khai bao class");
}

// chay: java CompactDemo.java
// compact source file: khong can khai bao class
  • Flexible constructor bodies (JEP 513) — this(...)/super(...) không còn bắt buộc là câu lệnh đầu tiên (đã trình bày ở mục 3).
Khi đọc code production hoặc đề phỏng vấn, bạn vẫn sẽ gặp public class X { public static void main(String[] args) { ... } } cùng System.out.println. Compact source chỉ là cú pháp tiện cho học tập/script nhỏ; class đầy đủ vẫn là chuẩn của dự án lớn (Spring Boot, Maven/Gradle).

13. Interview Q&A Hay hỏi phỏng vấn

Cơ bản

Câu 1. Class và object khác nhau thế nào? Cho ví dụ ngoài đời.
Class là bản thiết kế/bản vẽ — quy định có field và method nào nhưng chưa chiếm dữ liệu thật. Object là thực thể cụ thể tạo bằng new từ bản thiết kế đó. Ví dụ: class BankAccount là biểu mẫu mở tài khoản; object là tài khoản của An với owner = "An", balance = 500000. Từ một class tạo được vô số object độc lập.
Câu 2. Constructor khác method thường ở những điểm nào?
Bốn điểm: (1) tên trùng tên class; (2) không có kiểu trả về — viết void TenClass() là method chứ không phải constructor; (3) chỉ chạy qua new hoặc this(...)/super(...), không gọi như method; (4) không được kế thừa. Method thường có return type (hoặc void), tên bất kỳ, gọi trực tiếp, và kế thừa được.
Câu 3. Default constructor được sinh khi nào? Nó có tham số/access gì?
Chỉ sinh khi class không khai báo bất kỳ constructor nào. Nó không tham số, thân rỗng (chỉ gọi super() ngầm), và có cùng access modifier với class (class public → constructor public). Chỉ cần bạn viết một constructor có tham số, default constructor biến mất — new BankAccount() sẽ lỗi compile nếu class chỉ có BankAccount(String owner).
Câu 4. this là gì? Dùng để làm gì?
this là reference tới object hiện tại trong instance method/constructor. Dùng để: phân biệt field với tham số trùng tên (this.owner = owner), gọi method của chính object, gọi constructor khác (this(...)), truyền/trả chính object này (return this cho fluent API).
Câu 5. this(...) và super(...) khác nhau thế nào? this() có bắt buộc là câu lệnh đầu tiên không?
this(...) gọi constructor khác trong cùng class; super(...) gọi constructor class cha. Nếu không viết cả hai, compiler chèn super() ngầm. Trả lời phỏng vấn chuẩn: "trước JDK 25 bắt buộc là câu lệnh đầu tiên; từ JDK 25 (JEP 513) được phép có câu lệnh trước miễn không đọc instance đang tạo". Tốt nhất cho điểm: nói quy tắc cổ điển trước, rồi bổ sung JEP 513.
Câu 6. Static field khác instance field thế nào?
Instance field: mỗi object một bản, chỉ tồn tại khi có object, truy cập qua obj.field. Static field: một bản duy nhất thuộc class, dùng chung mọi object, truy cập qua TenClass.field, tồn tại theo vòng đời class. Static field hợp cho hằng số và bộ đếm; là nguồn race condition nếu mutable.
Câu 7. Vì sao main phải là static?
JVM gọi main làm entry point khi chưa tạo object nào. Instance method cần object để gọi, nên không dùng được. public để JVM ngoài package gọi được; void vì JVM không nhận giá trị trả về. Từ JDK 25, file compact có thể dùng instance void main() — JVM tự tạo object (JEP 512).
Câu 8. Static method có dùng được this hoặc gọi trực tiếp field instance không?
Không. Static method không gắn với object nào nên this không tồn tại và compiler chặn truy cập field instance: non-static variable balance cannot be referenced from a static context. Muốn dùng field instance từ static method phải truyền object vào làm tham số rồi obj.field.
Câu 9. Bốn access modifier khác nhau thế nào? Xếp theo độ mở.
private (chỉ trong class) < default/package-private (thêm cùng package) < protected (thêm subclass ở package khác, có điều kiện qua reference kiểu subclass) < public (mọi nơi). Field nên để private, API công khai tối thiểu — đó là encapsulation.
Câu 10. Top-level class được khai báo với những modifier nào?
Chỉ public hoặc không viết gì (package-private). Không được private/protected; cũng không được static/final ở top-level (final chỉ dùng cho class lồng). Mỗi file chỉ một class public và tên file phải trùng tên class đó.
Câu 11. package-private (default) là gì? Khi nào nên dùng?
Là mức truy cập khi không viết modifier nào: mọi class cùng package truy cập được, ngoài package thì không (kể cả subclass). Dùng cho class/method nội bộ của một module — "bạn cùng nhà" của Java, che giấu chi tiết triển khai khỏi API công khai.

Nâng cao (Junior+)

Câu 12. Static block chạy khi nào và bao nhiêu lần?
Chạy khi class được khởi tạo (class initialization) — lần đầu class được dùng thật: tạo object đầu tiên, gọi static method/field, hoặc tạo subclass. Thường lười, không phải lúc chương trình bắt đầu. Mỗi class loader chạy đúng một lần, theo thứ tự khai báo cùng static field initializer. Dùng để khởi tạo static final phức tạp.
Câu 13. Thứ tự khởi tạo đầy đủ khi tạo một object?
(0) Static field initializer + static block theo thứ tự khai báo, một lần khi class được nạp; (1) cấp phát object, field nhận giá trị mặc định; (2) constructor chạy: this(...) hoặc super() ngầm; (3) instance field initializer + instance initializer block theo thứ tự khai báo; (4) thân constructor. Class cha chạy trước class con.
Câu 14. Field và biến local khác nhau thế nào về giá trị mặc định và vòng đời?
Field tự nhận giá trị mặc định (0, 0.0, false, null) ngay khi object được cấp phát. Biến local không có giá trị mặc định — compiler bắt bạn gán trước khi dùng. Field sống theo object (trên heap); local sống trong stack frame của method, mất khi method kết thúc.
Câu 15. Hai constructor cùng signature có được không? Điều gì xảy ra?
Không — lỗi compile: constructor BankAccount(String) is already defined in class BankAccount. Java phân biệt constructor/method bằng tên + danh sách kiểu tham số, tên tham số không tính. Muốn "nhiều lựa chọn", đổi số lượng/kiểu tham số (overload).
Câu 16. Constructor private dùng để làm gì?
Chặn bên ngoài tạo object trực tiếp, buộc đi qua "cửa chính" do class kiểm soát: static factory method, Singleton (một instance duy nhất), hoặc utility class chứa toàn static method. Ví dụ JDK: Collections, Math có constructor private. Chi tiết Singleton ở 2.8 SOLID & patterns.
Câu 17. JavaBean là gì? POJO khác gì? Khi nào dùng record thay?
POJO là class Java thuần, không phụ thuộc framework. JavaBean là POJO theo quy ước: no-arg constructor + private field + getter/setter (+ Serializable). Framework như Jackson/JPA/Hibernate dựa vào quy ước này để hoạt động qua reflection. Record thay thế JavaBean khi cần DTO bất biến — gọn hơn và tự sinh accessor/equals/hashCode/toString; nhưng JPA entity không dùng record được vì cần no-arg constructor và field mutable.
Câu 18. Static import là gì? Có nên dùng không?
Là import thành viên static để gọi không cần tên class: import static java.lang.Math.PI; rồi dùng PI. Nên dùng cho hằng số/utility thật rõ nghĩa; tránh wildcard và tránh import hai thành viên trùng tên vì lời gọi sẽ mơ hồ (lỗi compile "reference to ... is ambiguous").
Câu 19. In trực tiếp một object ra console thì được gì? Muốn đẹp thì làm sao?
Mặc định dùng Object.toString(): chuỗi dạng BankAccount@52525845 — tên class + dấu @ + hashCode dạng hex, phần sau @ đổi mỗi lần chạy. Muốn đẹp thì override toString() (học ở 2.6 Object contract); record tự sinh toString dạng BankAccount[owner=An, balance=500000].
Câu 20. Vì sao không nên so sánh hai object bằng ==?
== so địa chỉ (có phải cùng một object không), không so nội dung. Hai object cùng dữ liệu vẫn == cho false. Dùng equals() cho nội dung — nhưng chỉ đúng nếu class override đúng cặp equals/hashCode (2.6). Ngoại lệ: enum và record so == được.
Câu 21. Import khác package khác gì so với cùng package? java.lang có cần import không?
Cùng package: dùng trực tiếp, không cần import, và truy cập được thành viên package-private. Khác package: phải import (hoặc dùng fully-qualified name), và chỉ truy cập được thành viên public/protected phù hợp. java.lang được tự động import trong mọi file — String, Math, System, IO không cần import.
Câu 22. Vì sao static mutable field nguy hiểm trong đa luồng?
Vì nó là state dùng chung giữa mọi thread. count++ gồm ba bước đọc → cộng → ghi; hai thread xen kẽ sẽ mất cập nhật (race condition), kết quả mỗi lần chạy một khác. Cách xử lý: tránh static mutable, dùng AtomicLong/AtomicInteger, hoặc synchronized; chỉ giữ static final immutable. Chi tiết ở Biến trong Java — mục 15.3.

14. Bài tập đoán output

Bài 1. Đoán thứ tự in khi có static, instance initializer và constructor 
public class BankAccount {
    static int count = init("static field");
    static { IO.println("static block"); }
    String owner = name("instance field");
    { IO.println("instance initializer"); }
    BankAccount() { IO.println("constructor"); }

    static int init(String s) { IO.println(s); return 0; }
    static String name(String s) { IO.println(s); return "An"; }

    public static void main() {
        new BankAccount();
        new BankAccount();
    }
}

In ra:

static field
static block
instance field
instance initializer
constructor
instance field
instance initializer
constructor

Phần static chỉ chạy một lần; phần instance chạy lại mỗi lần new, luôn trước constructor.

Bài 2. Viết class BankAccount có deposit/withdraw rồi đoán output 
BankAccount acc = new BankAccount();
acc.owner = "An";
acc.balance = 500_000;
acc.deposit(200_000);
IO.println(acc.owner + ": " + acc.balance);
acc.withdraw(1_000_000);
acc.withdraw(300_000);
IO.println(acc.owner + ": " + acc.balance);

Class cần có field String owner; long balance;, method deposit cộng tiền, withdraw trừ tiền nếu đủ (không thì in thông báo). Output:

An: 700000
So du khong du
An: 400000

Rút 1.000.000 thất bại nên số dư giữ 700.000; rút tiếp 300.000 còn 400.000.

Bài 3. Chuyện gì xảy ra khi quên new? 
public class BankAccount {
    static BankAccount acc;
    long balance;

    void deposit(long amount) { balance += amount; }

    public static void main() {
        try {
            acc.deposit(100);
        } catch (NullPointerException e) {
            IO.println(e.getMessage());
        }
    }
}

In ra message của NullPointerException (JDK 25 có "helpful NPE" chỉ rõ nguyên nhân):

Cannot invoke "BankAccount.deposit(long)" because "BankAccount.acc" is null

Code compile bình thường vì kiểu của acc vẫn đúng — lỗi chỉ lộ ra lúc chạy. Đây là lý do phải luôn new/khởi tạo trước khi dùng object.

Bài 4. Đếm object bằng static counter — đoán output 
public class BankAccount {
    static int soTaiKhoan = 0;
    String owner;

    BankAccount(String owner) {
        this.owner = owner;
        soTaiKhoan++;
    }

    public static void main() {
        new BankAccount("An");
        new BankAccount("Binh");
        new BankAccount("Cuong");
        IO.println(soTaiKhoan);
    }
}

In ra 3. Mỗi constructor tăng biến chung soTaiKhoan; ba object được tạo nên biến bằng 3.

Bài 5. Tìm và sửa lỗi shadowing thiếu this 
public class BankAccount {
    String owner;

    BankAccount(String owner) {
        owner = owner;
    }

    public static void main() {
        BankAccount acc = new BankAccount("An");
        IO.println(acc.owner);
    }
}

In ra null. Dòng owner = owner gán tham số cho chính nó, field this.owner không hề được gán (giữ mặc định null). Sửa thành this.owner = owner;.

Bài 6. Object in mặc định ra gì? 
public class BankAccount {
    String owner;
    long balance;

    BankAccount(String owner, long balance) {
        this.owner = owner;
        this.balance = balance;
    }

    public static void main() {
        IO.println(new BankAccount("An", 500_000));
    }
}

In ra dạng BankAccount@<hashCode hex>, ví dụ một lần chạy thật:

BankAccount@52525845

Phần sau dấu @ thay đổi mỗi lần chạy nên không đoán chính xác được — chỉ cần nhận dạng đúng định dạng. Muốn in đẹp, override toString() (2.6).

Bài 7. Đoán thứ tự khi nhiều constructor gọi this() 
public class BankAccount {
    BankAccount() {
        this("An");
        IO.println("constructor 0 tham so");
    }

    BankAccount(String owner) {
        this(owner, 0);
        IO.println("constructor 1 tham so: " + owner);
    }

    BankAccount(String owner, long balance) {
        IO.println("constructor 2 tham so");
    }

    public static void main() {
        new BankAccount();
    }
}

In ra theo thứ tự ngược từ constructor đầy đủ rồi quay lại:

constructor 2 tham so
constructor 1 tham so: An
constructor 0 tham so

new BankAccount() → this("An") → this("An", 0); constructor đích chạy thân trước, rồi trả về chạy tiếp phần còn lại của các constructor đã gọi nó.

Bài 8. Tìm lỗi compile: gọi constructor không tồn tại 
public class BankAccount {
    String owner;

    BankAccount(String owner) {
        this.owner = owner;
    }

    public static void main() {
        new BankAccount();
    }
}

Không compile vì class chỉ có constructor 1 tham số, default constructor không được sinh:

BankAccount.java:9: error: constructor BankAccount in class BankAccount cannot be applied to given types;
        new BankAccount();
        ^
  required: String
  found:    no arguments
  reason: actual and formal argument lists differ in length
1 error

Sửa: thêm constructor không tham số, hoặc gọi new BankAccount("An").

Bài 9. Static method truy cập field instance — chuyện gì xảy ra? 
public class BankAccount {
    long balance;

    static void reset() {
        balance = 0;
    }
}

Không compile. Static method không có object nào để biết "balance của ai":

BankAccount.java:5: error: non-static variable balance cannot be referenced from a static context
        balance = 0;
        ^
1 error

Sửa: biến reset thành instance method, hoặc cho balance thành static (cân nhắc bẫy static mutable).

Bài 10. == hay equals? Đoán output 
BankAccount a = new BankAccount("An");
BankAccount b = new BankAccount("An");
BankAccount c = a;
IO.println(a == b);
IO.println(a == c);
IO.println(a.owner.equals(b.owner));

In ra:

false
true
true

a và b là hai object khác nhau trên heap nên == false; c trỏ cùng object với a nên true; hai field String bằng nội dung nên equals true.

Bài 11. Subclass không đọc được field private của class cha 
class BankAccount {
    private long balance = 500_000;
}

class SavingsAccount extends BankAccount {
    long xem() {
        return balance;
    }
}

Không compile — private chỉ mở trong chính class khai báo, subclass cũng không ngoại lệ:

BankAccount.java:7: error: balance has private access in BankAccount
        return balance;
               ^
1 error

Muốn subclass đọc được, class cha phải cung cấp getter public/protected — đúng tinh thần encapsulation.

Bài 12. Static import trùng tên — vì sao lỗi? 
import static java.lang.Math.min;
import static java.lang.StrictMath.min;

public class BankAccount {
    public static void main() {
        IO.println(min(1, 2));
    }
}

Hai static import cùng tên min làm lời gọi mơ hồ:

BankAccount.java:6: error: reference to min is ambiguous
        IO.println(min(1, 2));
                   ^
  both method min(int,int) in StrictMath and method min(int,int) in Math match
1 error

Sửa: bỏ một import và gọi rõ Math.min(1, 2) — best practice là tránh static import trùng tên.

Bài 13. Method trùng tên class nhưng có void 
public class BankAccount {
    void BankAccount() {
        IO.println("method trung ten class");
    }

    BankAccount() {
        IO.println("constructor that");
    }

    public static void main() {
        BankAccount acc = new BankAccount();
        acc.BankAccount();
    }
}

Compile được nhưng gây nhầm lẫn. In ra:

constructor that
method trung ten class

new BankAccount() gọi constructor thật (không có void); acc.BankAccount() gọi method có return type void. Vì nhìn giống constructor mà không phải, đây là code xấu — không bao giờ viết như vậy.

Checklist tự đánh giá trước phỏng vấn

  • Giải thích được class vs object bằng ví dụ ngoài đời, không cần đọc định nghĩa.
  • Khai báo class có field, constructor, method và tạo object bằng new mà không tra cứu.
  • Phân biệt object trên heap và biến reference trên stack; giải thích pass-by-value với reference.
  • Nêu đúng khi nào default constructor được sinh và vì sao nó "biến mất" khi có constructor khác.
  • Viết được constructor overload + chuỗi this(...) và giải thích thứ tự chạy.
  • Trả lời được câu "this() có bắt buộc đầu tiên không?" kèm thông tin JEP 513 của JDK 25.
  • Phân biệt this và static; giải thích vì sao static method không có this.
  • Thuộc lòng bảng 4 access modifier theo 4 phạm vi; biết top-level class chỉ public/default.
  • Giải thích package ảnh hưởng truy cập thế nào; viết đúng khai báo package/import.
  • Vẽ lại được thứ tự khởi tạo: static → instance initializer → constructor (kèm ví dụ).
  • Giải thích static mutable nguy hiểm gì và cách thay bằng AtomicLong.
  • Nhận dạng JavaBean, biết khi nào record thay thế được và khi nào không (JPA entity).
  • Nêu 3 lỗi kinh điển: quên new, == thay equals, shadowing thiếu this.
