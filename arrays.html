Arrays chuyên sâu

Mảng (array) là cấu trúc dữ liệu đầu tiên bạn cần thành thạo trước khi học Collections (3.3). Khác JavaScript, mảng Java có kích thước cố định ngay lúc tạo, là object thật trên heap, và mang theo một loạt luật ngầm — copy nông, array covariance, varargs — rất hay xuất hiện khi phỏng vấn và trong code production.

2. Khai báo, khởi tạo & giá trị mặc định

Mảng là một dãy phần tử cùng kiểu, có kích thước chốt ngay khi tạo và không đổi được về sau. Ba cách khai báo thường gặp:

Cách viếtÝ nghĩaDùng khi
int[] a = new int[3];Tạo mảng 3 phần tử, gán giá trị mặc định cho từng phần tửBiết trước số lượng nhưng chưa biết giá trị
int[] b = {1, 2, 3};Khởi tạo nhanh bằng literalChỉ dùng ngay tại dòng khai báo
int[] c = new int[]{1, 2, 3};Cú pháp đầy đủ, là biểu thứcTruyền tham số, return, gán lại biến đã khai báo
Convention của Java là đặt ngoặc vuông sau kiểu: int[] a. Cách viết int a[] (kiểu C) vẫn hợp lệ nhưng gây nhầm khi khai báo nhiều biến trên một dòng — tránh dùng trong code production.

Mảng hai chiều thực chất là mảng của các mảng. Khi tạo new int[2][3], JVM tạo một mảng cha chứa 2 reference trỏ tới 2 mảng con, mỗi mảng con dài 3. Vì vậy bạn có thể tạo mảng cha trước, rồi gán từng hàng — gọi là ragged array (mảng răng cưa, các hàng dài ngắn khác nhau):

int[] a = new int[3];               // [0, 0, 0]
double[] d = new double[2];         // [0.0, 0.0]
boolean[] flags = new boolean[2];   // [false, false]
String[] names = new String[2];     // [null, null]

int[] b = {1, 2, 3};                // [1, 2, 3]
int[] c = new int[]{4, 5, 6};       // [4, 5, 6] - tuong duong b, nhung la bieu thuc

int[][] grid = new int[2][3];       // 2 hang, moi hang 3 cot
// Arrays.deepToString(grid) -> [[0, 0, 0], [0, 0, 0]]

int[][] ragged = new int[2][];      // 2 hang nhung CHUA tao mang con
ragged[0] = new int[]{1, 2};
ragged[1] = new int[]{3, 4, 5};
// Arrays.deepToString(ragged) -> [[1, 2], [3, 4, 5]]

Giá trị mặc định

Mọi phần tử được JVM zero-fill ngay khi mảng ra đời, nên mảng không bao giờ chứa "rác" như C/C++:

Kiểu phần tửGiá trị mặc định
byte, short, int, long0
float, double0.0
char'\u0000' (ký tự null)
booleanfalse
Mọi kiểu reference (String, BigDecimal, record, mảng con...)null
Bảng size/range đầy đủ của 8 kiểu nguyên thủy nằm ở Biến trong Java — mục 3. Bẫy hay gặp: String[] names = new String[3]; rồi gọi names[0].length() là NullPointerException — phần tử đang là null, không phải chuỗi rỗng.

length là field, không phải method

Mảng có field length (không ngoặc, không phải method như String.length()). Đây là câu bẫy phỏng vấn kinh điển:

int[] b = {1, 2, 3};
IO.println(b.length);      // 3   - field cua object mang

String s = "java";
IO.println(s.length());    // 4   - method cua String

Viết b.length() không compile:

IO.println(b.length());
            ^
error: cannot find symbol
  symbol:   method length()
  location: variable b of type int[]

Và length là final — kích thước mảng không sửa được sau khi tạo:

a.length = 5;
 ^
error: cannot assign a value to final variable length

3. Mảng trong bộ nhớ: reference, object & so sánh Hay hỏi phỏng vấn Junior+

Mảng là object, không phải primitive. Biến mảng nằm trên stack và giữ địa chỉ của object mảng trên heap (đúng mô hình đã học ở Biến trong Java — mục 7):

// STACK                     HEAP
// [ a = #1A2 ]  -------->  { [1, 2, 3] }
// [ b = #1A2 ]  -------->  (cung object - alias)
// [ c = #3F4 ]  -------->  { [1, 2, 3] }  (object khac)

Ba hệ quả thực tế, chạy thật:

int[] a = {1, 2, 3};
int[] b = a;                       // b va a cung tro MOT object
IO.println(a == b);                // true
b[0] = 100;
IO.println(Arrays.toString(a));    // [100, 2, 3] - sua qua b, a thay doi

int[] c = {100, 2, 3};
IO.println(a == c);                // false - khac identity
IO.println(a.equals(c));           // false - mang khong override equals
IO.println(Arrays.equals(a, c));   // true  - so noi dung tung phan tu

// mang ke thua truc tiep Object
IO.println(a.getClass().getName());                 // [I
IO.println(a.getClass().getSuperclass().getName()); // java.lang.Object
Vì sao a.equals(c) vẫn false? Mảng không override equals (không phải class do bạn viết), nên nó dùng Object.equals — tức so identity y như ==. Muốn so nội dung phải gọi Arrays.equals (1 chiều) hoặc Arrays.deepEquals (nhiều chiều).

Pass-by-value với reference

Java luôn pass-by-value. Với mảng, giá trị được truyền là bản sao của địa chỉ, nên method sửa được nội dung mảng nhưng gán lại reference thì không ảnh hưởng bên ngoài:

static void tryChange(int[] nums) {
    nums[0] = 99;                 // sua noi dung object -> ben ngoai thay
}

static void tryReassign(int[] nums) {
    nums = new int[]{7, 7, 7};    // chi doi ban sao reference -> ben ngoai khong doi
}

int[] a = {1, 2, 3};
tryChange(a);
IO.println(Arrays.toString(a));   // [99, 2, 3]
tryReassign(a);
IO.println(Arrays.toString(a));   // [99, 2, 3] - van nhu truoc
Cùng luật này giải thích vì sao Arrays.sort(nums) trong method sort được mảng gốc (sửa nội dung), còn Arrays.copyOf trả mảng mới thì phải return ra ngoài.

4. Duyệt mảng

Hai cách duyệt, chọn theo nhu cầu:

  • for theo index — khi cần chỉ số, cần sửa phần tử, hoặc duyệt ngược/xuôi có bước nhảy.
  • for-each — khi chỉ cần đọc từng giá trị; ngắn gọn, ít lỗi off-by-one.

4.1 for index vs for-each — chọn đúng công cụ

Cần index (vị trí), cần ghi vào phần tử, duyệt ngược/bước nhảy → for index. Chỉ đọc giá trị → for-each. Bẫy lớn nhất: for-each không gán được vào phần tử vì biến vòng lặp chỉ là bản sao giá trị — nhưng nó sửa được state của object mà phần tử trỏ tới, vì bản sao đó là bản sao reference. Hai ví dụ đối lập chạy thật:

import java.util.Arrays;

class HoaDon {
    int tong;

    HoaDon(int tong) {
        this.tong = tong;
    }

    void cong(int x) {
        this.tong += x;
    }

    public String toString() {
        return "HD(" + tong + ")";
    }
}

void main() {
    int[] nums = {10, 20, 30};

    for (int n : nums) {
        n = n * 2;                 // chi sua bien copy -> mang KHONG doi
    }
    IO.println("primitive copy : " + Arrays.toString(nums));
    // primitive copy : [10, 20, 30]

    for (int i = 0; i < nums.length; i++) {
        nums[i] *= 2;              // ghi that su vao phan tu
    }
    IO.println("sua qua index  : " + Arrays.toString(nums));
    // sua qua index  : [20, 40, 60]

    HoaDon[] ds = { new HoaDon(100), new HoaDon(200) };
    for (HoaDon h : ds) {
        h.cong(10);                // sua STATE cua object -> ben ngoai thay
    }
    IO.println("sua state      : " + Arrays.toString(ds));
    // sua state      : [HD(110), HD(210)]

    for (HoaDon h : ds) {
        h = new HoaDon(0);         // chi doi ban sao reference -> vo nghia
    }
    IO.println("doi reference  : " + Arrays.toString(ds));
    // doi reference  : [HD(110), HD(210)]
}
primitive copy : [10, 20, 30]
sua qua index  : [20, 40, 60]
sua state      : [HD(110), HD(210)]
doi reference  : [HD(110), HD(210)]
Quy tắc nhớ: for-each không gán được phần tử (n = ... chỉ đổi bản sao), nhưng gọi method để đổi state của object thì được (h.cong(10)). Mảng primitive: for-each vô dụng nếu muốn sửa. Mảng object: for-each sửa được state, nhưng không thay được phần tử bằng object khác.

Một bẫy nữa: for-each trên mảng null ném NullPointerException ngay vòng đầu — compiler dịch thành truy cập a.length:

int[] a = null;
try {
    for (int x : a) {             // NPE tai day
        IO.println(x);
    }
} catch (NullPointerException e) {
    IO.println("NPE: " + e.getClass().getSimpleName());
}
// NPE: NullPointerException

4.2 Duyệt ngược, bước nhảy, 2 chiều và label

for index linh hoạt hơn hẳn: chạy ngược, nhảy bước, lồng nhiều chiều. break/continue bình thường chỉ tác dụng ở vòng trong cùng; muốn thoát/next cả vòng ngoài thì gắn label:

void main() {
    int[] a = {1, 2, 3, 4, 5, 6};

    StringBuilder nguoc = new StringBuilder();
    for (int i = a.length - 1; i >= 0; i--) {
        nguoc.append(a[i]).append(' ');
    }
    IO.println(nguoc.toString().trim());     // 6 5 4 3 2 1

    StringBuilder buoc = new StringBuilder();
    for (int i = 0; i < a.length; i += 2) {
        buoc.append(a[i]).append(' ');
    }
    IO.println(buoc.toString().trim());      // 1 3 5

    int[][] grid = {{1, 2, 3}, {4, 5, 6}};
    StringBuilder haiChieu = new StringBuilder();
    for (int[] row : grid) {                 // grid la mang cua cac mang
        for (int v : row) {
            haiChieu.append(v).append(' ');
        }
    }
    IO.println(haiChieu.toString().trim());  // 1 2 3 4 5 6

    StringBuilder nhay = new StringBuilder();
    outer:                                   // label cho vong lap ngoai
    for (int i = 1; i <= 3; i++) {
        for (int j = 1; j <= 3; j++) {
            if (j == 2) continue outer;      // next thang vong i
            if (i == 3) break outer;         // thoat han ca hai vong
            nhay.append(i).append(j).append(' ');
        }
    }
    IO.println(nhay.toString().trim());      // 11 21
}
6 5 4 3 2 1
1 3 5
1 2 3 4 5 6
11 21

Trace label: i=1 in "11" rồi j=2 continue outer; i=2 in "21" rồi cũng continue outer; i=3, j=1 thì break outer — dừng cả hai vòng. Label viết tên trước vòng lặp kèm dấu : (outer:); dùng tên có nghĩa, đừng lạm dụng vì làm luồng chạy khó theo dõi.

4.3 IntStream, Arrays.stream, Arrays.asList và Iterable

Arrays.asList bọc mảng thành List (đủ để for-each), IntStream.range cho vòng index không cần khai báo i, còn Arrays.stream mở đường sang thế giới Stream (học sâu ở 3.8):

import java.util.stream.IntStream;

class BinhPhuong implements Iterable<Integer> {
    final int n;

    BinhPhuong(int n) {
        this.n = n;
    }

    public java.util.Iterator<Integer> iterator() {
        return new java.util.Iterator<Integer>() {
            int i = 1;

            public boolean hasNext() {
                return i <= n;
            }

            public Integer next() {
                return i * i++;
            }
        };
    }
}

void main() {
    int[] a = {10, 20, 30};

    StringBuilder theoRange = new StringBuilder();
    IntStream.range(0, a.length).forEach(i -> theoRange.append(a[i]).append(' '));
    IO.println(theoRange.toString().trim());        // 10 20 30

    StringBuilder rangeClosed = new StringBuilder();
    IntStream.rangeClosed(1, 3).forEach(i -> rangeClosed.append(i).append(' '));
    IO.println(rangeClosed.toString().trim());       // 1 2 3

    IO.println(Arrays.stream(a).sum());              // 60

    StringBuilder asList = new StringBuilder();
    for (int n : Arrays.asList(10, 20, 30)) {
        asList.append(n).append(' ');
    }
    IO.println(asList.toString().trim());            // 10 20 30

    StringBuilder iterable = new StringBuilder();
    for (int x : new BinhPhuong(4)) {                // for-each tren Iterable
        iterable.append(x).append(' ');
    }
    IO.println(iterable.toString().trim());          // 1 4 9 16
}
10 20 30
1 2 3
60
10 20 30
1 4 9 16
Phân biệt: Arrays.asList trả về List kích thước cố định gắn với mảng gốc — set() được (ghi vào mảng), add()/remove() ném UnsupportedOperationException. Còn IntStream.range(0, n) là nửa mở (không gồm n), rangeClosed(1, n) là đóng cả hai đầu — câu hỏi phỏng vấn hay gặp.

Mảng không implements Iterable — for-each trên mảng là đặc quyền do compiler "dịch" thành vòng lặp index, còn for-each trên List/Set mới gọi iterator() thật. Vì vậy đoạn sau không compile:

Iterable<Integer> it = a;
                      ^
error: incompatible types: int[] cannot be converted to Iterable<Integer>

4.4 Bẫy concurrent: sửa mảng ngay trong lúc duyệt

Collection fail-fast (duyệt bằng iterator mà add/remove thì ném ConcurrentModificationException). Mảng không có cơ chế đó — sửa thoải mái, không exception, nhưng hậu quả logic mới đáng sợ vì nó im lặng:

import java.util.ArrayList;
import java.util.ConcurrentModificationException;
import java.util.List;

void main() {
    int[] a = {1, 2, 3, 4, 5};
    int sum = 0;
    for (int x : a) {
        sum += x;
        a[0] = 100;                  // sua mang giua chung - KHONG nem exception
    }
    IO.println("sum = " + sum + ", a[0] = " + a[0]);

    // "xoa" phan tu so 2 bang dich trai ngay trong vong lap
    int[] b = {1, 2, 3, 4, 5};
    int n = b.length;
    for (int i = 0; i < n; i++) {
        if (b[i] == 2) {
            System.arraycopy(b, i + 1, b, i, n - i - 1);
            b[--n] = 0;
        }
    }
    IO.println(Arrays.toString(b));

    List<Integer> list = new ArrayList<>(List.of(1, 2, 3, 4));
    try {
        for (int x : list) {
            if (x == 2) {
                list.remove(Integer.valueOf(2));   // collection: no ngay
            }
        }
        IO.println("khong loi");
    } catch (ConcurrentModificationException e) {
        IO.println("Collection: ConcurrentModificationException");
    }
}
sum = 15, a[0] = 100
[1, 3, 4, 5, 0]
Collection: ConcurrentModificationException
  • sum = 15 — for-each chỉ đọc a[i] tại thời điểm bước tới, nên sửa a[0] giữa chừng không làm sai tổng (phần tử 1 đã cộng xong), nhưng nếu dịch/xoá phần tử thì kết quả phụ thuộc hoàn toàn vào thứ tự duyệt.
  • Dịch trái để "xoá" phần tử 2: khi i = 1 xoá xong, phần tử 3 dồn về index 1 nhưng vòng lặp đã tăng i lên 2 — số 3 bị bỏ qua. Mảng cho ra [1, 3, 4, 5, 0] (0 là ô padding, không phải dữ liệu thật). Muốn xoá an toàn: không tăng i cho vòng đó, hoặc duyệt ngược từ cuối.
  • Đa luồng còn tệ hơn: mảng không có bất kỳ kiểm tra nào, nên thread khác sửa cùng lúc sẽ cho kết quả rác không báo lỗi (học ở 4.2 Concurrency).
Nguyên tắc: với mảng, bạn tự chịu trách nhiệm về tính đúng đắn khi sửa trong lúc duyệt. Với collection, exception của iterator là "bạn tốt" giúp phát hiện sai — đừng lách bằng for index nếu cấu trúc thay đổi trong vòng lặp.

System.arraycopy(src, 0, back, 0, src.length);   // [1, 2, 3, 4, 5]

int[] slice = new int[3];
System.arraycopy(src, 2, slice, 0, 3);           // [3, 4, 5] - lay tu index 2

int[] copy = Arrays.copyOf(src, 3);              // [1, 2, 3] - cat bot
int[] grow = Arrays.copyOf(src, 8);              // [1, 2, 3, 4, 5, 0, 0, 0] - noi them

int[] shift = {1, 2, 3, 4, 5};
System.arraycopy(shift, 0, shift, 1, 4);         // [1, 1, 2, 3, 4] - overlap OK

int[] cloned = src.clone();
cloned[0] = 9;
IO.println(Arrays.toString(src));                // [1, 2, 3, 4, 5] - doc lap

Shallow copy — bẫy kinh điển với mảng 2 chiều

Mọi cách trên đều shallow: với mảng 2 chiều, phần tử là các reference, nên bản copy vẫn trỏ chung các mảng con:

int[][] a = {{1, 2}, {3, 4}};
int[][] shallow = Arrays.copyOf(a, a.length);
shallow[0][0] = 99;
IO.println(Arrays.deepToString(a));          // [[99, 2], [3, 4]] - mang goc cung doi!

// deep copy phai tu viet: copy tung hang
int[][] deep = new int[a.length][];
for (int i = 0; i < a.length; i++) {
    deep[i] = Arrays.copyOf(a[i], a[i].length);
}
deep[0][0] = 7;
IO.println(Arrays.deepToString(a));          // [[99, 2], [3, 4]] - khong doi
IO.println(Arrays.deepToString(deep));       // [[7, 2], [3, 4]]
Bẫy alias: int[] y = x; không phải copy — chỉ là biến thứ hai trỏ cùng mảng. Sửa qua y là sửa luôn x:
int[] x = {1, 2, 3};
int[] y = x;
y[1] = 200;
IO.println(Arrays.toString(x));    // [1, 200, 3]

6. Lớp Arrays — bộ công cụ chuẩn

java.util.Arrays là lớp tiện ích static (không khởi tạo, giống Math) gom hầu hết thao tác mảng. Nhớ nó để không tự viết vòng lặp thủ công.

sort và binarySearch

int[] unsorted = {5, 2, 9, 1, 5, 6};
Arrays.sort(unsorted);
IO.println(Arrays.toString(unsorted));           // [1, 2, 5, 5, 6, 9]

String[] words = {"banana", "Apple", "cherry", "apple"};
Arrays.sort(words);
IO.println(Arrays.toString(words));              // [Apple, apple, banana, cherry]

IO.println(Arrays.binarySearch(unsorted, 6));    // 4  - tim thay, tra index
IO.println(Arrays.binarySearch(unsorted, 4));    // -3 - khong thay, xem giai thich
Primitive vs object: Arrays.sort trên mảng primitive dùng dual-pivot quicksort (nhanh, không stable), trên mảng object dùng TimSort (stable — phần tử bằng nhau giữ nguyên thứ tự gốc). Vì sao cần stable và cách sort theo Comparator: xem mục 10.

Vì sao binarySearch trả -3? Mảng [1, 2, 5, 5, 6, 9] đang "thiếu" số 4; nếu chèn 4 vào để giữ thứ tự thì nó đứng ở index 2. Java mã hóa "không thấy tại điểm chèn p" thành -p - 1 (để phân biệt với tìm thấy ở index 0): -(2) - 1 = -3. Lấy lại điểm chèn: int p = -result - 1; (hoặc ~result).

Điều kiện bắt buộc: binarySearch chỉ đúng khi mảng đã được sort theo cùng thứ tự. Chạy trên mảng chưa sort sẽ trả kết quả vô nghĩa — không báo lỗi. Ví dụ {9, 1, 5} tìm 5 trả 2 dù đúng ra phải là 1.

toString, deepToString, equals, deepEquals

int[][] grid = {{1, 2}, {3, 4}};
IO.println(grid);                        // [[I@5ffead27 (hash thay doi moi lan chay)
IO.println(Arrays.deepToString(grid));   // [[1, 2], [3, 4]]

int[] p = {1, 2};
int[] q = {1, 2};
IO.println(Arrays.equals(p, q));         // true - so noi dung 1 chieu

int[][] p2 = {{1, 2}};
int[][] q2 = {{1, 2}};
IO.println(Arrays.equals(p2, q2));       // false - chi so reference cac hang
IO.println(Arrays.deepEquals(p2, q2));   // true  - so noi dung nhieu chieu
Quên deep là bug production hay gặp: Arrays.equals trên mảng 2 chiều chỉ so địa chỉ các hàng nên gần như luôn false với dữ liệu giống nhau. Mảng 2 chiều luôn đi với deepToString/deepEquals/deepHashCode.

fill, asList, stream

int[] filled = new int[5];
Arrays.fill(filled, 7);                       // [7, 7, 7, 7, 7]
Arrays.fill(filled, 1, 3, 0);                 // [7, 0, 0, 7, 7] - tu index 1 den 2

List<String> list = Arrays.asList("a", "b", "c");
list.set(0, "z");                             // OK: [z, b, c]
list.add("d");                                // UnsupportedOperationException

long count = Arrays.stream(filled).filter(n -> n > 3).count();
IO.println(count);                            // 3

Ba điểm cần nhớ:

  • Arrays.fill(arr, from, to, value) điền nửa mở [from, to) — index to không bị chạm.
  • Arrays.asList trả về view kích thước cố định bọc mảng gốc (java.util.Arrays$ArrayList): set ghi xuyên qua mảng gốc, còn add/remove ném UnsupportedOperationException. Chi tiết ở mục 11.
  • Arrays.stream(...) là cửa ngõ vào Stream API — map, filter, sum, collect... sẽ học ở 3.8 Stream API.

7. Array covariance & ArrayStoreException Hay hỏi phỏng vấn Junior+

Mảng trong Java covariant: nếu String là con của Object thì String[] được coi là con của Object[]. Điều này cho phép gán ngầm — và tạo ra lỗ hổng type-safety nổi tiếng:

String[] strings = {"a", "b"};
Object[] objects = strings;                  // covariance: compile OK
IO.println(Arrays.toString(objects));        // [a, b]

objects[0] = "c";                            // OK - phan tu la String
IO.println(Arrays.toString(strings));        // [c, b]

objects[0] = 42;                             // Integer -> JVM nem luc CHAY
// ArrayStoreException: java.lang.Integer

Compiler chỉ kiểm tra theo kiểu khai báo objects (Object[] nhận mọi object), còn JVM kiểm tra kiểu thật của mảng (String[]) ở mỗi lần ghi — gọi là store check. Message thật của JDK 25 lấy từ e.getMessage():

ArrayStoreException : java.lang.Integer
Vì sao Generics không covariant? Chính vì lỗ hổng này. Nếu List<String> là con của List<Object>, bạn có thể nhét Integer vào list chuỗi mà compiler không biết. Generics dùng wildcard (? extends, PECS) để kiểm soát — học ở 3.2 Generics. Còn mảng vẫn giữ covariance từ Java 1.0 để tương thích ngược.

Mảng nguyên thủy thì không covariant, dù bản thân int[] vẫn là object:

Object[] bad = nums;
               ^
error: incompatible types: int[] cannot be converted to Object[]
int[] nums = {1, 2};
IO.println(nums instanceof Object);   // true - mang la object
// nhung int[] KHONG phai Object[]: phan tu la int, khong phai reference

9. Varargs — tham số biến đổi Hay hỏi phỏng vấn

Varargs cho phép method nhận số lượng đối số tùy ý. Cú pháp type... và bên trong method nó chính là một mảng:

static int sum(int... nums) {         // nums co kieu int[]
    int total = 0;
    for (int n : nums) {
        total += n;
    }
    return total;
}

sum();                     // 0    - khong doi so nao
sum(1, 2, 3);              // 6    - compiler tu tao mang int[]{1, 2, 3}
int[] arr = {4, 5, 6};
sum(arr);                  // 15   - truyen mang co san cung duoc
sum(new int[0]);           // 0

Vì varargs là mảng, String[] args của main tương đương một varargs — gọi hai kiểu đều được:

static void printArgs(String... args) {
    IO.println("args.length       : " + args.length);
}

printArgs("--port", "8080");                 // args.length       : 2
printArgs(new String[]{"--port", "8080"});   // args.length       : 2

Hai luật bắt buộc nhớ. Thứ nhất, varargs phải là tham số cuối cùng:

static String join(String... parts, String sep) {
                             ^
error: varargs parameter must be the last parameter

Thứ hai, overload có varargs: bản fixed arity thắng (đúng 3 phase của overload resolution — xem Data Types — mục 9):

static void pick(int a, int b) { IO.println("pick(int, int)"); }
static void pick(int... a)     { IO.println("pick(int...)"); }

pick(1, 2);      // pick(int, int)
pick(1, 2, 3);   // pick(int...)

Nếu hai bản varargs đều khớp mà không bản nào "cụ thể hơn", compiler báo ambiguous:

m();
^
error: reference to m is ambiguous
  both method m(int...) in VarargsAmbigErr and method m(boolean...) in VarargsAmbigErr match
Production: tránh overload chỉ khác nhau phần varargs — rất dễ gọi nhầm bản. Nếu cần, đặt tên method khác nhau (sumAll vs sumRange) hoặc dùng một bản varargs duy nhất.

10. Sort object với Comparable & Comparator Junior+

Arrays.sort hoạt động với mọi mảng object miễn là các phần tử so sánh được. Có hai cách:

  • Comparable — class tự định nghĩa "thứ tự tự nhiên" qua compareTo. Một class chỉ có một thứ tự tự nhiên. String, Integer, BigDecimal đều implements Comparable.
  • Comparator — tiêu chí so sánh từ bên ngoài, viết bao nhiêu cũng được, truyền vào Arrays.sort(array, comparator).
record Score(String name, int point) implements Comparable<Score> {
    @Override
    public int compareTo(Score other) {
        return Integer.compare(this.point, other.point);
    }
}

Score[] scores = {new Score("An", 8), new Score("Binh", 9), new Score("Cuong", 7)};
Arrays.sort(scores);
// [Score[name=Cuong, point=7], Score[name=An, point=8], Score[name=Binh, point=9]]

Với DTO như record Order (theo convention production ở Biến trong Java — mục 15), thường không muốn "đóng đinh" một thứ tự — dùng Comparator:

record Order(long id, String customer, BigDecimal total) {}

Order[] orders = {
    new Order(3, "Cuong", new BigDecimal("250.50")),
    new Order(1, "An", new BigDecimal("1000.00")),
    new Order(2, "Binh", new BigDecimal("99.99"))
};
Arrays.sort(orders, Comparator.comparing(Order::total).reversed());
//   1 | An | 1000.00
//   3 | Cuong | 250.50
//   2 | Binh | 99.99

Arrays.sort trên object là stable sort (TimSort): các phần tử bằng nhau giữ nguyên thứ tự gốc. Điều này quan trọng khi sort nhiều tiêu chí:

Order[] ties = {
    new Order(1, "An", new BigDecimal("50.00")),
    new Order(2, "Binh", new BigDecimal("50.00")),
    new Order(3, "Cuong", new BigDecimal("10.00"))
};
Arrays.sort(ties, Comparator.comparing(Order::total));
//   tie 3 10.00
//   tie 1 50.00 - An van truoc Binh du cung total
//   tie 2 50.00
Sort mảng object không Comparable sẽ ném ClassCastException lúc chạy (không phải lỗi compile) — vì Arrays.sort(Object[]) cast phần tử sang Comparable. Gặp lỗi này, thêm Comparator hoặc cho class implements Comparable. Đào sâu Comparable/Comparator, thenComparing, so sánh nhiều khóa ở 3.3 Collections.

12.1 Nhận String[] args và parse an toàn

static final int DEFAULT_PORT = 8080;   // hang so: static final + UPPER_SNAKE_CASE

static int parsePort(String[] args) {
    if (args.length == 0) {             // args luon khac null, nhung co the rong
        return DEFAULT_PORT;
    }
    try {
        return Integer.parseInt(args[0]);
    } catch (NumberFormatException e) {
        return DEFAULT_PORT;            // config sai thi fallback, khong crash app
    }
}

IO.println(args == null);        // false - JVM luon truyen mang (co the rong)
IO.println(args.length);         // 0 khi chay: java ProductionDemo.java
IO.println(parsePort(args));     // 8080

Chạy kèm đối số: java ProductionDemo.java 9090 → args.length là 1 và parsePort trả 9090. Lưu ý khác biệt với input người dùng: config/env thì fallback âm thầm, còn input API thì phải ném lỗi rõ ràng (400), như đã bàn ở Data Types — mục 13.

static boolean isEmpty(String[] a) {

Method nhận mảng từ bên ngoài nên xử lý cả hai trường hợp: mảng null (quên khởi tạo) và mảng rỗng (hợp lệ nhưng không có dữ liệu).

14. Interview Q&A Hay hỏi phỏng vấn

Cơ bản

Câu 1. Mảng trong Java là primitive hay object? Nêu 3 bằng chứng.
Là object. (1) a.getClass().getName() trả [I, superclass là java.lang.Object; (2) gán được cho biến Object và a instanceof Object là true (kể cả mảng primitive); (3) có field length và được cấp phát trên heap, biến mảng chỉ là reference trên stack.
Câu 2. Vì sao mảng dùng length còn String dùng length()?
length là field của object mảng do JVM quản lý (final, không sửa được). Array không phải class thường viết trong source nên không có method nào cả. String.length() là method vì String là class bình thường. Viết array.length() bị lỗi compile "cannot find symbol".
Câu 3. Giá trị mặc định của phần tử mảng là gì?
Số nguyên và số thực: 0/0.0; boolean: false; char: '\u0000'; mọi reference (String, record, mảng con): null. JVM zero-fill nên phần tử không bao giờ là "rác". Bảng đầy đủ ở Biến trong Java — mục 3.
Câu 4. a == b, a.equals(b) và Arrays.equals(a, b) khác nhau thế nào?
== so identity (cùng object hay không); a.equals(b) của mảng không override Object.equals nên cũng là identity; Arrays.equals mới so nội dung từng phần tử. Hai mảng cùng nội dung nhưng khác object cho kết quả: false, false, true.
Câu 5. Truyền mảng vào method là pass-by-value hay pass-by-reference? Vì sao sửa phần tử được?
Java luôn pass-by-value; với mảng, giá trị được truyền là bản sao của reference. Sửa phần tử (nums[0] = 99) ảnh hưởng mảng gốc vì hai reference trỏ cùng object. Gán lại nums = new int[]{...} chỉ đổi bản sao bên trong method — mảng gốc không đổi.
Câu 6. Vì sao for-each không sửa được phần tử mảng? Mảng có implements Iterable không?
Biến vòng lặp chỉ nhận bản sao giá trị của từng phần tử, gán vào nó không ghi ngược vào mảng — muốn sửa phải dùng for index. Mảng không implements Iterable; for-each trên mảng là compiler hỗ trợ riêng (dịch thành vòng lặp index), nên Iterable<Integer> it = array; không compile.
Câu 7. Mảng 2 chiều thực chất là gì? Ragged array là gì?
Là mảng của các mảng: mảng cha chứa các reference trỏ tới từng mảng con. new int[3][4] tạo 3 mảng con length 4; new int[3][] chỉ tạo mảng cha với 3 null, phải gán từng hàng — cho phép mỗi hàng dài khác nhau (ragged). Truy cập grid[i][j] là hai lần index liên tiếp.
Câu 8. System.arraycopy khác Arrays.copyOf ở đâu? Copy có sâu không?
arraycopy nhận mảng nguồn + đích + offset + length, không tạo mảng mới, xử lý được vùng chồng lấn, ném IndexOutOfBoundsException nếu vượt biên. copyOf tạo mảng mới với độ dài tùy chọn (ngắn hơn thì cắt, dài hơn thì pad giá trị mặc định) — tiện để resize. Cả hai đều shallow: mảng 2 chiều chỉ được copy các reference hàng, muốn sâu phải tự copy từng hàng.

Nâng cao (Junior+)

Câu 9. binarySearch yêu cầu gì? Kết quả âm có nghĩa gì?
Mảng phải được sort trước theo đúng thứ tự so sánh — nếu không, kết quả vô nghĩa mà không báo lỗi. Tìm thấy trả index ≥ 0 (không đảm bảo là phần tử đầu tiên khi trùng nhau); không thấy trả -(điểm chèn) - 1. Ví dụ 25 trong [10, 20, 30, 40]: điểm chèn 2 → trả -3. Lấy điểm chèn: int p = -result - 1; hoặc ~result.
Câu 10. Vì sao Arrays.asList(...) set được mà add lại ném UnsupportedOperationException?
Arrays.asList trả về java.util.Arrays$ArrayList — một view kích thước cố định bọc đúng mảng gốc, không có vùng lưu trữ riêng để tăng kích thước. set chỉ ghi đè phần tử nên ghi xuyên qua mảng gốc; add/remove cần đổi kích thước nên không hỗ trợ (message rỗng). Muốn list động: new ArrayList<>(Arrays.asList(...)).
Câu 11. Array covariance là gì? Vì sao Object[] o = new String[1]; o[0] = 1; compile được nhưng runtime ném ArrayStoreException?
Covariance: String[] được coi là subtype của Object[] (vì String là subtype của Object), nên gán ngầm hợp lệ. Compiler chỉ biết kiểu khai báo Object[] nên cho ghi mọi object; JVM kiểm tra kiểu thật của mảng (String[]) ở mỗi lần ghi và ném ArrayStoreException("java.lang.Integer") khi sai. Generics không covariant chính là để tránh lỗ hổng này.
Câu 12. Vì sao Object[] o = new int[3]; không compile?
Vì int[] là object nhưng không phải subtype của Object[]. Covariance chỉ áp dụng khi cả hai đều là mảng reference; phần tử của int[] là primitive int, không phải reference. Muốn "hộp" mảng primitive: Object o = new int[3]; (được) nhưng không index qua o được.
Câu 13. Varargs hoạt động thế nào? Vì sao phải là tham số cuối?
int... nums được compiler dịch thành tham số int[] nums; gọi sum(1, 2, 3) compiler tự tạo mảng, truyền mảng trực tiếp cũng được — vì vậy main(String[] args) tương đương varargs. Varargs phải đứng cuối vì nếu không compiler không biết đối số nào thuộc varargs (lỗi "varargs parameter must be the last parameter").
Câu 14. Overload có cả bản fixed arity lẫn varargs thì chọn bản nào? Khi nào ambiguous?
Overload resolution theo 3 phase: widening → boxing → varargs. Bản fixed arity khớp ngay phase 1/2 nên luôn thắng bản varargs (phase 3): pick(1, 2) chọn pick(int, int). Ambiguous xảy ra khi hai bản varargs đều khớp mà không bản nào cụ thể hơn, ví dụ m(int...) và m(boolean...) gọi m() — compiler báo "reference to m is ambiguous".
Câu 15. Arrays.sort trên mảng primitive và mảng object khác nhau thế nào?
Primitive dùng dual-pivot quicksort — hiệu năng cao, không stable; object dùng TimSort — stable, các phần tử bằng nhau giữ nguyên thứ tự gốc. Với primitive không cần stable vì hai số bằng nhau không phân biệt được; với object tính stable quan trọng khi sort nhiều tiêu chí (sort theo tên rồi sort tiếp theo lương vẫn giữ thứ tự tên).
Câu 16. Sort mảng object không implements Comparable thì sao? Comparable khác Comparator ở đâu?
Ném ClassCastException lúc chạy vì Arrays.sort(Object[]) cast phần tử sang Comparable. Comparable định nghĩa thứ tự tự nhiên của class (một class chỉ một thứ tự, method compareTo); Comparator là tiêu chí từ ngoài, tạo bao nhiêu cũng được (Comparator.comparing(Order::total).reversed()). DTO production thường để mặc định không Comparable rồi truyền Comparator khi cần.
Câu 17. Message của ArrayIndexOutOfBoundsException và NPE trên JDK hiện đại có gì đáng chú ý?
Từ JDK 14 (helpful NullPointerExceptions), message rất cụ thể: Index 3 out of bounds for length 3; NPE: Cannot read the array length because "ErrorsDemo.uninit" is null hoặc Cannot load from int array because "ErrorsDemo.uninit" is null. Tên biến local chỉ hiện khi class có debug info — chạy source-file mode (java TenFile.java) có thể hiện <local1>.
Câu 18. In mảng ra log thế nào? Vì sao System.out.println(array) ra [I@1a2b3c?
Mảng không override toString nên dùng Object.toString: tên class + "@" + identityHashCode dạng hex. [I nghĩa là mảng int, [Ljava.lang.String; nghĩa là mảng String. Dùng Arrays.toString (1D), Arrays.deepToString (2D+), hoặc List.of(array)/Arrays.stream(arr).boxed().toList(). Hash thay đổi mỗi lần chạy nên log kiểu này vô nghĩa.
Câu 19. Khi nào chọn mảng, khi nào chọn List?
Mảng khi kích thước biết trước và cố định, cần lưu primitive số lượng lớn (không boxing), cần hiệu năng/API cấp thấp, hoặc API bắt buộc (args, toArray, JDBC). List/ArrayList khi cần thêm/xóa, kích thước động, API phong phú và an toàn kiểu generics. ArrayList thực chất bọc một mảng động bên trong — mảng là nền tảng của Collections.
Câu 20. Chia sẻ mảng giữa nhiều thread cần chú ý gì?
Mảng không thread-safe: ghi/đọc đồng thời có thể race và không đảm bảo visibility (thread khác có thể thấy giá trị cũ). volatile chỉ áp dụng cho biến reference chứ không cho từng phần tử mảng; final chỉ chốt reference. Cần đồng bộ (lock, copy-on-write, hoặc cấu trúc concurrent) — đào sâu ở 4.2 Concurrency.

Checklist tự đánh giá trước phỏng vấn

  • Giải thích được mảng là object và vì sao length không có ngoặc.
  • Kể đúng giá trị mặc định của mọi kiểu phần tử.
  • Phân biệt ==, equals, Arrays.equals và deepEquals.
  • Giải thích pass-by-value của reference và vì sao sửa phần tử được nhưng gán lại mảng thì không.
  • Nói rõ vì sao for-each không sửa được phần tử.
  • Viết lại công thức trả về âm của binarySearch và cho ví dụ.
  • Giải thích shallow copy và cách deep copy mảng 2 chiều.
  • Trình bày được array covariance + ArrayStoreException bằng ví dụ tự viết.
  • Viết method varargs, biết vì sao phải đứng cuối và khi nào ambiguous.
  • Chọn được mảng hay List cho một tình huống cụ thể và nêu lý do.
