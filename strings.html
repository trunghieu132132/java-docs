2. Method quan trọng của String

String có hơn 80 method; dưới đây là nhóm dùng hằng ngày. Ghi nhớ: String bất biến, mọi method trả về chuỗi mới, không sửa object gốc (xem Biến trong Java — mục 14).

2.1 Đo, truy cập, tìm kiếm

String s = "Hello, Java!";

IO.println("length()               : " + s.length());          // 12
IO.println("charAt(0)              : " + s.charAt(0));         // H
IO.println("charAt(11)             : " + s.charAt(11));        // !
IO.println("indexOf('a')           : " + s.indexOf('a'));      // 8
IO.println("lastIndexOf('a')       : " + s.lastIndexOf('a'));  // 10
IO.println("indexOf(\"Java\")        : " + s.indexOf("Java"));   // 7
IO.println("indexOf(\"xyz\")         : " + s.indexOf("xyz"));    // -1
IO.println("contains(\"Java\")       : " + s.contains("Java"));  // true
IO.println("startsWith(\"Hell\")     : " + s.startsWith("Hell")); // true
IO.println("endsWith(\"!\")          : " + s.endsWith("!"));     // true
  • length() trả số UTF-16 code unit, không phải số ký tự người dùng nhìn thấy — emoji sẽ chiếm 2 (xem mục 7).
  • indexOf / lastIndexOf trả -1 khi không tìm thấy — đừng so với 0.
  • charAt(i) trả char; muốn lấy code point dùng codePointAt(i).

2.2 substring — bẫy chỉ số

substring(begin, end) lấy từ begin đến trước end (end độc quyền). Vượt biên là ném exception ngay lúc chạy, không trả về null:

IO.println("substring(7)           : " + s.substring(7));      // Java!
IO.println("substring(7, 11)       : " + s.substring(7, 11));  // Java
IO.println("substring(12)          : [" + s.substring(12) + "]"); // []  - chuoi rong, hop le

try {
    "abc".charAt(3);
} catch (StringIndexOutOfBoundsException e) {
    IO.println("charAt(3)      : " + e.getMessage());
    // Index 3 out of bounds for length 3
}
try {
    "abc".substring(1, 9);
} catch (StringIndexOutOfBoundsException e) {
    IO.println("substring(1,9) : " + e.getMessage());
    // Range [1, 9) out of bounds for length 3
}
try {
    "abc".substring(-1);
} catch (StringIndexOutOfBoundsException e) {
    IO.println("substring(-1)  : " + e.getMessage());
    // Range [-1, 3) out of bounds for length 3
}
try {
    "abc".repeat(-1);
} catch (IllegalArgumentException e) {
    IO.println("repeat(-1)     : " + e.getMessage());
    // count is negative: -1
}
Bẫy: substring(len) trả chuỗi rỗng (hợp lệ), nhưng charAt(len) ném exception. Và nhớ end là độc quyền: substring(0, 3) lấy 3 ký tự 0, 1, 2.

2.3 replace vs replaceAll

IO.println("replace(\".\", \"-\")        : " + "a.b".replace(".", "-"));      // a-b
IO.println("replaceAll(\"\\\\.\", \"-\")   : " + "a.b".replaceAll("\\.", "-")); // a-b
IO.println("replaceAll(\".\", \"-\")    : " + "a.b".replaceAll(".", "-"));   // ---
IO.println("replace(\"a\", \"b\")       : " + "aaa".replace("a", "b"));     // bbb
IO.println("replaceAll(\"a\", \"b\")    : " + "aaa".replaceAll("a", "b"));  // bbb
  • replace(char, char) và replace(CharSequence, CharSequence) xử lý literal, thay tất cả lần xuất hiện (khác JavaScript replace chỉ thay lần đầu).
  • replaceAll(regex, replacement) nhận regex. Dấu . là "mọi ký tự" nên "a.b".replaceAll(".", "-") thành "---". Muốn thay dấu chấm thật phải escape: "\\.".
  • replaceFirst(regex, replacement) chỉ thay lần khớp đầu tiên.

2.4 split — bẫy phần tử rỗng cuối

String[] p1 = "a,b,,c".split(",");
IO.println("a,b,,c split(\",\")      : len=" + p1.length + " -> [" + String.join("|", p1) + "]");
// len=4 -> [a|b||c]

String[] p2 = "a,b,,".split(",");
IO.println("a,b,, split(\",\")       : len=" + p2.length + " -> [" + String.join("|", p2) + "]");
// len=2 -> [a|b]      <- 2 phan tu rong cuoi bi cat bo

String[] p3 = "a,b,,".split(",", -1);
IO.println("a,b,, split(\",\", -1)   : len=" + p3.length + " -> [" + String.join("|", p3) + "]");
// len=4 -> [a|b||]

String[] p4 = "a,b,,".split(",", 2);
IO.println("a,b,, split(\",\", 2)    : len=" + p4.length + " -> [" + String.join("|", p4) + "]");
// len=2 -> [a|b,,]    <- phan con lai nam trong phan tu cuoi

String[] p5 = "one two  three".split("\\s+");
IO.println("split(\"\\\\s+\")          : len=" + p5.length + " -> [" + String.join("|", p5) + "]");
// len=3 -> [one|two|three]

String[] p6 = ",a,b".split(",");
IO.println(",a,b split(\",\")        : len=" + p6.length + " -> [" + String.join("|", p6) + "]");
// len=3 -> [|a|b]     <- rong dau chuoi thi duoc giu

String[] p7 = "".split(",");
IO.println("empty split(\",\")       : len=" + p7.length + " -> [" + String.join("|", p7) + "]");
// len=1 -> []

IO.println("split(\"\\\\s*\") on '  '  : len=" + "  ".split("\\s*").length);
// len=0
  • Mặc định Java cắt bỏ các phần tử rỗng ở cuối (limit = 0) — khác JavaScript giữ lại hết.
  • limit = -1: giữ tất cả, kể cả rỗng cuối (hay dùng khi parse CSV).
  • limit > 0: tách tối đa limit - 1 lần, phần còn lại dồn vào phần tử cuối.
  • Phần tử rỗng ở đầu hoặc giữa luôn được giữ.
Production: parse CSV thủ công bằng split(",") chỉ đúng với dữ liệu đơn giản (không có dấu phẩy trong ngoặc kép). Dữ liệu thật nên dùng thư viện CSV chuyên dụng.

2.5 Chuẩn hóa hoa/thường — chuyện locale

import java.util.Locale;

IO.println("ROOT : " + "istanbul".toUpperCase(Locale.ROOT));   // ISTANBUL
IO.println("TR   : " + "istanbul".toUpperCase(Locale.forLanguageTag("tr"))
        .replace("\u0130", "[U+0130]"));                       // [U+0130]STANBUL
IO.println("TR lower: " + "I".toLowerCase(Locale.forLanguageTag("tr"))
        .replace("\u0131", "[U+0131]"));                       // [U+0131]
IO.println("default locale: " + Locale.getDefault().toLanguageTag()); // tuy may - vi du: en-VN

Tiếng Thổ Nhĩ Kỳ có hai chữ i: i hoa thành İ (U+0130), còn I thường thành ı (U+0131, i không chấm). Nếu server chạy với locale tr, code so sánh chuỗi case-insensitive sẽ sai âm thầm.

Convention production: với dữ liệu không phải ngôn ngữ tự nhiên (mã trạng thái, email, enum name) luôn dùng toUpperCase(Locale.ROOT) / toLowerCase(Locale.ROOT) (API này có từ Java 1.1). Gọi toLowerCase() không truyền locale nghĩa là dùng locale mặc định của JVM — thứ thay đổi theo máy chủ và biến môi trường.

2.6 isEmpty vs isBlank, trim vs strip

void main() {
    String em = "\u2003abc\u2003";

    IO.println("trim()        : [" + show(em.trim()) + "] len=" + em.trim().length());
    // [[EM]abc[EM]] len=5   - EM SPACE khong bi cat
    IO.println("strip()       : [" + show(em.strip()) + "] len=" + em.strip().length());
    // [abc] len=3

    String nbsp = "\u00A0x\u00A0";
    IO.println("nbsp trim()   : [" + show(nbsp.trim()) + "] len=" + nbsp.trim().length());
    // [[NBSP]x[NBSP]] len=3
    IO.println("nbsp strip()  : [" + show(nbsp.strip()) + "] len=" + nbsp.strip().length());
    // [[NBSP]x[NBSP]] len=3  - NBSP khong phai whitespace

    IO.println("isBlank(\"\")            : " + "".isBlank());          // true
    IO.println("isBlank(\"   \")         : " + "   ".isBlank());       // true
    IO.println("isBlank(\"\\u2003\")      : " + "\u2003".isBlank());    // true
    IO.println("isBlank(\"\\u00A0\")      : " + "\u00A0".isBlank());    // false
    IO.println("isEmpty(\"   \")         : " + "   ".isEmpty());       // false
    IO.println("isEmpty(\"\")            : " + "".isEmpty());          // true
}

String show(String v) {
    return v.replace(" ", ".")
            .replace("\u2003", "[EM]")
            .replace("\u00A0", "[NBSP]");
}
  • trim() cắt mọi ký tự <= U+0020 (từ thời ASCII); strip() (Java 11+) cắt theo Character.isWhitespace (Unicode). EM SPACE (U+2003) bị strip cắt, trim giữ nguyên.
  • NBSP (non-breaking space, U+00A0) không phải whitespace theo Java: cả trim, strip lẫn isBlank đều giữ nó — dữ liệu copy từ web rất hay dính loại này.
  • isEmpty() tương đương length() == 0; isBlank() đúng cả khi chỉ toàn khoảng trắng. Validate input dùng isBlank().

3. So sánh chuỗi: equals, compareTo, matches Hay hỏi phỏng vấn

So sánh chuỗi tưởng đơn giản nhưng là nguồn bug thật trong production: == vs equals, thứ tự sắp xếp "kỳ lạ", dấu tiếng Việt, NFC/NFD. Phần String pool và == đã học ở Biến trong Java — mục 14; dưới đây là phần thực chiến.

3.1 equals vs == & so sánh null-safe

import java.util.Objects;

String a = "apple";
String b = new String("apple");

IO.println("a == b                    : " + (a == b));                    // false - khac object
IO.println("a.equals(b)               : " + a.equals(b));                 // true
IO.println("Objects.equals(a, b)      : " + Objects.equals(a, b));        // true
IO.println("Objects.equals(null, a)   : " + Objects.equals(null, a));     // false
IO.println("Objects.equals(null, null): " + Objects.equals(null, null));  // true
IO.println("a.equalsIgnoreCase(APPLE) : " + a.equalsIgnoreCase("APPLE")); // true

String x = null;
IO.println("Objects.equals(x, apple)  : " + Objects.equals(x, "apple"));  // false - khong NPE
IO.println("\"apple\".equals(x)         : " + "apple".equals(x));          // false - literal khong bao gio null
try {
    x.equals("apple");
} catch (NullPointerException e) {
    IO.println("x.equals(apple)           : NullPointerException");
}
  • == so địa chỉ object, equals so nội dung. Hai literal cùng nội dung có thể == true nhờ String pool, nhưng new String(...) luôn tạo object mới nên == false (xem Biến trong Java — mục 14).
  • Null-safe: gọi x.equals(...) khi x null sẽ ném NPE. Hai cách tránh: viết literal trước ("apple".equals(x)) hoặc dùng Objects.equals(x, y) (Java 7+) — null so null trả true, một bên null trả false.
  • equalsIgnoreCase so không phân biệt hoa thường, nhưng vẫn so từng ký tự theo ánh xạ Unicode đơn giản, không theo locale — bẫy ở mục 3.5.

3.2 compareTo / compareToIgnoreCase trả gì

IO.println("apple vs app     : " + "apple".compareTo("app"));      // 2
IO.println("apple vs banana  : " + "apple".compareTo("banana"));   // -1
IO.println("banana vs apple  : " + "banana".compareTo("apple"));   // 1
IO.println("(int) 'A'        : " + (int) 'A');                    // 65
IO.println("(int) 'a'        : " + (int) 'a');                    // 97
IO.println("A vs a           : " + "A".compareTo("a"));            // -32
IO.println("Z vs a           : " + "Z".compareTo("a"));            // -7
IO.println("apples vs Apple  : " + "apples".compareTo("Apple"));   // 32
IO.println("ignoreCase APPLE : " + "apple".compareToIgnoreCase("APPLE"));  // 0
  • Cơ chế: quét từng UTF-16 code unit; khác nhau ở vị trí đầu tiên thì trả hiệu hai code unit ('a' - 'b' = -1). Nếu một chuỗi là tiền tố của chuỗi kia thì trả hiệu độ dài: "apple".compareTo("app") = 5 - 3 = 2. Bằng nhau trả 0.
  • Thứ tự không theo alphabet người: theo code unit, chữ số (48–57) < chữ hoa A–Z (65–90) < chữ thường a–z (97–122). Nên "Z".compareTo("a") = -7 và "apples".compareTo("Apple") dương. Kết quả chỉ đảm bảo dấu (<0, 0, >0), đừng hardcode -1/1.
  • compareTo (từ Comparable) sinh ra để sắp xếp; muốn kiểm tra bằng nhau hãy dùng equals. Với String hai cái nhất quán (compareTo == 0 ⟺ equals true), nhưng không phải class nào cũng vậy — ví dụ kinh điển là BigDecimal("1.0") vs "1.00" (Biến trong Java — mục 13.6).
  • compareToIgnoreCase hạ/hoa từng ký tự bằng Character (không theo locale) rồi mới so code unit — cùng họ bẫy với equalsIgnoreCase ở mục 3.5.

3.3 Bẫy tiếng Việt: compareTo xếp sai alphabet

Chữ cái tiếng Việt có dấu nằm ở code point cao (U+00C1, U+00C2, U+0102, U+0110…), tức là sau "Z" theo thứ tự code unit — không nằm cạnh chữ gốc như người Việt mong đợi:

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

IO.println("(int) 'Z' : " + (int) 'Z');   // 90
IO.println("(int) 'Á' : " + (int) 'Á');   // 193
IO.println("(int) 'Â' : " + (int) 'Â');   // 194
IO.println("(int) 'Ă' : " + (int) 'Ă');   // 258
IO.println("(int) 'Đ' : " + (int) 'Đ');   // 272
IO.println("Á vs Z    : " + "Á".compareTo("Z"));   // 103

List<String> ten = new ArrayList<>(List.of("An", "Ánh", "Bình", "Dũng", "Đào"));
Collections.sort(ten);
IO.println("sort tu nhien : " + ten);
// [An, Bình, Dũng, Ánh, Đào]

Thứ tự đúng của người Việt là An, Ánh, Bình, Dũng, Đào (A < Á < B < D < Đ); Collections.sort mặc định đẩy "Ánh" xuống sau "Dũng" và "Đào" xuống cuối. Với dữ liệu chỉ có ASCII không dấu thì có thể "may mắn đúng", nên bug chỉ lộ khi dữ liệu thật có dấu.

3.4 Sắp xếp đúng theo ngôn ngữ: java.text.Collator

Collator là comparator hiểu quy tắc collation của từng ngôn ngữ. Lấy instance theo locale rồi truyền thẳng vào sort:

import java.text.Collator;
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.Locale;

Locale vi = Locale.forLanguageTag("vi");
Locale vi2 = Locale.of("vi");               // Java 19+, ngan hon
IO.println("vi             : " + vi);              // vi
IO.println("vi.equals(vi2) : " + vi.equals(vi2));   // true

Collator col = Collator.getInstance(vi);
List<String> ten = new ArrayList<>(List.of("An", "Ánh", "Bình", "Dũng", "Đào"));

Collections.sort(ten);
IO.println("natural        : " + ten);   // [An, Bình, Dũng, Ánh, Đào]

Collections.sort(ten, col);
IO.println("collator vi    : " + ten);   // [An, Ánh, Bình, Dũng, Đào]

Collator phân tầng (strength) khi so: strength càng mạnh thì phân biệt càng nhiều. Mặc định là TERTIARY:

import java.text.Collator;
import java.util.Locale;
import java.util.TreeMap;

Collator col = Collator.getInstance(Locale.of("vi"));

IO.println("A vs Á         : " + col.compare("A", "Á"));   // -1
IO.println("a vs A         : " + col.compare("a", "A"));   // -1 - chu thuong truoc chu hoa

Collator p = (Collator) col.clone();
p.setStrength(Collator.PRIMARY);
IO.println("PRIMARY A = Á  : " + (p.compare("A", "Á") == 0));   // true  - bo dau
IO.println("PRIMARY a = A  : " + (p.compare("a", "A") == 0));   // true  - bo hoa thuong

Collator s = (Collator) col.clone();
s.setStrength(Collator.SECONDARY);
IO.println("SECONDARY A = Á: " + (s.compare("A", "Á") == 0));   // false - phan biet dau
IO.println("SECONDARY a = A: " + (s.compare("a", "A") == 0));   // true  - van bo hoa thuong

Collator t = (Collator) col.clone();
t.setStrength(Collator.TERTIARY);
IO.println("TERTIARY a = A : " + (t.compare("a", "A") == 0));   // false - phan biet ca hoa thuong

TreeMap<String, Integer> map = new TreeMap<>(col);
map.put("Đào", 1);
map.put("An", 2);
map.put("Bình", 3);
IO.println("TreeMap keys   : " + map.keySet());   // [An, Bình, Đào]
  • Collator.getInstance(locale) lấy quy tắc collation mà JDK có sẵn cho locale đó. Locale.forLanguageTag("vi") và Locale.of("vi") (Java 19+) tương đương — dùng cái ngắn hơn; code cũ hơn thì new Locale("vi") (deprecated từ Java 19).
  • Strength: PRIMARY bỏ hết dấu và hoa thường (Á = A = a); SECONDARY phân biệt dấu nhưng bỏ hoa thường (A = a, A ≠ Á); TERTIARY (mặc định) phân biệt cả hai. Kết quả compare của Collator chỉ cần dấu, đừng hardcode -1/1.
  • Collator là Comparator<Object> nên dùng được với List.sort, Collections.sort, TreeMap, TreeSet. Javadoc lưu ý implementation mặc định (RuleBasedCollator) có thể tranh chấp khi dùng đồng thời — nên mỗi thread một instance; tuyệt đối không đổi strength trên instance đang chia sẻ.
  • Collation của Java ≠ collation của DB. MySQL/Postgres có bảng collation riêng (MySQL utf8mb4_vi_0900_ai_ci, Postgres ICU vi-x-icu…); Java sort theo dữ liệu collation của JDK còn DB sort theo cài đặt của nó — hai kết quả có thể lệch ở các trường hợp biên. Hãy thống nhất sort ở một tầng (hoặc đảm bảo DB collation khớp ngôn ngữ) thay vì trộn.

3.5 Bẫy locale: equalsIgnoreCase không theo locale

equalsIgnoreCase so từng char bằng Character.toLowerCase/toUpperCase — ánh xạ Unicode đơn giản, không theo locale. Kiểm chứng thật trên JDK 25:

import java.util.Locale;

IO.println("ß vs SS equalsIgnoreCase : " + "ß".equalsIgnoreCase("SS"));      // false
IO.println("ß.toUpperCase()          : " + "ß".toUpperCase());               // SS
IO.println("ß.toUpperCase() bang SS  : " + "ß".toUpperCase().equals("SS"));  // true

IO.println("İ vs i equalsIgnoreCase  : " + "İ".equalsIgnoreCase("i"));       // true
IO.println("I vs ı equalsIgnoreCase  : " + "I".equalsIgnoreCase("ı"));       // true
IO.println("I vs i equalsIgnoreCase  : " + "I".equalsIgnoreCase("i"));       // true

IO.println("I.toLowerCase()          : " + "I".toLowerCase());               // i
IO.println("I.toLowerCase(tr)        : " + "I".toLowerCase(Locale.of("tr"))); // ı
IO.println("i.toUpperCase(tr)        : " + "i".toUpperCase(Locale.of("tr"))); // İ
  • "ß".equalsIgnoreCase("SS") = false vì ß là 1 ký tự còn SS là 2, dù "ß".toUpperCase() = "SS". Ánh xạ 1-nhiều (ß→SS, ﬁ→FI) chỉ xảy ra ở toUpperCase(), không xảy ra khi so từng ký tự.
  • Chiều ngược: equalsIgnoreCase theo ánh xạ chuẩn Unicode chứ không theo locale — "İ".equalsIgnoreCase("i") và "I".equalsIgnoreCase("ı") trả true (đúng cặp Unicode), nhưng nó cũng trả true cho "I".equalsIgnoreCase("i"), cặp mà tiếng Thổ Nhĩ Kỳ coi là hai chữ khác nhau ("I".toLowerCase(Locale.of("tr")) = "ı", "i".toUpperCase(Locale.of("tr")) = "İ"). Vì vậy đừng dùng nó cho dữ liệu đa ngôn ngữ khi cần đúng ngữ nghĩa.
  • Muốn không phân biệt hoa thường đúng ngôn ngữ: dùng Collator với PRIMARY/SECONDARY (mục 3.4), hoặc chuẩn hoá dữ liệu về một dạng (NFC + toLowerCase(Locale)) ngay khi nhập rồi so equals.
  • toLowerCase/toUpperCase mới theo locale nếu truyền Locale: "I".toLowerCase(Locale.of("tr")) = "ı".

  • Sort tên để hiển thị/tìm kiếm cho người Việt: luôn dùng Collator locale vi (hoặc collation DB tương ứng), không dùng thứ tự tự nhiên. binarySearch bắt buộc dùng cùng comparator với lúc sort, nếu không kết quả vô nghĩa.
  • Chuẩn hoá NFC ngay khi nhận dữ liệu rồi mới lưu/so — equals không tự bỏ qua khác biệt NFC/NFD. Collator thì compare được cả hai dạng, nhưng vẫn phải normalize để dữ liệu sạch và unique index trong DB hoạt động đúng. Chi tiết ở mục 7 — Unicode & tiếng Việt.
  • Tìm kiếm "không dấu" bằng PRIMARY chỉ gộp dấu phụ (A = Á, a = á) nhưng không gộp Đ = D — vì "đ" là chữ cái riêng chứ không phải "d" cộng dấu. Muốn tìm "dat" ra "Đạt" phải strip dấu bằng tay (Đ→D, bỏ dấu thanh…) hoặc dùng tìm kiếm full-text của DB; đừng tưởng PRIMARY là "bỏ hết dấu".
  • Dữ liệu từ DB: cột collation ..._ai_ci (accent-insensitive, case-insensitive) làm WHERE name = ? có thể khớp khác Java; nếu app cũng tự lọc/sort thì cần biết chính xác collation hai bên để tránh lệch kết quả giữa UI và DB.

Góc Node.js

  • JS không có bẫy == kiểu Java: "a" === "a" so theo giá trị. Chỉ khi bọc new String("a") mới thành object và new String("a") === "a" là false — trường hợp hiếm; quy tắc JS là luôn dùng ===, còn Java là luôn dùng equals.
  • "Ánh".localeCompare("Bình", "vi") trả thứ tự đúng ngôn ngữ; nhưng gọi trong comparator của sort sẽ tạo collator mỗi lần so — tốn kém.
  • Cách chuẩn: tạo một lần new Intl.Collator("vi", { sensitivity: "base" }) rồi dùng .compare như Comparator. sensitivity: "base" ≈ PRIMARY (bỏ dấu + hoa thường), "accent" ≈ SECONDARY, "variant" ≈ TERTIARY.
  • JS cũng dùng UTF-16, length và normalize("NFC") hành xử giống Java — và localeCompare cũng không tự normalize, nên vẫn phải normalize trước khi so.
Chốt gọn: bằng nhau → equals (null-safe: Objects.equals hoặc literal-first), không bao giờ ==; thứ tự kỹ thuật → compareTo; thứ tự cho người đọc (tên, địa danh) → Collator theo locale + strength phù hợp; dữ liệu nhập từ nhiều nguồn → normalize NFC trước và thống nhất collation với DB.

  • matches() một lần cũng ngầm thêm ^...$; ngược lại find() chỉ cần khớp một đoạn.
  • Greedy vs reluctant: .* tham lam — khớp dài nhất có thể nên <.*> nuốt cả chuỗi HTML; .*? nhường — khớp ngắn nhất, cho kết quả từng thẻ.
  • Email/số điện thoại thật rất phức tạp; regex đơn giản như trên chỉ để chặn dữ liệu rõ ràng sai (mức "nhận biết": nên xác thực email triệt để bằng gửi mail xác nhận).

Pattern là bất biến và thread-safe, còn Matcher thì không — muốn dùng ở nhiều thread phải tạo Matcher mới từ cùng Pattern. Pattern.compile khá tốn kém nên trong production khai báo một lần:

private static final Pattern EMAIL = Pattern.compile("^[\\w.+-]+@[\\w-]+\\.[\\w.]+$");

7. Unicode & tiếng Việt Hay hỏi phỏng vấn

char là một UTF-16 code unit (16 bit), không phải một ký tự Unicode. Ký tự ngoài BMP (basic multilingual plane) như emoji cần 2 char (surrogate pair), nên length() đếm code unit chứ không đếm ký tự:

String emoji = "a\uD83D\uDE00b";   // a + U+1F600 + b

IO.println("length()           : " + emoji.length());                       // 4
IO.println("codePointCount     : " + emoji.codePointCount(0, emoji.length())); // 3
IO.println("codePoints().count : " + emoji.codePoints().count());           // 3
IO.println("chars().count      : " + emoji.chars().count());                 // 4
IO.println("charAt(1) hex      : " + Integer.toHexString(emoji.charAt(1)));  // d83d
IO.println("charAt(2) hex      : " + Integer.toHexString(emoji.charAt(2)));  // de00
IO.println("codePointAt(1) hex : " + Integer.toHexString(emoji.codePointAt(1))); // 1f600
IO.println("codePoints hex     : " + emoji.codePoints()
        .mapToObj(cp -> "U+" + Integer.toHexString(cp).toUpperCase())
        .toList());
// [U+61, U+1F600, U+62]
  • charAt(1) trả nửa đầu surrogate (0xD83D) — cắt chuỗi theo char có thể làm vỡ emoji.
  • codePointCount, codePointAt, codePoints() làm việc theo code point — đúng với ký tự người dùng thấy. Phân biệt với chars(): method này trả về IntStream các code unit (4 cho "a\uD83D\uDE00b"), còn codePoints() trả các code point (3).
  • Cả Java lẫn JavaScript đều dùng UTF-16 cho String, nên "a\uD83D\uDE00b".length trong JS cũng bằng 4.

Normalize NFC/NFD — cạm bẫy tiếng Việt

Một ký tự tiếng Việt như "ế" có hai cách biểu diễn Unicode: NFC (một code point U+1EBF) hoặc NFD (e + dấu mũ + dấu sắc = 3 code point). Nhìn giống nhau nhưng equals trả false:

import java.text.Normalizer;

String nfc = "\u1EBF";        // ế - precomposed
String nfd = "e\u0302\u0301"; // e + U+0302 + U+0301

IO.println("NFC length         : " + nfc.length());          // 1
IO.println("NFD length         : " + nfd.length());          // 3
IO.println("NFC.equals(NFD)    : " + nfc.equals(nfd));      // false
IO.println("NFC.compareTo(NFD) : " + nfc.compareTo(nfd));   // 7770

String nfdNormalized = Normalizer.normalize(nfd, Normalizer.Form.NFC);
IO.println("normalize(NFD,NFC) : " + nfc.equals(nfdNormalized));   // true
IO.println("NFD len sau normalize: " + Normalizer.normalize(nfc, Normalizer.Form.NFD).length()); // 3

String composed = "\u00E9";   // é
String decomposed = "e\u0301"; // e + dấu sắc
IO.println("\\u00E9 equals e+\\u0301 : " + composed.equals(decomposed));   // false
IO.println("sau NFC            : " + Normalizer.normalize(decomposed, Normalizer.Form.NFC).equals(composed)); // true
Production: macOS lưu tên file ở dạng NFD; dữ liệu người dùng nhập từ nhiều nguồn có thể lẫn NFC/NFD. Hệ quả: so sánh equals thất bại, unique index trong DB không chặn được bản ghi trùng, tìm kiếm không khớp. Cách phòng: chuẩn hóa về NFC ngay tại biên nhận dữ liệu (Normalizer.normalize(s, Form.NFC)) rồi mới lưu/so sánh.

11. Interview Q&A Hay hỏi phỏng vấn

Cơ bản

Câu 1. String bất biến nghĩa là gì? Hệ quả thực tế?
Không thể đổi nội dung sau khi tạo; mọi method như substring, trim, toUpperCase trả object mới. Hệ quả: nối chuỗi trong vòng lặp tạo nhiều object rác (dùng StringBuilder), String có thể chia sẻ an toàn giữa các thread, và String pool/intern hoạt động được. Chi tiết pool và == xem Biến trong Java — mục 14.
Câu 2. length() đếm gì? charAt trả gì?
length() đếm số UTF-16 code unit (kiểu char), không phải số ký tự Unicode. charAt(i) trả một char (16 bit). Ký tự ngoài BMP chiếm 2 code unit nên "\uD83D\uDE00".length() == 2.
Câu 3. substring(1, 3) lấy ký tự nào? Vì sao?
Lấy ký tự ở chỉ số 1 và 2 — tham số thứ hai là độc quyền (không lấy ký tự ở chỉ số 3). "hello".substring(1, 3) = "el"; substring(3) = "lo".
Câu 4. Vì sao "a,b,,".split(",").length bằng 2?
Mặc định split (limit = 0) cắt bỏ mọi phần tử rỗng ở cuối. Muốn giữ hết dùng split(",", -1) → length 4. Phần tử rỗng ở đầu/giữa vẫn luôn được giữ.
Câu 5. Tham số limit của split có mấy kiểu giá trị ảnh hưởng?
Ba nhóm: limit > 0 — tách tối đa limit - 1 lần, phần còn lại dồn vào phần tử cuối; limit = 0 — cắt rỗng cuối (mặc định); limit < 0 — giữ tất cả, kể cả rỗng cuối.
Câu 6. replace và replaceAll khác nhau thế nào?
replace xử lý literal và thay tất cả lần xuất hiện; replaceAll nhận regex. Bẫy: "a.b".replaceAll(".", "-") ra "---" vì dấu chấm là regex "mọi ký tự" — phải viết "\\.". Lưu ý Java replace thay tất cả, khác JS replace chỉ thay lần đầu.
Câu 7. isEmpty khác isBlank thế nào?
isEmpty() tương đương length() == 0; isBlank() còn đúng khi chuỗi chỉ gồm ký tự whitespace theo Character.isWhitespace. Validate input nên dùng isBlank(). Cảnh báo: NBSP (U+00A0) không tính là whitespace với Java.
Câu 8. trim() khác strip() thế nào?
trim() cắt ký tự <= U+0020 (chỉ ASCII); strip() (Java 11+) cắt theo whitespace Unicode nên xử lý được EM SPACE U+2003, các khoảng trắng tiếng Nhật... Dữ liệu người dùng nên dùng strip(). Cả hai đều không cắt NBSP.
Câu 9. So sánh nội dung chuỗi bằng gì? Vì sao không dùng ==?
Dùng equals() (hoặc equalsIgnoreCase). == so tham chiếu object; chuỗi tạo từ new, cắt ghép, đọc từ DB/JSON không nằm cùng ô nhớ với literal nên == trả false dù nội dung giống. Chi tiết pool/intern ở Biến trong Java — mục 14.
Câu 10. compareTo trả về gì?
Hiệu của hai ký tự khác nhau đầu tiên (theo UTF-16), hoặc hiệu độ dài nếu một chuỗi là tiền tố của chuỗi kia; 0 nghĩa là bằng nhau. Ví dụ "apple".compareTo("banana") = -1, "apple".compareTo("app") = 2. Dùng để sắp xếp, dùng equals để kiểm tra bằng nhau.
Câu 11. %02d và %.2f làm gì?
%02d in số nguyên với tối thiểu 2 chữ số, thiếu thì thêm 0 (9 → "09"). %.2f in số thực với 2 chữ số sau dấu chấm, làm tròn HALF_UP (2.345 → "2.35"). Dạng khác: %,d phân cách nghìn theo locale, %-10s căn trái.
Câu 12. Text block là gì, khai báo ra sao?
Chuỗi nhiều dòng (Java 15+) mở/đóng bằng """. Dấu mở phải xuống dòng ngay sau đó (nếu không là lỗi compile "missing line terminator"). Java tự bỏ phần thụt lề chung nhỏ nhất; nếu dấu đóng nằm dòng riêng thì chuỗi kết quả có newline cuối. Dùng cho JSON/SQL/HTML; không nội suy biến nên thường ghép .formatted().

Nâng cao (Junior+)

Câu 13. Vì sao "\uD83D\uDE00".length() bằng 2?
U+1F600 nằm ngoài BMP nên cần 2 UTF-16 code unit (surrogate pair). length() đếm code unit, không đếm ký tự. Muốn đếm đúng ký tự dùng codePointCount(0, s.length()).
Câu 14. Khi nào dùng codePoints() thay vì lặp charAt?
Khi xử lý văn bản có ký tự ngoài BMP (emoji, chữ tượng hình mở rộng): đảo chuỗi, kiểm tra độ dài theo người dùng, cắt/gộp theo ký tự. Lặp charAt có thể tách đôi surrogate pair gây lỗi hiển thị.
Câu 15. NFC/NFD là gì? Vì sao quan trọng với tiếng Việt?
Hai dạng chuẩn hóa Unicode: NFC gộp dấu thành một code point ("ế" = U+1EBF, length 1), NFD tách thành chữ cơ sở + dấu tổ hợp ("ế" = e + U+0302 + U+0301, length 3). Hai chuỗi nhìn giống hệt nhưng equals trả false. Dữ liệu từ macOS (APFS lưu tên file NFD), từ web, từ các hệ thống khác có thể lẫn dạng. Cách xử lý: chuẩn hóa về NFC ngay khi nhận dữ liệu.
Câu 16. Khi nào dùng StringBuilder thay String?
Khi nối/biến đổi chuỗi nhiều lần: vòng lặp, build SQL/JSON/HTML động, xử lý file lớn. String bất biến nên mỗi phép + tạo object mới. Một biểu thức + đơn lẻ thì compiler đã tối ưu qua invokedynamic, không cần StringBuilder.
Câu 17. StringBuilder và StringBuffer khác nhau thế nào?
StringBuffer có các method synchronized nên thread-safe nhưng chậm hơn; StringBuilder nhanh hơn, không thread-safe. Mặc định dùng StringBuilder; StringBuffer gần như chỉ còn trong code cũ.
Câu 18. Vì sao nên viết "ACTIVE".equals(status) thay vì status.equals("ACTIVE")?
Nếu status là null, cách đầu trả false an toàn, cách sau ném NullPointerException. Trong production, dữ liệu từ DB/API rất hay null nên convention là đặt hằng số/literal bên trái.
Câu 19. Greedy và reluctant trong regex khác nhau thế nào?
Lượng từ greedy (.*, .+) khớp dài nhất có thể; thêm ? thành reluctant khớp ngắn nhất. Ví dụ "<b>a</b>".replaceAll("<.*>", "X") ra "X" (nuốt cả chuỗi), còn "<.*?>" ra "XaX".
Câu 20. Vì sao nên Pattern.compile một lần rồi tái sử dụng? Catastrophic backtracking là gì?
Pattern.compile tốn kém và Pattern là bất biến/thread-safe nên compile một lần vào static final. Catastrophic backtracking là hiện tượng regex có nhóm lồng lượng từ (ví dụ (a+)+$) thử số tổ hợp tăng theo cấp số nhân với input không khớp, gây treo CPU/DoS. Phòng bằng cách tránh nhóm lồng nhau và giới hạn độ dài input.
Câu 21. %.2f làm tròn theo quy tắc nào? Có nên dùng cho tiền không?
HALF_UP trên biểu diễn thập phân: 2.345 → "2.35", 1.005 → "1.01". Nhưng nó vẫn dựa trên số thực nhị phân, không phù hợp để tính tiền. Hãy tính bằng BigDecimal với RoundingMode rồi mới format (xem Biến trong Java — mục 13).
Câu 22. Vì sao không nên dùng String cho mật khẩu?
String bất biến nên không thể xóa nội dung khỏi bộ nhớ; mật khẩu có thể tồn tại lâu trong heap, lọt vào heap dump hoặc String pool (nếu từng là literal). char[] có thể ghi đè bằng Arrays.fill ngay sau khi dùng. Đây là mức nhận biết; thực tế còn tùy thư viện và API bên dưới.

Dòng 1 in false (không NPE vì hằng số đứng trước). Dòng 2 ném NullPointerException — đây chính là lý do convention "ACTIVE".equals(status).
Bài 11 
IO.println("<b>a</b>".replaceAll("<.*>", "X"));
IO.println("<b>a</b>".replaceAll("<.*?>", "X"));
In ra X rồi XaX. .* greedy nuốt cả chuỗi từ < đầu đến > cuối; .*? reluctant chỉ khớp từng cặp thẻ.
Bài 12 
IO.println("|" + "%-6s|".formatted("ab"));
IO.println("|" + "%6s|".formatted("ab"));
In ra |ab | rồi | ab|. Dấu - nghĩa là căn trái, mặc định (không có -) căn phải; số 6 là độ rộng tối thiểu.
