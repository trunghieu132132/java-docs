1. Tổng quan & cách học

Hay hỏi phỏng vấn Junior+ Production

Enum (enumeration — kiểu liệt kê) là kiểu dữ liệu đặc biệt: bạn khai báo một danh sách hữu hạn các hằng có tên, và Java đảm bảo biến chỉ nhận đúng một trong các hằng đó. Ví dụ trạng thái đơn hàng chỉ có thể là PENDING, PAID, SHIPPED, CANCELLED — không có giá trị thứ năm nào khác.

Trước Java 5, người ta thường dùng hằng int (static final int PAID = 2;) hoặc String ("PAID"). Cách này có ba vấn đề lớn:

  • Không type-safe — setStatus(999) hay setStatus("PADI") (gõ sai một ký tự) vẫn compile bình thường, lỗi chỉ lộ ra lúc chạy.
  • Magic number/string rải rác — cùng một trạng thái được so sánh với 2 ở chỗ này, "PAID" ở chỗ khác, đổi giá trị là đi sửa khắp nơi.
  • Không gắn được hành vi — không thể viết status.label(); phải tạo switch hoặc Map tra cứu ở ngoài.

Enum giải quyết cả ba. Điểm cần khắc sâu ngay từ đầu: mỗi hằng enum là một object singleton duy nhất của enum class, được JVM tạo đúng một lần khi enum class được khởi tạo (class initialization — lần đầu được dùng, first active use). Vì vậy so sánh enum bằng == vừa đúng vừa nhanh (không cần gọi equals), và switch trên enum rất hiệu quả.

Mức độ bắt buộc của chủ đề 2.7 (phỏng vấn: cao · production: bắt buộc):

  • Phải làm được — khai báo enum (kể cả có field/constructor/method); dùng values()/valueOf()/name()/ordinal() đúng chỗ; viết switch trên enum; phân biệt 4 loại nested class và chọn đúng loại; viết sealed hierarchy + switch exhaustive không cần default.
  • Phải hiểu — vì sao không lưu ordinal() vào DB; vì sao enum constructor chỉ private; vì sao inner class giữ outer reference và có thể gây memory leak; vì sao sealed giúp compiler kiểm tra đủ nhánh.
  • Nhận biết — enum singleton idiom (Effective Java); EnumMap/EnumSet và lý do tối ưu; pattern matching switch + record pattern (Java 21); non-sealed; lambda thay thế anonymous class (học ở 3.6 Lambda & functional interfaces).

Cách học hiệu quả nhất:

  1. Đoán output của ví dụ trước khi nhìn khối kết quả.
  2. Làm mục Bài tập đoán output trước, chỉ mở đáp án sau khi đã đoán.
  3. Ôn nhanh bằng Cheat sheet trước buổi phỏng vấn.
  4. Gặp câu lạ, tra ở mục Interview Q&A.
Ví dụ dùng IO.println(...) — cách viết gọn của JDK 25 (JEP 512), tương đương System.out.println(...) mà bạn sẽ thấy trong đề phỏng vấn và tài liệu cũ. Các file ví dụ là compact source file: chạy trực tiếp java TenFile.java, không cần khai báo class bao ngoài cho hàm main.

2. Enum cơ bản — Color Junior+

Khai báo enum gọn nhất: danh sách hằng viết hoa, ngăn cách bằng dấu phẩy. Nếu còn thân enum (field, method) thì kết thúc danh sách bằng dấu chấm phẩy.

[access] enum Color { RED, GREEN, BLUE } 
enum Color { RED, GREEN, BLUE }

void main() {
    Color c = Color.GREEN;
    IO.println("c = " + c);                                      // GREEN
    IO.println("name = " + c.name());                            // GREEN
    IO.println("ordinal = " + c.ordinal());                      // 1
    IO.println("valueOf = " + Color.valueOf("RED"));             // RED
    IO.println("values = " + Arrays.toString(Color.values()));   // [RED, GREEN, BLUE]
    IO.println("so luong = " + Color.values().length);           // 3

    Color a = Color.valueOf("RED");
    IO.println("a == Color.RED: " + (a == Color.RED));           // true
    IO.println("a.equals(Color.RED): " + a.equals(Color.RED));   // true

    switch (c) {
        case RED -> IO.println("Dung lai");
        case GREEN -> IO.println("Di tiep");
        case BLUE -> IO.println("Cham lai");
    }
}

Qua reflection: Color.class.isEnum() kiểm tra có phải enum, Color.class.getEnumConstants() trả mảng hằng (hoặc null nếu không phải enum) — hữu ích khi kiểu enum chỉ biết lúc runtime.

switch trên enum

Case label là tên hằng trần, không viết Color.RED (compiler đã biết kiểu selector). Switch expression trên enum trở nên exhaustive nếu bạn liệt kê đủ hằng — không cần default; thêm hằng mới mà quên nhánh là lỗi compile ngay (chi tiết ở mục 6).

Bẫy null: switch trên biến enum đang là null sẽ ném NullPointerException — enum không "khớp default" như bạn có thể tưởng. Từ Java 21 có thể thêm case null để xử lý tường minh (xem mục 11).

Enum cũng là object nên đặt vào collection thoải mái:

List<Color> ds = List.of(Color.RED, Color.BLUE);
Set<Color> tap = new HashSet<>(ds);
IO.println(ds);              // [RED, BLUE]
IO.println(tap.contains(Color.RED)); // true

Với hai collection chuyên biệt cho enum là EnumMap và EnumSet, bạn nên dùng chúng thay HashMap/HashSet — lý do ở mục 5.

3. Enum có field, constructor & method Junior+

Enum là class thật, nên hoàn toàn có thể mang dữ liệu và hành vi. Ví dụ trạng thái đơn hàng kèm nhãn hiển thị và mã số nghiệp vụ:

enum OrderStatus { PENDING("Cho xu ly", 1), PAID("Da thanh toan", 2); ... constructor + getter } 
enum OrderStatus {
    PENDING("Cho xu ly", 1),
    PAID("Da thanh toan", 2),
    SHIPPED("Dang giao", 3),
    CANCELLED("Da huy", 0);

    private final String label;
    private final int code;

    OrderStatus(String label, int code) {   // constructor ngam private
        this.label = label;
        this.code = code;
    }

    String label() {
        return label;
    }

    int code() {
        return code;
    }

    static OrderStatus fromCode(int code) {
        for (OrderStatus s : values()) {
            if (s.code == code) {
                return s;
            }
        }
        throw new IllegalArgumentException("code khong hop le: " + code);
    }
}

void main() {
    OrderStatus s = OrderStatus.fromCode(2);
    IO.println(s + " -> " + s.label() + " (" + s.code() + ")");

    for (OrderStatus x : OrderStatus.values()) {
        IO.println(x.ordinal() + ": " + x.label());
    }

    try {
        OrderStatus.fromCode(99);
    } catch (IllegalArgumentException e) {
        IO.println("loi: " + e.getMessage());
    }
}

4. Enum nâng cao — abstract method, interface, singleton Hay hỏi phỏng vấn

Mỗi hằng một hành vi — abstract method

Enum có thể khai báo abstract method, và từng hằng bắt buộc override bằng thân riêng. Cú pháp: hằng viết như TEN { ... }:

enum Day {
    MONDAY {
        @Override
        boolean isWeekend() {
            return false;
        }
    },
    SATURDAY {
        @Override
        boolean isWeekend() {
            return true;
        }
    },
    SUNDAY {
        @Override
        boolean isWeekend() {
            return true;
        }
    };

    abstract boolean isWeekend();
}

void main() {
    IO.println(Day.MONDAY + " -> " + Day.MONDAY.isWeekend());
    IO.println(Day.SATURDAY + " -> " + Day.SATURDAY.isWeekend());
    IO.println(Day.SUNDAY + " -> " + Day.SUNDAY.isWeekend());
    IO.println("lop that cua SATURDAY: " + Day.SATURDAY.getClass().getName());
}
MONDAY -> false
SATURDAY -> true
SUNDAY -> true
lop that cua SATURDAY: DayDemo$Day$2

Dòng cuối tiết lộ cơ chế: hằng có thân riêng trở thành một anonymous subclass của enum (Day$2 là class vô danh thứ hai). Hằng không có thân riêng dùng chung class enum. Đây là lý do getClass() của hai hằng có thể khác nhau — đừng bao giờ viết day.getClass() == Day.class.

Luật bắt buộc: khi enum khai báo abstract method, mọi hằng phải có thân override riêng. Hằng không có thân sẽ là instance của enum class — vốn abstract — nên bị lỗi compile. (Câu "hằng không có thân dùng chung class enum" ở trên chỉ đúng khi enum không có abstract method.)

    MONDAY,                                              // khong co than override
    SUNDAY { boolean isWeekend() { return true; } };

Enum implements interface

Enum không extends được class khác (đã extends java.lang.Enum ngầm), nhưng implements bao nhiêu interface cũng được. Kết hợp với abstract method per constant, bạn có bảng chiến lược cực gọn:

import java.util.function.IntBinaryOperator;

enum PhepTinh implements IntBinaryOperator {
    CONG("cong") {
        @Override
        public int applyAsInt(int a, int b) {
            return a + b;
        }
    },
    TRU("tru") {
        @Override
        public int applyAsInt(int a, int b) {
            return a - b;
        }
    },
    NHAN("nhan") {
        @Override
        public int applyAsInt(int a, int b) {
            return a * b;
        }
    };

    private final String ten;

    PhepTinh(String ten) {
        this.ten = ten;
    }

    String ten() {
        return ten;
    }
}

void main() {
    IO.println(PhepTinh.CONG.ten() + ": " + PhepTinh.CONG.applyAsInt(3, 4));
    IO.println(PhepTinh.TRU.ten() + ": " + PhepTinh.TRU.applyAsInt(10, 4));
    IO.println(PhepTinh.NHAN.ten() + ": " + PhepTinh.NHAN.applyAsInt(3, 4));

    IntBinaryOperator f = PhepTinh.CONG;
    IO.println("qua interface: " + f.applyAsInt(1, 2));
}
cong: 7
tru: 6
nhan: 12
qua interface: 3

IntBinaryOperator là functional interface chuẩn của JDK — nghĩa là mỗi hằng enum cũng dùng được như một lambda/strategy truyền vào method khác. JDK có sẵn ví dụ tương tự: java.util.concurrent.TimeUnit vừa là enum vừa có method chuyển đổi đơn vị.

Enum singleton — cách viết singleton an toàn nhất

Vì mỗi hằng enum là singleton do JVM quản lý, chỉ cần một hằng INSTANCE là có ngay singleton. Effective Java gọi đây là cách viết singleton tốt nhất: an toàn với đa luồng, an toàn với serialization (JVM tự đảm bảo đọc ra vẫn là cùng instance), và chống cả reflection (không thể new enum bằng constructor).

enum AppConfig {
    INSTANCE;

    private final String env = "prod";
    private final int timeout = 30;

    String env() {
        return env;
    }

    int timeout() {
        return timeout;
    }
}

void main() {
    AppConfig a = AppConfig.INSTANCE;
    AppConfig b = AppConfig.INSTANCE;
    IO.println(a.env() + " / timeout=" + a.timeout());
    IO.println("cung mot object: " + (a == b));
}
prod / timeout=30
cung mot object: true

Trong production hiện đại, singleton thường được để cho container (Spring) quản lý thay vì tự viết. Nhưng enum singleton vẫn xuất hiện đầy trong codebase — nhất là các utility/config không phụ thuộc framework. Xem thêm ở 2.8 SOLID & design patterns.

5. EnumMap & EnumSet Production

EnumMap và EnumSet là hai collection chuyên cho enum key, được thiết kế tối ưu dựa trên đặc điểm enum có tập hằng cố định và ordinal() liên tục:

enum Day { MON, TUE, WED, THU, FRI, SAT, SUN }

void main() {
    EnumMap<Day, String> lich = new EnumMap<>(Day.class);
    lich.put(Day.FRI, "review sprint");
    lich.put(Day.MON, "hop team");
    IO.println("EnumMap: " + lich);

    EnumSet<Day> cuoiTuan = EnumSet.of(Day.SAT, Day.SUN);
    IO.println("EnumSet: " + cuoiTuan);
    IO.println("co SUN? " + cuoiTuan.contains(Day.SUN));
    IO.println("tat ca: " + EnumSet.allOf(Day.class));
}
EnumMap: {MON=hop team, FRI=review sprint}
EnumSet: [SAT, SUN]
co SUN? true
tat ca: [MON, TUE, WED, THU, FRI, SAT, SUN]

Hai chi tiết đáng chú ý trong output:

  • Thứ tự duyệt luôn là thứ tự khai báo hằng — dù FRI được put trước MON, EnumMap vẫn in {MON=..., FRI=...}. Không phụ thuộc hash, kết quả ổn định giữa các lần chạy.
  • Không nhận key/element null — EnumMap và EnumSet ném NullPointerException thay vì lưu null.

6. Pitfalls của enum Hay hỏi phỏng vấn

Enum an toàn hơn hằng int/String, nhưng vẫn có những cái bẫy khiến dữ liệu sai âm thầm hoặc chương trình nổ lúc chạy. Sáu nhóm dưới đây đều đã chạy thật bằng JDK 25 — biết trước để không mất cả buổi debug.

6.1 values() tạo mảng mới mỗi lần gọi

values() không trả về mảng nội bộ mà tạo một mảng copy mới ở mỗi lần gọi. Điều này bảo vệ hằng enum khỏi bị sửa qua mảng, nhưng lại là bẫy cấp phát trong vòng lặp nóng:

enum Day {
    MON, TUE, WED;

    private static final Day[] VALUES = values();   // cache mot lan

    static int dem() {
        return VALUES.length;                       // khong cap phat them
    }
}

void main() {
    Day[] a = Day.values();
    Day[] b = Day.values();
    IO.println(a == b);          // false - hai mang khac nhau

    a[0] = Day.WED;              // sua ban copy
    IO.println(Day.MON);         // MON - hang so khong doi
    IO.println(Day.values()[0]); // MON - lan goi sau van dung
    IO.println(Day.dem());       // 3 - lay tu cache
}
false
MON
MON
3
  • Đừng gọi values() lặp đi lặp lại trong hot path — kể cả values().length, mỗi lần vẫn cấp phát một mảng chỉ để lấy độ dài.
  • Cache một lần: private static final Day[] VALUES = values(); rồi tra cứu trên mảng đó. Nếu buộc phải trả mảng ra ngoài, trả clone() (hoặc List.copyOf) để người nhận không sửa được bản gốc.
Trong enhanced for for (Day d : Day.values()), mảng chỉ được tạo một lần cho cả vòng lặp — cách viết thông thường này hoàn toàn ổn. Vấn đề chỉ nằm ở việc gọi values() bên trong vòng lặp hoặc trong hàm được gọi dày đặc.

6.2 ordinal() mong manh — đừng lưu DB/JSON theo ordinal

Thứ tự khai báo quyết định ordinal() (0, 1, 2...). Đổi thứ tự hoặc chèn hằng mới vào giữa làm mọi giá trị dịch chuyển, dữ liệu cũ trỏ sai trạng thái:

enum OrderStatusV1 { PENDING, PAID, SHIPPED }

enum OrderStatusV2 { PENDING, REFUNDED, PAID, SHIPPED }

void main() {
    int luuDb = OrderStatusV1.PAID.ordinal();          // 1
    OrderStatusV2 docLai = OrderStatusV2.values()[luuDb];
    IO.println("luu DB: " + luuDb);                    // 1
    IO.println("doc lai thanh: " + docLai);            // REFUNDED - sai!
    IO.println("dung name: " + OrderStatusV2.valueOf("PAID"));   // PAID - dung
}
luu DB: 1
doc lai thanh: REFUNDED
dung name: PAID
Bản ghi cũ lưu 1 được đọc lại thành REFUNDED thay vì PAID. Quy tắc production: lưu name() (chuỗi tên hằng) hoặc tốt hơn là một code riêng ổn định kèm fromCode() — vì đổi tên hằng cũng làm name() vỡ. 6.4 Thứ tự khởi tạo — hằng enum tạo trước static field

Các hằng enum được khởi tạo trước mọi static field khác của enum, nên constructor (chạy trong lúc tạo hằng) chưa thấy static field. Đọc trực tiếp static field trong constructor còn bị compiler chặn:

7. Nested classes — bốn loại Junior+

Java cho phép khai báo class/interface/enum/record bên trong một class khác — gọi chung là nested type. Mục đích: gom những kiểu chỉ có nghĩa trong ngữ cảnh của class ngoài (outer), che giấu implementation, và giữ code gần nhau. Effective Java khuyên: chỉ dùng nested class khi nó thực sự phục vụ outer; nếu không, tách ra top-level class cho dễ đọc.

8. Static nested vs inner class Hay hỏi phỏng vấn

Static nested class

Đúng như tên gọi: nó là class nằm trong namespace của outer nhưng không gắn với instance nào của outer. Tạo thẳng bằng new Outer.Inner():

public class Outer {
    private static String loiNhan = "static nested doc duoc field private static cua Outer";
    private String ten = "outer instance";

    static class Inner {
        void in() {
            IO.println(loiNhan);
        }
    }

    public static void main() {
        Outer.Inner inner = new Outer.Inner();
        inner.in();
    }
}
static nested doc duoc field private static cua Outer

Inner ở trên giống hệt một top-level class, chỉ khác là được "đóng gói" trong Outer. Nó đọc được field private static của outer, nhưng không đọc được ten (field instance) vì không có instance outer nào cả.

Inner class (non-static)

Bỏ chữ static đi, mọi instance của Inner sẽ gắn chặt với một instance của Outer — Java giữ ngầm một reference tới outer đó. Cú pháp tạo đặc biệt: outer.new Inner().

public class Outer {
    private String ten = "Outer";
    private int dem = 0;

    class Inner {
        private String ten = "Inner";

        void in() {
            IO.println("this.ten       = " + this.ten);
            IO.println("Outer.this.ten = " + Outer.this.ten);
            dem++;
        }
    }

    public static void main() {
        Outer outer = new Outer();
        Outer.Inner inner = outer.new Inner();
        inner.in();
        inner.in();
        IO.println("dem = " + outer.dem);
    }
}
this.ten       = Inner
Outer.this.ten = Outer
this.ten       = Inner
Outer.this.ten = Outer
dem = 2

Hai chi tiết đắt giá: Outer.this cho phép phân biệt khi tên field bị trùng, và dem++ chứng minh inner sửa được state private của chính outer instance mà nó gắn vào — hai lần gọi cùng một inner thì dem = 2.

Vì inner giữ ngầm reference tới outer, nếu bạn đưa inner vào nơi sống lâu (static collection, cache, listener, thread pool), outer cũng không bao giờ được thu gom rác dù code không còn dùng outer nữa:

static final List<Outer.Inner> CACHE = new ArrayList<>();

static void nho(Outer outer) {
    CACHE.add(outer.new Inner());   // Inner giu ngam reference toi outer
}

// outer khong con bien nao tro toi, nhung CACHE con Inner
// -> ca Inner lan Outer deu nam lai trong bo nho mai mai

Cách tránh rất đơn giản: nếu inner không cần state instance của outer, hãy khai báo nó là static nested. Đây cũng là lý do các Builder, DTO, cache key trong production hầu hết là static nested. (Từ Java 16, inner class được phép khai báo static member — trước đó là lỗi compile — nhưng điều đó không làm nó thôi giữ outer reference.)

Builder — ứng dụng kinh điển của static nested

Builder pattern (đã giới thiệu ở Methods — mục 4) chuẩn mực nhất là một static nested class, vì builder không cần instance của class đích cho tới lúc build():

public class OrderDemo {
    static final class Order {
        private final String ma;
        private final long tongTien;

        private Order(Builder b) {
            this.ma = b.ma;
            this.tongTien = b.tongTien;
        }

        static class Builder {
            private String ma = "DH-000";
            private long tongTien;

            Builder ma(String ma) {
                this.ma = ma;
                return this;
            }

            Builder tongTien(long tongTien) {
                this.tongTien = tongTien;
                return this;
            }

            Order build() {
                return new Order(this);
            }
        }

        @Override
        public String toString() {
            return "Order[ma=" + ma + ", tongTien=" + tongTien + "]";
        }
    }

    public static void main() {
        Order o = new Order.Builder().ma("DH-042").tongTien(250_000).build();
        IO.println(o);
    }
}
Order[ma=DH-042, tongTien=250000]

Chú ý constructor Order là private — chỉ Builder (cùng nest) gọi được. Nhờ đó object Order bất biến và luôn được tạo hợp lệ.

9. Local & anonymous class Junior+

Local class — class trong method

Local class khai báo ngay trong thân method, chỉ tồn tại trong phạm vi đó. Nó hữu ích khi logic phụ cần một type có tên, nhiều method, nhưng không đáng tách ra ngoài:

void main() {
    String tienTo = "DH-";
    int so = 42;

    class Inner {
        void in() {
            IO.println(tienTo + so);
        }
    }

    Inner inner = new Inner();
    inner.in();
}
DH-42

Local class capture biến local xung quanh, nhưng chỉ khi biến đó effectively final — tức không được gán lại sau lần khởi tạo đầu tiên. Cố tình gán lại sẽ lỗi compile:

CaptureErr.java:6: error: local variables referenced from an inner class must be final or effectively final
            IO.println(so);
                       ^
1 error

Lý do: biến local sống trên stack và biến mất khi method return, còn object của local class có thể sống lâu hơn — nên Java copy giá trị vào object và cấm thay đổi để tránh hai nguồn sự thật. Muốn "biến đổi được" thì dùng một field của object (như int[], AtomicInteger, hoặc field instance).

Anonymous class — implementation không tên

Anonymous class vừa khai báo vừa tạo object trong một biểu thức new. Ví dụ trước thời lambda, đây là cách duy nhất truyền hành vi:

void main() {
    Runnable chao = new Runnable() {
        @Override
        public void run() {
            IO.println("Chay trong anonymous class");
        }
    };
    chao.run();

    int lan = 2;
    Runnable dem = new Runnable() {
        @Override
        public void run() {
            IO.println("lan = " + lan);   // capture bien effectively final
        }
    };
    dem.run();
}

Ví dụ thực chiến hơn — sắp xếp danh sách mà không cần tạo class riêng:

void main() {
    List<String> ds = new ArrayList<>(List.of("Java", "JS", "TypeScript", "C"));
    ds.sort(new Comparator<String>() {
        @Override
        public int compare(String a, String b) {
            return a.length() - b.length();
        }
    });
    IO.println(ds);
}
[C, JS, Java, TypeScript]

Từ Java 8, hầu hết anonymous class cho functional interface (Runnable, Comparator, Callable...) được thay bằng lambda gọn hơn hẳn — sẽ học ở 3.6 Lambda & functional interfaces. Anonymous class vẫn còn chỗ đứng khi:

  • Cần extends một abstract class (lambda chỉ dùng cho interface).
  • Interface/class có nhiều hơn một method cần implement.
  • Cần state riêng hoặc instance initializer cho object dùng một lần. Anonymous class không có constructor, nhưng có khối khởi tạo { ... }.
  • Logic dài hơn vài dòng — dù vậy khi đó thường local class có tên sẽ dễ đọc hơn.
Anonymous và local class nằm trong method của instance cũng giữ ngầm outer reference y như inner class — bẫy memory leak ở mục 8 áp dụng cho cả ba loại.

10. Sealed classes & interfaces Hay hỏi phỏng vấn

Bình thường, bất kỳ ai cũng extends/implements được class/interface của bạn (trừ khi final). Sealed (Java 17, JEP 409) là lựa chọn ở giữa: bạn mở kế thừa có kiểm soát, liệt kê chính xác ai được phép là subtype qua permits.

sealed [class|interface] Shape permits Circle, Rectangle, Square { }

Ví dụ với cây kế thừa Shape quen thuộc từ Polymorphism — mục 4, giờ đây đóng khung thành đúng ba subtype:

sealed interface Shape permits Circle, Rectangle, Square {
}

record Circle(double r) implements Shape {
}

record Rectangle(double w, double h) implements Shape {
}

record Square(double canh) implements Shape {
}

double dienTich(Shape s) {
    return switch (s) {
        case Circle(double r) -> Math.PI * r * r;
        case Rectangle(double w, double h) -> w * h;
        case Square(double c) -> c * c;
    };
}

void main() {
    Shape[] shapes = { new Circle(1), new Rectangle(2, 3), new Square(4) };
    for (Shape s : shapes) {
        IO.println(s + " -> " + dienTich(s));
    }
}
Circle[r=1.0] -> 3.141592653589793
Rectangle[w=2.0, h=3.0] -> 6.0
Square[canh=4.0] -> 16.0

Luật của sealed

  • Mỗi subtype trực tiếp phải khai báo là final (đóng nhánh), sealed (đóng tiếp có danh sách), hoặc non-sealed (mở lại tự do). Thiếu modifier là lỗi compile — xem errblock bên dưới.
  • record và enum mặc định final, nên chỉ cần implements Shape là hợp lệ (như ví dụ trên).
  • Sealed class/interface phải có ít nhất một subtype.
  • Subtype phải nằm cùng module (named module) hoặc cùng package (unnamed module) với class cha.
  • Nếu tất cả subtype nằm chung một compilation unit (một file), có thể bỏ qua permits — compiler tự suy ra từ các subtype cùng file. Các ví dụ trong trang này vẫn ghi permits tường minh cho rõ nghĩa.
  • sealed không có nghĩa là abstract: sealed class không abstract vẫn new được, chỉ là hạn chế kế thừa.
SealedSubErr.java:4: error: sealed, non-sealed or final modifiers expected

non-sealed — mở lại một nhánh

Đôi khi bạn muốn đóng 95% cây kế thừa nhưng chừa một nhánh cho phép mở rộng tự do (plugin, extension point). non-sealed làm đúng việc đó:

sealed interface Shape permits Circle, Polygon {
}

record Circle(double r) implements Shape {
}

non-sealed class Polygon implements Shape {
}

class Square extends Polygon {
}

void main() {
    Shape s = new Square();
    IO.println("Square la Polygon: " + (s instanceof Polygon));
}
Square la Polygon: true

non-sealed chỉ hợp lệ khi class đó là subtype trực tiếp của một sealed type. Đặt ở top-level hoặc ở class không có cha sealed sẽ lỗi:

Tên class trong thông báo có tiền tố NonSealedErr. vì file là compact source file: class top-level khai báo thêm trở thành member của implicit class cùng tên file — đúng cơ chế đã thấy với DayDemo$Day$2 ở mục 4.

So sánh ba thái cực: final (không ai extends), sealed (chỉ danh sách cho phép), mở hoàn toàn (mặc định). Sealed class đã được nhắc ở Inheritance — mục 13 và sealed interface ở Abstract vs Interface — mục 12; phần dưới đây khai thác lợi ích lớn nhất của nó.

11. Switch exhaustive & pattern matching Hay hỏi phỏng vấn

Java 21 hoàn thiện pattern matching for switch (JEP 441) cùng record pattern (JEP 440). Ba thứ mới đáng nhớ: case theo kiểu, bóc tách record, và guard when:

sealed interface Shape permits Circle, Rectangle, Square {
}

record Circle(double r) implements Shape {
}

record Rectangle(double w, double h) implements Shape {
}

record Square(double canh) implements Shape {
}

String moTa(Shape s) {
    return switch (s) {
        case Circle c when c.r() > 10 -> "hinh tron lon";
        case Circle c -> "hinh tron nho";
        case Rectangle r -> "hinh chu nhat";
        case Square q -> "hinh vuong";
    };
}

void main() {
    IO.println(moTa(new Circle(20)));
    IO.println(moTa(new Circle(2)));
    IO.println(moTa(new Square(4)));
}
hinh tron lon
hinh tron nho
hinh vuong

Vì Shape là sealed, compiler biết chính xác ba subtype và switch expression trên không cần default. Quên một nhánh là lỗi compile ngay khi build, chạy thật với JDK 25:

    return switch (s) {
           ^
1 error

Đó chính là giá trị lớn nhất của sealed: thêm subtype mới, toàn bộ switch liên quan lập tức báo lỗi để bạn cập nhật, thay vì âm thầm rơi vào default và sai logic lúc chạy. Nếu bỏ sealed, switch buộc phải có default và mất hoàn toàn sự bảo vệ này.

case null (Java 21) xử lý luôn giá trị null thay vì ném NPE:

enum Color { RED, GREEN, BLUE }

String ten(Color c) {
    return switch (c) {
        case null -> "khong co mau";
        case RED -> "do";
        case GREEN -> "xanh la";
        case BLUE -> "xanh duong";
    };
}

void main() {
    IO.println(ten(null));
    IO.println(ten(Color.GREEN));
}
khong co mau
xanh la
Enum cũng là "sealed" theo nghĩa tập hằng cố định, nên switch expression trên enum cũng exhaustive và không cần default khi liệt kê đủ hằng (xem mục 6). Pattern matching switch còn áp dụng cho bất kỳ reference type nào — xem thêm Polymorphism — mục 4.

Hai cú pháp nâng cao nên biết: record pattern lồng nhau bóc tách luôn component con, và nhãn ghép case null, default gom null chung với phần còn lại:

record Point(int x, int y) {}
record Circle(Point tam, double banKinh) {}

String moTa(Circle c) {
    return switch (c) {
        case Circle(Point(int x, int y), double r) -> "tam (" + x + ", " + y + "), r=" + r;
    };
}

enum Color { RED, GREEN, BLUE }

String ten(Color c) {
    return switch (c) {
        case RED -> "do";
        case GREEN -> "xanh la";
        case BLUE -> "xanh duong";
        case null, default -> "khac";

}

void main() {

14. Interview Q&A Hay hỏi phỏng vấn

Cơ bản

Câu 1. Enum là gì? Khác gì so với dùng hằng int/String?
Enum là kiểu dữ liệu mô tả một tập giá trị hữu hạn có tên; mỗi hằng là một object singleton của enum class, được JVM tạo một lần khi class nạp. So với hằng int/String: enum type-safe (truyền sai giá trị là lỗi compile, không cần kiểm tra runtime), có namespace riêng, in ra tên có nghĩa, gắn được field/method, và dùng được trong switch/EnumMap/EnumSet. String constant vẫn nhận giá trị lạ; int constant có thể trùng giá trị mà compiler không biết.
Câu 2. Mỗi hằng enum có phải singleton không? So sánh enum bằng == được không?
Đúng — mỗi hằng được JVM khởi tạo đúng một lần cho mỗi classloader, và không có cách nào tạo thêm instance (constructor là private, không thể gọi new, reflection cũng bị chặn). Vì là singleton, == so identity chính là so đúng hằng: an toàn, nhanh, không lo NPE từ equals. equals của enum cũng chỉ là so identity, nên hai cách tương đương — nhưng == là chuẩn mực.
Câu 3. Enum có field, constructor, method không? Constructor có modifier gì?
Có đầy đủ như class thường: field (nên private final), constructor, method, static method. Constructor của enum ngầm là private; viết public/protected bị lỗi "modifier public not allowed here". Mỗi hằng truyền tham số trong ngoặc ngay sau tên, và constructor chạy một lần cho mỗi hằng theo thứ tự khai báo.
Câu 4. Enum extends class khác được không? implements interface thì sao?
Không extends được class nào — enum đã extends java.lang.Enum ngầm, và Java chỉ cho đơn kế thừa. Bù lại, enum implements bao nhiêu interface cũng được, kể cả functional interface như IntBinaryOperator, và có thể implement ở cấp enum hoặc override riêng từng hằng.
Câu 5. values(), valueOf(), name(), ordinal() khác nhau thế nào?
values() trả mảng tất cả hằng theo thứ tự khai báo — và tạo mảng mới mỗi lần gọi. valueOf(String) trả hằng theo tên (khớp chính xác), không có thì ném IllegalArgumentException, còn valueOf(null) ném NullPointerException. name() là tên hằng đúng như khai báo, final. ordinal() là vị trí 0-based, cũng final. compareTo so theo ordinal; getDeclaringClass() trả enum class thật (khác getClass() với hằng có thân riêng).
Câu 6. Vì sao không nên lưu ordinal() vào database?
Vì ordinal() phụ thuộc thứ tự khai báo. Chỉ cần chèn một hằng mới vào giữa, xoá một hằng, hoặc sắp xếp lại danh sách, mọi ordinal phía sau dịch chuyển — dữ liệu cũ đọc lên sẽ trỏ sai trạng thái. An toàn hơn: lưu name() (nhưng đổi tên hằng vẫn phá), hoặc tốt nhất là lưu một code nghiệp vụ ổn định kèm static factory fromCode() như mục 3.
Câu 7. Switch trên enum có cần default không? Biến enum là null thì sao?
Switch expression chỉ cần default nếu bạn không liệt kê đủ hằng — liệt kê đủ thì không cần (enum exhaustive), và thiếu hằng là lỗi compile. Switch statement truyền thống không bắt buộc đủ nhánh. Biến đang là null mà switch sẽ ném NullPointerException, không rơi vào default; Java 21 có case null để xử lý tường minh.
Câu 8. Enum override toString() được không? name() thì sao?
toString() override thoải mái để in nhãn thân thiện, ví dụ "Da thanh toan". Còn name() là final, không override được, và valueOf dùng đúng name(). Vì vậy đừng parse toString() để lưu trữ hoặc tra ngược — hãy dùng name() hoặc code riêng.

Junior+

Câu 9. Abstract method trong enum hoạt động thế nào?
Enum khai báo abstract method, mỗi hằng có thân riêng thì override method đó. Cơ chế: hằng có thân riêng trở thành một anonymous subclass của enum — Day.SATURDAY.getClass() in ra dạng DayDemo$Day$2, khác class enum gốc. Hằng không có thân riêng dùng chung class enum. Vì vậy đừng so sánh kiểu bằng getClass(); hãy so hằng bằng ==.
Câu 10. Enum singleton idiom là gì? Vì sao được coi là cách viết singleton an toàn nhất?
Chỉ cần một hằng INSTANCE: enum AppConfig { INSTANCE; ... }, truy cập AppConfig.INSTANCE. An toàn với đa luồng (JVM khởi tạo class một lần, có cơ chế đồng bộ sẵn), với serialization (đọc ra vẫn đúng instance, không tạo bản sao), và với reflection (constructor enum không accessible). Không cần viết double-checked locking hay holder class. Pattern này được Effective Java khuyến nghị; xem thêm 2.8 SOLID & design patterns.
Câu 11. EnumMap/EnumSet hiệu quả hơn HashMap/HashSet ở đâu? Khi nào dùng?
Vì enum có tập hằng cố định và ordinal() liên tục, EnumMap bên trong dùng mảng index theo ordinal thay vì bảng băm, còn EnumSet dùng bit vector (enum ≤ 64 hằng chỉ cần một long). Kết quả: tra cứu O(1) không băm, tiết kiệm bộ nhớ, duyệt theo đúng thứ tự khai báo. Dùng khi key/element là enum: đếm trạng thái, mapping message, bộ cờ quyền. Lưu ý cả hai đều không nhận null.
Câu 12. Static nested class và inner class khác nhau ở đâu?
Static nested không giữ reference tới outer, tạo bằng new Outer.Inner() — giống top-level class chỉ khác namespace, truy cập được static member của outer. Inner class gắn với một instance outer cụ thể, tạo bằng outer.new Inner(), có Outer.this, truy cập được mọi member instance (kể cả private) của outer — đổi lại giữ outer sống theo. Quy tắc thực dụng: mặc định static nested, chỉ dùng inner khi cần state của outer instance.
Câu 13. Inner class gây memory leak như thế nào?
Mỗi instance inner giữ ngầm một reference tới outer instance. Nếu inner được lưu ở nơi sống lâu — static collection, cache, event listener, thread — thì outer cũng bị giữ theo và không bao giờ được GC, dù code không còn dùng outer nữa. Anonymous/local class trong ngữ cảnh instance cũng vậy. Cách tránh: dùng static nested nếu không cần outer state; hủy đăng ký listener đúng lúc; hoặc dùng WeakReference khi buộc phải giữ.
Câu 14. Nested class có truy cập private của outer không? Compiler làm gì?
Có — cả hai chiều, kể cả field/method private, vì chúng cùng một "nest". Trước Java 11, compiler phải sinh các synthetic accessor method để vượt qua rào cản truy cập; từ Java 11 (JEP 181, nest-based access control), bytecode khai báo NestHost/NestMembers và các class cùng nest truy cập private trực tiếp, không cần accessor trung gian.
Câu 15. Khi nào dùng anonymous class thay vì lambda?
Lambda chỉ thay được cho functional interface (đúng một abstract method). Còn anonymous class khi: cần extends một abstract class; interface có nhiều abstract method; cần state riêng/instance initializer; hoặc cần override thêm method khác ngoài method chính. Ngược lại, nếu logic chỉ một vài dòng và là functional interface, lambda gọn và rõ hơn; nếu logic dài, local class có tên sẽ dễ đọc hơn cả hai.
Câu 16. Local class capture biến xung quanh theo quy tắc nào?
Chỉ capture được biến local (và parameter) final hoặc effectively final — nghĩa là không gán lại sau lần khởi tạo đầu tiên. Gán lại sẽ lỗi compile "local variables referenced from an inner class must be final or effectively final". Lý do: biến stack có thể biến mất khi method return, nên Java copy giá trị vào object; cấm thay đổi để tránh hai nguồn dữ liệu lệch nhau. Cần mutable state thì dùng field của object, AtomicInteger, hoặc mảng một phần tử.
Câu 17. Khi nào nên dùng nested class thay vì top-level class?
Khi class chỉ có nghĩa trong ngữ cảnh outer: Builder của outer, Node của cây, Entry của Map, Iterator, cache key nội bộ. Lợi ích: đóng gói (có thể private), giữ code liên quan gần nhau, giảm namespace, và với static nested thì không tốn gì so với top-level. Nếu class vẫn hữu ích độc lập hoặc file bắt đầu rối, hãy tách ra top-level — Effective Java: nested chỉ để phục vụ outer.

Nâng cao

Câu 18. Sealed class/interface là gì? Subtype phải khai báo gì?
Sealed (Java 17, JEP 409) giới hạn tập subtype đúng bằng danh sách permits. Mỗi subtype trực tiếp phải là final, sealed, hoặc non-sealed; record/enum mặc định final nên chỉ cần implements. Có thể bỏ permits nếu mọi subtype nằm cùng file, nhưng subtype phải cùng module (named module) hoặc cùng package (unnamed module) với cha. Sealed không nhất thiết abstract.
Câu 19. Sealed + switch exhaustive lợi gì khi thêm subtype mới?
Compiler biết chính xác tất cả subtype nên switch expression không cần default, và khi bạn thêm subtype mới mà quên nhánh tương ứng, build fail ngay với "the switch expression does not cover all possible input values". Đây là refactor an toàn: không thể quên xử lý case mới. Nếu không sealed, buộc phải có default — và mọi case mới sẽ âm thầm rơi vào default, sinh bug runtime khó phát hiện.
Câu 20. non-sealed dùng khi nào? Đặt sai chỗ thì sao?
non-sealed mở lại một nhánh của cây sealed cho phép kế thừa tự do — hữu ích cho extension point/plugin. Nó chỉ hợp lệ khi class đó là subtype trực tiếp của một sealed type. Đặt ở top-level hoặc class không có cha sealed sẽ lỗi "non-sealed modifier not allowed here (class ... does not have any sealed supertypes)". Lưu ý: nhánh non-sealed làm switch trên sealed gốc mất tính exhaustive — cần default hoặc xử lý theo kiểu cụ thể.
Câu 21. Pattern matching for switch (Java 21) có gì mới?
Ba thứ chính: type pattern case Circle c -> (vừa kiểm tra kiểu vừa gán biến), record pattern case Circle(double r) -> (bóc tách component), và guard when (case Circle c when c.r() > 10 ->) để lọc thêm điều kiện. Ngoài ra có case null. Kết hợp với sealed, switch trở thành exhaustive không cần default. Đã finalized ở Java 21 (JEP 441 cùng record patterns JEP 440).
Câu 22. Khi nào chọn enum, khi nào chọn sealed class/interface, khi nào final class?
Enum khi các giá trị là hằng thuần nhất, không mang bộ dữ liệu riêng khác nhau (trạng thái, ngày, phương thức thanh toán). Sealed interface + records khi mỗi "case" mang dữ liệu khác nhau (Circle bán kính, Rectangle hai cạnh) — union type có kiểm soát. Final class khi chỉ cần chặn kế thừa, không cần biết danh sách subtype. Ba công cụ kết hợp được: enum có thể là subtype của sealed interface, record có thể thay hằng có hành vi riêng.

    IO.println(Day.SATURDAY.isWeekend());
}
In ra false rồi true. Mỗi hằng override theo thân riêng: MONDAY là anonymous subclass trả false, SATURDAY trả true.
Bài 4 — so sánh enum 
enum Color { RED, GREEN }

void main() {
    Color a = Color.valueOf("RED");
    Color b = Color.RED;
    IO.println(a == b);
    IO.println(a.equals(b));
    IO.println(a.hashCode() == b.hashCode());
}
In ra true, true, true. valueOf("RED") trả đúng instance singleton Color.RED, nên cả ==, equals lẫn hashCode đều khớp.
Bài 5 — EnumMap & EnumSet 
enum Day { MON, FRI, SAT }

void main() {
    EnumMap<Day, Integer> dem = new EnumMap<>(Day.class);
    dem.put(Day.SAT, 2);
    dem.put(Day.MON, 1);
    IO.println(dem);
    IO.println(EnumSet.of(Day.SAT, Day.MON));
}
In ra {MON=1, SAT=2} rồi [MON, SAT]. Dù put SAT trước MON, cả hai collection duyệt theo thứ tự khai báo hằng (MON trước FRI, SAT).
Bài 6 — static nested class 
public class Outer {
    static class Inner {
        String ten() {
            return "static nested";
        }
    }

    public static void main() {
        IO.println(new Outer.Inner().ten());
    }
}
In ra static nested. Static nested tạo được trực tiếp bằng new Outer.Inner() mà không cần instance Outer nào.
Bài 7 — inner class và Outer.this 
public class Outer {
    private String ten = "Outer";

    class Inner {
        String moTa() {
            return Outer.this.ten + " -> Inner";
        }
    }

    public static void main() {
        Outer.Inner i = new Outer().new Inner();
        IO.println(i.moTa());
    }
}
In ra Outer -> Inner. Inner đọc được field private instance của outer qua Outer.this; object inner được tạo từ instance outer bằng cú pháp new Outer().new Inner().
Bài 8 — anonymous comparator 
void main() {
    List<String> ds = new ArrayList<>(List.of("Java", "JS", "TypeScript", "C"));
    ds.sort(new Comparator<String>() {
        @Override
        public int compare(String a, String b) {
            return b.length() - a.length();
        }
    });
    IO.println(ds);
}
In ra [TypeScript, Java, JS, C] — sắp xếp giảm dần theo độ dài. Anonymous class implement Comparator truyền thẳng vào sort; từ Java 8 đoạn này có thể viết gọn bằng lambda (a, b) -> b.length() - a.length() (học ở 3.6).
Bài 9 — local class 
void main() {
    int a = 3;

    class Inner {
        int binhPhuong() {
            return a * a;
        }
    }

    IO.println(new Inner().binhPhuong());
}
In ra 9. Local class khai báo trong method, capture được a (effectively final) và dùng ngay trong phạm vi method.
Bài 10 — sealed + switch exhaustive 
sealed interface Shape permits Circle, Square {
}

record Circle(double r) implements Shape {
}

record Square(double c) implements Shape {
}

void main() {
    Shape s = new Square(3);
    IO.println(switch (s) {
        case Circle c -> "tron";
        case Square q -> "vuong";
    });
}
In ra vuong. Switch expression trên sealed Shape bao đủ hai subtype nên không cần default; object thật là Square nên khớp nhánh thứ hai.
Bài 11 — thiếu nhánh switch 
sealed interface Shape permits Circle, Rectangle {
}

record Circle(double r) implements Shape {
}

record Rectangle(double w, double h) implements Shape {
}

double moTa(Shape s) {
    return switch (s) {
        case Circle c -> 1.0;
    };
}

void main() {
    IO.println(moTa(new Circle(1)));
}
Không compile. Lỗi thật khi chạy javac: 
ErrMissingCase.java:11: error: the switch expression does not cover all possible input values
    return switch (s) {
           ^
1 error
Phải thêm nhánh case Rectangle r (không được ỷ lại vào default nếu muốn giữ sự bảo vệ của sealed).
Bài 12 — ordinal khi thêm hằng vào giữa 
enum OrderStatus { PENDING, PAID, SHIPPED }

enum OrderStatus2 { PENDING, REFUNDED, PAID, SHIPPED }

void main() {
    IO.println(OrderStatus.PAID.ordinal());
    IO.println(OrderStatus2.PAID.ordinal());
}
In ra 1 rồi 2. Chỉ cần chèn REFUNDED vào giữa, ordinal của PAID đã dịch từ 1 lên 2 — minh hoạ sống động vì sao không lưu ordinal vào DB.
Bài 13 — sửa mảng values() 
enum Color { RED, GREEN }

void main() {
    Color[] mang = Color.values();
    mang[0] = Color.GREEN;
    IO.println(mang[0]);
    IO.println(Color.values()[0]);
}
In ra GREEN rồi RED. Bạn sửa được mảng clone ở lần gọi đầu, nhưng values() lần sau trả mảng mới tinh từ enum — hằng enum là bất biến, không sửa được qua mảng.

Checklist tự đánh giá trước phỏng vấn

  • Giải thích được enum là gì và vì sao thay được hằng int/String.
  • Khẳng định chắc chắn: mỗi hằng enum là singleton, so sánh bằng ==.
  • Khai báo thành thạo enum có field/constructor/method mà không cần tra cứu.
  • Nhớ constructor enum ngầm private và giải thích vì sao.
  • Phân biệt values()/valueOf()/name()/ordinal() và bẫy values() tạo mảng mới.
  • Giải thích được vì sao không lưu ordinal vào DB, nêu cách thay thế.
  • Viết được enum có abstract method với hành vi riêng từng hằng và biết nó là anonymous subclass.
  • Kể tên ít nhất hai trường hợp dùng EnumMap/EnumSet thay HashMap/HashSet.
  • Phân biệt 4 loại nested class và chọn đúng loại cho tình huống cụ thể.
  • Viết được hai câu lệnh tạo static nested và inner class, giải thích Outer.this.
  • Giải thích được inner class gây memory leak thế nào và cách tránh.
  • Nêu được khi nào anonymous class còn hợp lý hơn lambda.
  • Viết được sealed hierarchy + switch exhaustive không default.
  • Nêu luật subtype của sealed (final/sealed/non-sealed) và lỗi khi vi phạm.
  • Giải thích vì sao thêm subtype mới làm compiler báo lỗi ở mọi switch.
