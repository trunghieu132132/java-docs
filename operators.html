2. Short-circuit && / || Hay hỏi phỏng vấn Production

Hai toán tử logic chạy theo luật short-circuit (đoản mạch): Java đánh giá từ trái sang phải và dừng ngay khi biết kết quả.

  • A && B — nếu A là false, B không được chạy (vì chắc chắn kết quả false).
  • A || B — nếu A là true, B không được chạy (vì chắc chắn kết quả true).

Điều này quan trọng vì nhánh phải có thể có side effect (gọi hàm, tăng biến, truy cập object). Ví dụ chạy thật:

public class ShortCircuitDemo {
    static int calls = 0;

    static boolean check(boolean ketQua) {
        calls++;
        return ketQua;
    }

    public static void main() {
        calls = 0;
        boolean a = check(false) && check(true);
        IO.println("false && true : " + a + ", so lan goi = " + calls);
        // false && true : false, so lan goi = 1   - check(true) KHONG chay

        calls = 0;
        boolean b = check(true) || check(false);
        IO.println("true || false : " + b + ", so lan goi = " + calls);
        // true || false : true, so lan goi = 1    - check(false) KHONG chay

        calls = 0;
        boolean c = check(false) & check(true);
        IO.println("false &  true : " + c + ", so lan goi = " + calls);
        // false &  true : false, so lan goi = 2   - & luon chay ca hai

        calls = 0;
        boolean d = check(true) | check(false);
        IO.println("true  | false : " + d + ", so lan goi = " + calls);
        // true  | false : true, so lan goi = 2    - | luon chay ca hai
    }
}

Ứng dụng quan trọng nhất: chống NullPointerException

Idiom quen thuộc s != null && s.length() > 0 hoạt động được nhờ short-circuit: nhánh phải chỉ chạy khi nhánh trái đã xác nhận không null.

String s = null;
IO.println("s != null && s.length() > 0 : " + (s != null && s.length() > 0));
// s != null && s.length() > 0 : false    - an toan, khong NPE

try {
    IO.println(s != null & s.length() > 0);
} catch (NullPointerException e) {
    IO.println("s != null &  s.length() > 0 : NullPointerException");
}
// s != null &  s.length() > 0 : NullPointerException   - & chay ca s.length()
Thứ tự điều kiện có ý nghĩa: đặt check null/rẻ tiền ở bên trái. user != null && user.isActive() an toàn; đảo thành user.isActive() && user != null là NPE. Tuyệt đối không dùng & cho điều kiện có thể null — nó vẫn nổ như thường.

& và | trên boolean — không short-circuit

& (bitwise AND) và | (bitwise OR) khi áp vào hai boolean cũng cho kết quả logic, nhưng luôn đánh giá cả hai nhánh. Chúng hữu ích khi cả hai vế đều là phép tính không có side effect (ví dụ gộp cờ), còn cho điều kiện thông thường hãy dùng &&/||.

Góc Node.js: JS có truthy/falsy nên viết được if (count) hay if (name). Java bắt buộc điều kiện là boolean — số, chuỗi, object đều không tự chuyển. Và trong JS, a && b trả về một trong hai toán hạng, còn Java luôn trả boolean. Pattern JS value || defaultValue khi sang Java dùng ternary hoặc Objects.requireNonNullElse.

Thử compile đoạn kiểu JS:

3. Toán tử so sánh Hay hỏi phỏng vấn

Nhóm so sánh gồm ==, !=, <, >, <=, >= — tất cả trả về boolean.

  • Với primitive, == so giá trị: 5 == 5 là true.
  • Với reference, == so địa chỉ (có phải cùng một object không). Muốn so nội dung phải dùng .equals() — chi tiết và cache wrapper đã có ở Biến trong Java — mục 12 và mục 14.
  • Java không có ===. == của Java đã là so sánh chặt, không ép kiểu như == của JS.

Không so sánh float/double bằng ==

Số thực IEEE 754 có sai số biểu diễn, nên so bằng == gần như luôn sai. Ví dụ chạy thật:

double a = 0.1 + 0.2;
double b = 0.3;
IO.println("0.1 + 0.2        = " + a);              // 0.30000000000000004
IO.println("a == b           = " + (a == b));       // false
IO.println("|a - b|          = " + Math.abs(a - b)); // 5.551115123125783E-17

double eps = 1e-9;
IO.println("|a - b| < 1e-9   = " + (Math.abs(a - b) < eps));  // true

IO.println("Double.compare a,b = " + Double.compare(a, b));   // 1
IO.println("Double.compare a,a = " + Double.compare(a, a));   // 0

IO.println("NaN == NaN       = " + (Double.NaN == Double.NaN));            // false
IO.println("compare NaN,NaN  = " + Double.compare(Double.NaN, Double.NaN)); // 0
IO.println("0.0 == -0.0      = " + (0.0 == -0.0));                          // true
IO.println("Float.compare 1,1 = " + Float.compare(1.0f, 1.0f));             // 0

IO.println("BigDecimal 0.1+0.2 = " + new BigDecimal("0.1").add(new BigDecimal("0.2")));  // 0.3
IO.println("compareTo 0.3      = " + new BigDecimal("0.1").add(new BigDecimal("0.2")).compareTo(new BigDecimal("0.3")));  // 0
  • Epsilon — coi hai số là bằng nhau nếu Math.abs(a - b) < 1e-9 (chọn epsilon theo độ chính xác nghiệp vụ).
  • Double.compare / Float.compare — so sánh chuẩn, xử lý đúng NaN và -0.0; trả về -1, 0, 1 như compareTo.
  • NaN — mọi phép == với NaN đều false, kể cả NaN == NaN; Double.compare(NaN, NaN) == 0.
  • Tiền tệ — đừng dùng float/double từ đầu; dùng BigDecimal (xem Biến trong Java — mục 13).

4. Tăng/giảm ++ và --

Đây là toán tử một ngôi, có hai dạng cho mỗi phép:

DạngTênThứ tựTrả về
++iPrefix incrementTăng trướcGiá trị mới
i++Postfix incrementTăng sauGiá trị cũ
--iPrefix decrementGiảm trướcGiá trị mới
i--Postfix decrementGiảm sauGiá trị cũ
 
int i = 5;
IO.println("i ban dau   : " + i);        // i ban dau   : 5
IO.println("i++ tra ve  : " + (i++));    // i++ tra ve  : 5   - tra gia tri cu
IO.println("i sau i++   : " + i);        // i sau i++   : 6
IO.println("++i tra ve  : " + (++i));    // ++i tra ve  : 7   - tra gia tri moi
IO.println("i sau ++i   : " + i);        // i sau ++i   : 7

int j = 1;
int k = j++ + ++j;
IO.println("j++ + ++j   : " + k + " (j = " + j + ")");
// j++ + ++j   : 4 (j = 3)
// j++ tra 1 (j thanh 2); ++j tang j thanh 3 va tra 3 -> 1 + 3 = 4

int x = 5;
int y = x++ + x++;
IO.println("x++ + x++   : " + y + " (x = " + x + ")");
// x++ + x++   : 11 (x = 7)
// 5 + 6 = 11, vi ve trai tra 5 (x=6) roi ve phai tra 6 (x=7)

int z = ++x + x++;
IO.println("++x + x++   : " + z + " (x = " + x + ")");
// ++x + x++   : 16 (x = 9)
// x dang la 7: ++x tra 8 (x=8), x++ tra 8 (x=9) -> 16

Biểu thức j++ + ++j là câu hỏi phỏng vấn kinh điển. Cách giải: Java đánh giá trái sang phải; mỗi toán tử postfix trả giá trị cũ rồi mới tăng; prefix tăng rồi trả giá trị mới.

Bẫy thường gặp

int m = 5;
m = m++;
IO.println("m = m++     : " + m);           // m = m++     : 5   - khong tang!

byte by = Byte.MAX_VALUE;                  // 127
by++;
IO.println("byte 127 ++ : " + by);         // byte 127 ++ : -128  - tran quay vong

int p = 0;
int q = p++ + ++p + p--;
IO.println("p++ + ++p + p--: " + q + " (p = " + p + ")");
// p++ + ++p + p--: 4 (p = 1)   - 0 + 2 + 2 = 4
  • m = m++ là no-op: m++ trả 5 (m thành 6), rồi phép gán ghi đè lại 5. Không bao giờ viết kiểu này.
  • by++ trên byte hợp lệ (có ngầm ép kiểu) nhưng tràn thì quay vòng âm thầm — xem Biến trong Java — mục 9.
  • Quy tắc production: không nhồi ++/-- vào biểu thức. Mỗi dòng một phép tăng, code dễ đọc và không phụ thuộc thứ tự đánh giá.

5. Bitwise & shift Nhận biết

Nhóm toán tử bit làm việc trực tiếp trên từng bit của số nguyên. Trong code nghiệp vụ ít gặp, nhưng rất hay dùng cho cờ (bit flags), quyền, giao thức, hash và tối ưu.

|OR0b1100 | 0b10100b1110 = 14
^XOR0b1100 ^ 0b10100b0110 = 6
~Đảo bit (complement)~0b1100-13
<<Dịch trái0b1100 << 124
>>Dịch phải giữ dấu0b1100 >> 16

int b = 0b1010;
IO.println("a & b    = " + (a & b));   // 8
IO.println("a | b    = " + (a | b));   // 14
IO.println("a ^ b    = " + (a ^ b));   // 6
IO.println("~a       = " + (~a));      // -13
IO.println("~0       = " + (~0));      // -1
IO.println("a << 1   = " + (a << 1));  // 24
IO.println("a >> 1   = " + (a >> 1));  // 6

IO.println("1 << 31  = " + (1 << 31));    // -2147483648   - bit dau thanh 1
IO.println("1 << 32  = " + (1 << 32));    // 1            - 32 & 0b11111 = 0
IO.println("1 << 33  = " + (1 << 33));    // 2            - 33 & 0b11111 = 1
IO.println("1L << 63 = " + (1L << 63));   // -9223372036854775808
IO.println("1L << 64 = " + (1L << 64));   // 1            - long dung 6 bit cuoi

int neg = -8;
IO.println("-8 >> 1  = " + (neg >> 1));   // -4           - giu dau am
IO.println("-8 >>> 1 = " + (neg >>> 1));  // 2147483644   - lap 0
IO.println("-8 >>> 28= " + (neg >>> 28)); // 15
Bẫy shift count: Java chỉ dùng 5 bit thấp của số dịch với int (vì cần 5 bit để biểu diễn 0..31) và 6 bit thấp với long. Nên 1 << 32 = 1 << 0 = 1, 1 << 33 = 1 << 1 = 2 — không phải lỗi compile, chỉ là kết quả "lạ". Và 1 << 31 là số âm vì bit 31 là bit dấu.

Cờ bit với enum (bit flags)

Mỗi quyền là một bit; gộp nhiều quyền bằng |, kiểm tra bằng &, bật bằng |=, tắt bằng &= ~:

import java.util.EnumSet;

public class BitwiseShiftDemo {
    enum Permission {
        READ(1 << 0),
        WRITE(1 << 1),
        DELETE(1 << 2);

        static final int ALL = READ.bit | WRITE.bit | DELETE.bit;

        final int bit;

        Permission(int bit) {
            this.bit = bit;
        }
    }

    static boolean has(int mask, Permission p) {
        return (mask & p.bit) != 0;
    }

    static int validate(int mask) {
        if ((mask & ~Permission.ALL) != 0) {
            throw new IllegalArgumentException("Bit la: " + mask);
        }
        return mask;
    }

    public static void main() {
        IO.println("READ.bit    = " + Permission.READ.bit);     // 1
        IO.println("WRITE.bit   = " + Permission.WRITE.bit);    // 2
        IO.println("DELETE.bit  = " + Permission.DELETE.bit);   // 4

        int mask = Permission.READ.bit | Permission.WRITE.bit;
        IO.println("mask R|W    = " + mask + " (binary " + Integer.toBinaryString(mask) + ")");
        // mask R|W    = 3 (binary 11)

        IO.println("has READ    = " + has(mask, Permission.READ));    // true
        IO.println("has DELETE  = " + has(mask, Permission.DELETE));  // false

        mask |= Permission.DELETE.bit;
        IO.println("sau |= DEL  = " + mask);    // 7
        mask &= ~Permission.WRITE.bit;
        IO.println("sau &= ~W   = " + mask);    // 5
        mask ^= Permission.READ.bit;
        IO.println("sau ^= R    = " + mask);    // 4

        IO.println("validate(7) = " + validate(7));   // 7
        try {
            validate(8);
        } catch (IllegalArgumentException e) {
            IO.println("validate(8) : " + e.getMessage());   // Bit la: 8
        }

        IO.println("EnumSet     = " + EnumSet.of(Permission.READ, Permission.WRITE));
        // EnumSet     = [READ, WRITE]
    }
}
Production: khi làm việc với tập nhỏ các cờ, EnumSet<Permission> là lựa chọn hiện đại — type-safe, đọc rõ nghĩa hơn bitmask, vẫn tối ưu. Chỉ dùng bitmask khi giao tiếp với DB/protocol đã quy định sẵn dạng số, hoặc cần nhồi cờ vào một cột int/long.

Ứng dụng: hash code

String.hashCode() dùng công thức h = 31 * h + c, và 31 * h tương đương (h << 5) - h — trình biên dịch/JIT hay dùng dạng dịch bit này. Chạy thử:

String s = "java";
int h = 0;
for (char c : s.toCharArray()) {
    h = 31 * h + c;
}
IO.println("hash tinh tay = " + h);          // 3254818
IO.println("s.hashCode()  = " + s.hashCode()); // 3254818
IO.println("(h << 5) - h  = " + ((h << 5) - h)); // 100899358  = 31 * 3254818
Góc Node.js: JS cũng có đủ bộ toán tử bit này (kể cả >>>), nhưng mọi phép bit trong JS đều ép về số nguyên 32-bit rồi trả về number — không có bitwise 64-bit. Java làm việc đúng theo width của int (32-bit) hoặc long (64-bit), nên 1L << 40 mới có ý nghĩa.

IO.println("1 | 2 & 2      = " + (1 | 2 & 2));      // 3     - & truoc |
IO.println("(1 | 2) & 2    = " + ((1 | 2) & 2));    // 2
IO.println("10 - 4 - 3     = " + (10 - 4 - 3));     // 3     - cung cap, trai sang phai
IO.println("2 + 3 > 4 ? 10 : 20         = " + (2 + 3 > 4 ? 10 : 20));  // 10
Bẫy precedence với bitwise: == ưu tiên cao hơn &, nên 1 & 3 == 3 được hiểu là 1 & (3 == 3) — vế phải là boolean trong khi vế trái là int, compile fail ngay:
ErrBitwise.java:3: error: bad operand types for binary operator '&'
        int result = 1 & 3 == 3;
                       ^
  first type:  int
  second type: boolean
1 error

Lời khuyên thực dụng: đừng học thuộc bảng precedence. Khi trộn nhiều nhóm toán tử, cứ thêm ngoặc cho rõ ý — người đọc code không phải tự suy luận, và compiler cũng không phàn nàn.

    IO.println("toIntExact   : " + e.getMessage());          // integer overflow
}
  • Math.pow luôn trả double — đây là bẫy phổ biến. Math.pow(2, 10) in ra 1024.0; nếu cần int phải ép. Và (int) Math.pow(2, 31) bị kẹp về Integer.MAX_VALUE chứ không tràn — xem luật ép double → int ở Data Types — mục 4.
  • Math.round làm tròn theo công thức floor(x + 0.5), nên -2.5 → -2 (không phải -3). Nếu nghiệp vụ yêu cầu "làm tròn xa số 0" (-2.5 → -3), dùng BigDecimal.setScale(..., RoundingMode.UP/HALF_UP).
  • Math.abs(Integer.MIN_VALUE) vẫn âm vì -2147483648 không có biểu diễn dương trong 32-bit. Đừng dùng Math.abs làm "chuẩn hóa" ID/timestamp.
  • Math.floorMod — modulo của Java giữ dấu số bị chia (-1 % 7 = -1), còn floorMod cho kết quả cùng dấu với số chia — số chia dương thì luôn không âm (floorMod(-1, 7) = 6). Rất hữu ích cho chỉ số vòng (circular index) — xem mục 11.
  • Math.addExact, multiplyExact, toIntExact ném ArithmeticException (message integer overflow) thay vì tràn âm thầm — xem Biến trong Java — mục 9.

9. Ternary ? :

Toán tử ba ngôi là cách viết if/else trả về giá trị trên một dòng:

int score = 75;
String grade = score >= 80 ? "A" : score >= 60 ? "B" : "C";
IO.println("grade        = " + grade);        // B

int a = 5;
int b = 3;
IO.println("max          = " + (a > b ? a : b));   // 5

String nhan = a == b ? "bang" : a > b ? "lon hon" : "nho hon";
IO.println("nhan         = " + nhan);          // lon hon

boolean flag = true;
IO.println("int/double   = " + (flag ? 1 : 2.0));   // 1.0

int safe = flag ? 0 : Integer.parseInt("x");
IO.println("chi cham 1 nhanh = " + safe);     // 0

try {
    int risky = flag ? Integer.parseInt("x") : 0;
    IO.println(risky);
} catch (NumberFormatException e) {
    IO.println("nhanh duoc chon moi chay: NumberFormatException");
}
  • Lazy: chỉ nhánh được chọn mới được đánh giá — nên flag ? 0 : Integer.parseInt("x") chạy an toàn khi flag true; đảo lại là nổ NumberFormatException.
  • Kiểu kết quả: hai nhánh được đưa về cùng một kiểu theo numeric promotion — flag ? 1 : 2.0 trả 1.0. Bẫy unboxing khi một nhánh là wrapper null đã phân tích ở Data Types — mục 7.
  • Đọc hiểu: lồng 2-3 tầng vẫn ổn, sâu hơn thì nên chuyển sang if/else hoặc switch (và switch expression ở Control Flow). Đừng viết ternary mà mỗi nhánh lại là một ternary khác khó đọc.
  • Không lạm dụng: ternary dùng để lấy giá trị, đừng dùng để chạy side effect kiểu flag ? doA() : doB(); — dùng if/else cho rõ.
Góc Node.js: JS cũng có ?: nhưng nhận điều kiện truthy; Java bắt buộc boolean. JS có thêm optional chaining ?. và nullish coalescing ?? — Java không có; thay thế bằng Optional, Objects.requireNonNullElse hoặc ternary.

10. Assignment & compound

Các toán tử gán: =, +=, -=, *=, /=, %=, &=, ^=, |=, <<=, >>=, >>>=.

Phần quan trọng nhất của compound assignment — ngầm ép kiểu về kiểu biến bên trái — đã có ở Data Types — mục 6, trang này không nhắc lại. Ở đây chỉ bổ sung hai điểm về bản thân phép gán:

1. Phép gán là biểu thức, trả về giá trị vừa gán — nên gán chuỗi được, chạy từ phải sang trái:

int a, b, c;
a = b = c = 5;
IO.println(a + " " + b + " " + c);   // 5 5 5

int d = 10;
int e = d = 3;
IO.println("d = " + d + ", e = " + e);   // d = 3, e = 3

2. Compound assignment kết hợp với ++ trong chỉ số mảng — chạy được nhưng là code smell, hãy tách dòng:

int[] arr = {1, 2, 3};
int i = 1;
arr[i++] += 10;
IO.println("arr[i++] += 10 -> " + java.util.Arrays.toString(arr) + ", i = " + i);
// arr[i++] += 10 -> [1, 12, 3], i = 2
Đừng bao giờ gán trong điều kiện kiểu if (user = findUser()) — Java sẽ báo lỗi vì user không phải boolean (khác C), nhưng nếu cả hai đều boolean thì lại compile và gây bug. Cần so sánh thì dùng ==.

11.2 Production patterns

Chỉ số vòng với Math.floorMod — khi index có thể âm (xoay vòng danh sách, carousel, chia ca trực):

static String ngayTrongTuan(int index) {
    String[] days = {"Thu 2", "Thu 3", "Thu 4", "Thu 5", "Thu 6", "Thu 7", "Chu nhat"};
    return days[Math.floorMod(index, days.length)];
}

IO.println("index -1  -> " + ngayTrongTuan(-1));    // index -1  -> Chu nhat
IO.println("index 0   -> " + ngayTrongTuan(0));     // index 0   -> Thu 2
IO.println("index 7   -> " + ngayTrongTuan(7));     // index 7   -> Thu 2
IO.println("index 100 -> " + ngayTrongTuan(100));   // index 100 -> Thu 4

Validate bitmask — chặn dữ liệu rác từ DB/API trước khi tin tưởng các bit:

static final int READ = 1 << 0;
static final int WRITE = 1 << 1;
static final int DELETE = 1 << 2;
static final int ALL = READ | WRITE | DELETE;

static int validateMask(int mask) {
    if ((mask & ~ALL) != 0) {
        throw new IllegalArgumentException("Mask chua bit la: " + mask);
    }
    return mask;
}

IO.println("validateMask(5) = " + validateMask(5));   // validateMask(5) = 5
try {
    validateMask(8);
} catch (IllegalArgumentException e) {
    IO.println("validateMask(8) : " + e.getMessage());   // Mask chua bit la: 8
}

Tính tiền với BigDecimal — toán tử số học trên tiền luôn đi qua BigDecimal, không bao giờ dùng double hay Math.round cho số tiền. Chi tiết scale/RoundingMode ở Biến trong Java — mục 13:

BigDecimal price = new BigDecimal("199000");
BigDecimal vat = price.multiply(new BigDecimal("0.10"));
IO.println("VAT 10% chua lam tron : " + vat);                              // 19900.00
IO.println("VAT 10% lam tron      : " + vat.setScale(0, RoundingMode.HALF_UP)); // 19900

int quantity = 3;
BigDecimal total = price.multiply(BigDecimal.valueOf(quantity));
IO.println("Tong 3 san pham       : " + total);                          // 597000

Thứ tự điều kiện null-safe — pattern đọc dữ liệu lồng nhau, luôn để check null/rẻ nhất bên trái:

import java.math.BigDecimal;
import java.util.Objects;

public class NullSafeConditionDemo {
    record Customer(String name, boolean active) {}

    record Order(Customer customer, BigDecimal total) {}

    public static void main() {
        Order order = new Order(new Customer("An", true), new BigDecimal("199000"));
        if (order != null
                && order.customer() != null
                && order.customer().active()
                && order.total().signum() > 0) {
            IO.println("Don hang hop le: " + order.total());
        }
        // Don hang hop le: 199000

        String inputName = null;
        String name = Objects.requireNonNullElse(inputName, "Khach le");
        IO.println("name = " + name);
        // name = Khach le   - thay cho JS: inputName || "Khach le"
    }
}

12. Interview Q&A Hay hỏi phỏng vấn

Cơ bản

Câu 1. && và & khác nhau thế nào khi dùng với boolean?
&& short-circuit: nếu vế trái false thì vế phải không chạy. & luôn đánh giá cả hai vế rồi mới AND. Vì vậy s != null & s.length() > 0 ném NPE còn s != null && s.length() > 0 thì không.
Câu 2. || và | khác nhau thế nào?
Tương tự: || dừng khi vế trái true (vế phải không chạy); | luôn chạy cả hai vế. Trên boolean cả hai đều cho kết quả logic; trên số nguyên | là OR từng bit.
Câu 3. Short-circuit giúp tránh NullPointerException như thế nào? Cho ví dụ.
Đặt check null bên trái: if (s != null && s.length() > 0). Vì s.length() chỉ chạy khi s != null, không bao giờ gọi method trên null. Cùng idiom với user != null && user.isActive() hay list != null && !list.isEmpty().
Câu 4. Java có truthy/falsy như JavaScript không? if (1) có chạy không?
Không. Điều kiện trong Java bắt buộc là boolean; if (1) hay if (name) là compile error "incompatible types: int cannot be converted to boolean". In JS a && b trả về một toán hạng, còn Java luôn trả boolean.
Câu 5. == và equals() khác nhau thế nào?
Với primitive, == so giá trị. Với reference, == so địa chỉ (identity); equals() so nội dung nếu class override (String, wrapper, record...). Java không có ===; == của Java giống === của JS hơn là ==.
Câu 6. Vì sao không nên so sánh double bằng ==? Cách đúng?
IEEE 754 có sai số biểu diễn: 0.1 + 0.2 == 0.3 là false (0.30000000000000004). Cách đúng: so với epsilon Math.abs(a - b) < 1e-9, hoặc Double.compare(a, b) == 0 (xử lý đúng NaN, -0.0). Với tiền tệ dùng BigDecimal.compareTo.
Câu 7. ++i và i++ khác nhau thế nào?
++i tăng trước rồi trả giá trị mới; i++ trả giá trị cũ rồi mới tăng. int i = 5; IO.println(i++); in 5 rồi i thành 6; IO.println(++i); in 7.
Câu 8. int j = 1; int k = j++ + ++j; — k bằng bao nhiêu, j bằng bao nhiêu?
k = 4, j = 3. Đánh giá trái sang phải: j++ trả 1 (j thành 2); ++j tăng j lên 3 và trả 3; tổng 1 + 3 = 4.
Câu 9. 1 << 32 bằng bao nhiêu? Vì sao?
Bằng 1. Java chỉ dùng 5 bit thấp của số dịch với int: 32 = 0b100000, lấy 5 bit thấp là 0, nên thành 1 << 0. Tương tự 1 << 33 = 1 << 1 = 2; với long dùng 6 bit thấp nên 1L << 64 = 1.
Câu 10. >> và >>> khác nhau thế nào?
>> dịch phải giữ dấu (bit dấu được kéo theo, số âm vẫn âm): -8 >> 1 = -4. >>> dịch phải lấp 0 — với int, dịch từ 1 bit trở lên luôn cho kết quả không âm: -8 >>> 1 = 2147483644.

Nâng cao (Junior+)

Câu 11. Vì sao 1 << 31 là số âm?
Bit cao nhất (bit 31) là bit dấu trong biểu diễn bù hai của int. 1 << 31 đặt bit 31 lên 1 nên giá trị là Integer.MIN_VALUE = -2147483648. Với long, 1L << 63 cho Long.MIN_VALUE.
Câu 12. Bitmask (bit flags) là gì? Vì sao production hay dùng EnumSet thay thế?
Bitmask là dùng từng bit để biểu diễn nhiều cờ trong một số: READ = 1 << 0, WRITE = 1 << 1; gộp bằng |, kiểm tra bằng (mask & flag) != 0. Nhược điểm: không type-safe, khó đọc, phải validate bit lạ. EnumSet type-safe, có tên rõ nghĩa, vẫn tối ưu — dùng khi không bị ràng buộc bởi DB/protocol dạng số.
Câu 13. Math.abs(Integer.MIN_VALUE) bằng bao nhiêu? Vì sao?
Vẫn là -2147483648. Số dương lớn nhất biểu diễn được là 2147483647, nên giá trị đối của MIN_VALUE không tồn tại trong 32-bit; Java trả về chính nó (tràn). Đừng dùng Math.abs để chuẩn hóa giá trị có thể chạm biên.
Câu 14. -1 % 7 và Math.floorMod(-1, 7) khác nhau thế nào? Khi nào cần floorMod?
-1 % 7 = -1 (Java giữ dấu số bị chia); Math.floorMod(-1, 7) = 6 (kết quả cùng dấu với số chia; số chia dương thì không âm). Cần floorMod khi index có thể âm: xoay vòng mảng, carousel, chọn ca theo modulo — dùng % sẽ ra index âm và ném ArrayIndexOutOfBoundsException.
Câu 15. Bẫy của Math.pow là gì?
Luôn trả double, kể cả khi đầu vào là số nguyên: Math.pow(2, 10) = 1024.0. Cần int phải ép, và ép giá trị vượt khoảng sẽ bị kẹp chứ không tràn: (int) Math.pow(2, 31) = Integer.MAX_VALUE. Với lũy thừa nguyên chính xác nên nhân dần với multiplyExact hoặc dùng 1L << n.
Câu 16. Math.round(-2.5) bằng bao nhiêu? Vì sao? Khi nào cần khác?
Bằng -2. Math.round làm theo công thức floor(x + 0.5): -2.5 + 0.5 = -2.0 → -2. Nếu nghiệp vụ yêu cầu làm tròn "xa số 0" (-2.5 → -3), dùng BigDecimal.setScale(0, RoundingMode.UP).
Câu 17. Random và SecureRandom khác nhau thế nào? Khi nào dùng cái nào?
Random là PRNG thông thường, dãy số xác định nếu biết seed — phù hợp game, mô phỏng, test (có seed để tái lập). SecureRandom lấy entropy từ hệ điều hành, không đoán được — dùng cho token, OTP, session ID, mật khẩu tạm. Tuyệt đối không dùng Random cho mục đích bảo mật.
Câu 18. ThreadLocalRandom khác Math.random() ở đâu? Khi nào dùng?
Math.random() dùng chung một Random static — nhiều thread gọi cùng lúc sẽ tranh chấp. ThreadLocalRandom.current() cho mỗi thread một instance riêng, không contention, nhanh hơn trong code đa luồng. Đây là mức nhận biết; code một luồng dùng Random/Math.random() là đủ.
Câu 19. Vì sao String.hashCode() dùng 31? 31 * h liên quan gì tới shift?
Công thức là h = 31 * h + c; 31 là số nguyên tố lẻ, nhân nhanh và phân bố hash tốt. Về bit, 31 * h == (h << 5) - h — JIT thường tối ưu theo dạng dịch bit này. Đó là ví dụ thực tế nhất của toán tử shift trong code thường ngày.
Câu 20. 1 << 2 + 3 bằng bao nhiêu? Vì sao? Lời khuyên?
Bằng 32 vì + ưu tiên cao hơn <<: 1 << (2 + 3) = 1 << 5 = 32. Tương tự, == ưu tiên hơn & nên 1 & 3 == 3 là compile error (1 & (3 == 3)). Lời khuyên: không học thuộc precedence, hãy thêm ngoặc khi trộn nhóm toán tử.

IO.println(score >= 80 ? "A" : score >= 60 ? "B" : "C");
In ra B. Ternary lồng chạy từ trái sang phải: 75 không đủ 80, rơi vào nhánh sau và đủ 60.
Bài 11 
int m = 5;
m = m++;
IO.println(m);
In ra 5. m++ trả 5 rồi m thành 6, nhưng phép gán ghi đè lại 5 — no-op.
Bài 12 
int READ = 1;
int WRITE = 2;
int mask = READ | WRITE;
IO.println((mask & WRITE) != 0);
IO.println((mask & 4) != 0);
In ra true rồi false. Mask = 3 có bit WRITE (2) nhưng không có bit 4 (DELETE).

Checklist tự đánh giá trước phỏng vấn

  • Giải thích short-circuit và tự viết ví dụ tránh NPE.
  • Phân biệt &&/&, ||/| và nói được khi nào side effect bị bỏ qua.
  • Giải thích vì sao Java không có truthy/falsy, không có ===.
  • So sánh double bằng epsilon hoặc Double.compare thành thạo.
  • Tính nhẩm được j++ + ++j và giải thích từng bước.
  • Giải thích 1 << 32 = 1, 1 << 31 âm, >> vs >>>.
  • Viết được helper bitmask: kiểm tra, bật, tắt, validate bit lạ; biết EnumSet thay thế.
  • Nêu 5 method Math hay dùng và bẫy của từng cái.
  • Biết floorMod cho index vòng và addExact chống tràn.
  • Phân biệt Random / SecureRandom / ThreadLocalRandom và nêu đúng use case.
