2. Cú pháp khai báo

[modifier] type variableName = value;

Ba thành phần, theo đúng thứ tự:

  • type — kiểu dữ liệu (int, String, BigDecimal...). Bắt buộc.
  • variableName — tên bạn tự đặt, theo quy tắc camelCase. Bắt buộc.
  • = value — giá trị ban đầu. Có thể bỏ, gán sau cũng được.
public class VariablesDemo {
    public static void main() {
        // Khai báo và gán giá trị ngay
        String ten = "Nguyen Van An";
        int tuoi = 25;
        double diemTrungBinh = 8.75;
        char xepLoai = 'A';
        boolean dangLamViec = true;

        IO.println(ten);            // Nguyen Van An
        IO.println(tuoi);           // 25
        IO.println(diemTrungBinh);  // 8.75
        IO.println(xepLoai);        // A
        IO.println(dangLamViec);    // true
    }
}
Ví dụ dùng IO.println(...) — cách viết gọn của JDK 25 (JEP 512), tương đương System.out.println(...) mà bạn sẽ thấy trong đề phỏng vấn và tài liệu cũ.

Quy tắc đặt tên (Identifiers)

  • Được dùng: chữ cái, chữ số, dấu gạch dưới _ và $. Không bắt đầu bằng chữ số.
  • Không được trùng từ khóa: class, int, static, final, new...
  • Phân biệt hoa thường: age và Age là hai biến khác nhau.
  • Quy ước: biến camelCase (userId), hằng số UPPER_SNAKE_CASE (MAX_SIZE), class PascalCase (UserService).
  • Tên phải có nghĩa: retryCount tốt hơn x; tránh tmp, data1, data2.

Giá trị mặc định: field có, biến local không

Field (biến khai báo trong class) được Java gán mặc định. Còn biến local không có giá trị mặc định — phải gán trước khi dùng, nếu không compiler chặn ngay. Đây là câu hỏi phỏng vấn rất hay gặp.

public class DefaultsShadow {
    static int soNguyen;
    static boolean co;
    static String ten;
    static Integer diem;

    static int value = 100;

    public static void main() {
        IO.println("int field    : " + soNguyen); // 0
        IO.println("boolean field: " + co);       // false
        IO.println("String field : " + ten);      // null
        IO.println("Integer field: " + diem);     // null

        IO.println("field value  : " + value);    // 100
        int value = 5;                            // local che (shadow) field
        IO.println("local value  : " + value);    // 5
        {
            int inside = 10;
            IO.println("trong block  : " + inside); // 10
        }
    }
}
error: variable x might not have been initialized
        IO.println(x);
                   ^

Lỗi trên xảy ra với đoạn int x; IO.println(x); — biến local chưa gán thì không được dùng. JS in ra undefined, Java chặn từ lúc compile.

4. Literals — cách viết giá trị

Literal là giá trị viết thẳng trong code. Java có nhiều cách viết mà lập trình viên production dùng hằng ngày:

public class LiteralsDemo {
    public static void main() {
        int million = 1_000_000;      // gach duoi cho de doc
        int hex = 0xFF;               // he 16 -> 255
        int binary = 0b1010;          // he 2  -> 10
        int octal = 017;              // he 8  -> 15 (co bay, xem ben duoi)
        long big = 9_999_999_999L;    // hau to L cho long
        float f = 5.99f;              // hau to f cho float
        double sci = 1.5e3;           // ky phap khoa hoc -> 1500.0
        char newline = '\n';          // ky tu escape
        char unicode = '\u0041';      // ma Unicode -> A
        String quote = "Noi dung \"trong nhay kep\"";

        IO.println(million);   // 1000000
        IO.println(hex);       // 255
        IO.println(binary);    // 10
        IO.println(octal);     // 15
        IO.println(big);       // 9999999999
        IO.println(f);         // 5.99
        IO.println(sci);       // 1500.0
        IO.println((int) newline); // 10
        IO.println(unicode);   // A
        IO.println(quote);     // Noi dung "trong nhay kep"
    }
}
Bẫy thực tập: số bắt đầu bằng 0 là hệ 8 (octal). int i = 010; in ra 8, không phải 10. Đừng bao giờ viết số 0 ở đầu trừ khi cố ý. Và hậu tố long nên viết hoa L — chữ l thường nhìn như số 1: 10l trông giống 101.

5. Gán, ghi đè, khai báo trước

Biến có thể khai báo trước rồi gán giá trị sau. Khác JavaScript, Java bắt buộc phải có giá trị trước khi dùng — không có undefined như JS.

int myNum;          // khai báo, chưa có giá trị
myNum = 15;         // gán giá trị lần đầu
IO.println(myNum);  // 15

myNum = 20;         // ghi đè giá trị cũ
IO.println(myNum);  // 20

Lần gán sau không cần ghi lại kiểu, vì kiểu đã cố định từ lúc khai báo. Và bạn không thể gán String vào biến int — compiler chặn ngay (khác JS vốn cho phép đổi kiểu tùy ý).

6. Scope & vòng đời biến

Trong class có ba loại biến, đi làm gặp hằng ngày:

  • Biến local — khai báo trong method hoặc block { }, chỉ sống trong phạm vi đó. Hết method/block là biến "chết".
  • Field (instance variable) — khai báo trong class, mỗi object có một bản riêng, sống theo object.
  • Static field — dùng chung cho mọi object của class, sống theo class. Kèm final thành hằng số.
public class User {
    private String name;                          // field: mỗi object có bản riêng
    private static int userCount = 0;             // static: dùng chung mọi object
    public static final int MAX_NAME_LEN = 100;   // hằng số

    User(String name) {
        this.name = name;
        userCount++;
    }

    void rename(String newName) {
        String trimmed = newName.trim();          // local: chỉ sống trong method này
        this.name = trimmed;
    }
}
Shadowing là khi biến local trùng tên field — local sẽ "che" field (như value trong ví dụ mục 3). Muốn chỉ field thì dùng this. (this.value). Đừng đặt tên local trùng field nếu không cần, dễ gây nhầm.

7. Stack vs Heap & pass-by-value Hay hỏi phỏng vấn Junior+

Hiểu chỗ này thì mọi câu hỏi "biến lưu ở đâu", "truyền tham số thế nào" đều giải được. JVM chia bộ nhớ thành hai vùng chính:

  • Stack — mỗi thread có stack riêng. Chứa biến local primitive (int x = 5 lưu thẳng số 5) và địa chỉ của object. Tổ chức theo kiểu LIFO như chồng đĩa; nhanh, nhỏ; hết thì StackOverflowError.
  • Heap — dùng chung cho mọi thread. Chứa object thật (new ArrayList<>(), String...). Lớn; được Garbage Collector dọn dẹp; hết thì OutOfMemoryError.
int x = 5;                       // so 5 nam ngay tren stack
String s = "java";               // bien s (dia chi) tren stack -> object tren heap
Integer n = 1000;                // dia chi tren stack -> object Integer tren heap

// Hinh dung:
// STACK                        HEAP
// [ x = 5 ]
// [ s = #1A2 ]  ------------>  { String "java" }
// [ n = #3F4 ]  ------------>  { Integer 1000 }

Java luôn pass-by-value

Câu hỏi phỏng vấn kinh điển: "Java truyền tham số theo giá trị hay tham chiếu?" — Trả lời: luôn theo giá trị. Nhưng với object, giá trị được truyền là bản sao của địa chỉ, nên bạn sửa được nội dung object, mà gán lại reference bên trong method thì bên ngoài không đổi.

public class PassByValueDemo {
    static void tang(int x) {
        x++;                      // chi sua ban sao
    }

    static void themMon(List<String> mon) {
        mon.add("Toan");          // sua noi dung object -> ben ngoai thay doi
    }

    static void doiList(List<String> mon) {
        mon = new ArrayList<>();  // gan lai reference -> ben ngoai KHONG doi
        mon.add("Ly");
    }

    public static void main() {
        int a = 5;
        tang(a);
        IO.println("sau tang(a)      : " + a);      // 5

        List<String> mon = new ArrayList<>(List.of("Van"));
        themMon(mon);
        IO.println("sau themMon(mon) : " + mon);    // [Van, Toan]

        doiList(mon);
        IO.println("sau doiList(mon) : " + mon);    // [Van, Toan]
    }
}

8. Chuyển kiểu & numeric promotion Hay hỏi phỏng vấn

Có hai chiều chuyển kiểu:

ChiềuTự động?Ví dụGhi chú
Widening (nhỏ → lớn) Có byte → short → int → long → float → double An toàn với số nguyên; riêng int → float và long → double có thể mất chữ số
Narrowing (lớn → nhỏ) Không, phải ép (type) int i = (int) 3.9; → 3 Mất dữ liệu nên Java bắt tự chịu trách nhiệm
Bẫy phỏng vấn: widening nhìn chung an toàn, nhưng int → float và long → double có thể mất chữ số: float chỉ giữ 24 bit phần định trị, double 53 bit, nên (float) 16_777_217 in ra 1.6777216E7 (hụt 1 đơn vị). Cần chính xác tuyệt đối với số nguyên lớn thì đừng đi qua float/double.
int i = 'a';                     // char -> int tu dong
IO.println("int i = 'a'      -> " + i);      // 97

char c = 97;                     // hang so vua khoang -> duoc
IO.println("char c = 97      -> " + c);      // a

IO.println("'a' + 1          -> " + ('a' + 1));           // 98
IO.println("(char)('a' + 1)  -> " + (char) ('a' + 1));   // b

byte b = 10;
b += 5;                          // compound assignment: ngam ep kieu
IO.println("byte b += 5      -> " + b);      // 15

IO.println("5 / 2            -> " + (5 / 2));      // 2   (chia nguyen!)
IO.println("5 / 2.0          -> " + (5 / 2.0));    // 2.5
IO.println("5 % 2            -> " + (5 % 2));      // 1
IO.println("-5 % 2           -> " + (-5 % 2));     // -1

double d = 5 / 2;
IO.println("double d = 5 / 2 -> " + d);      // 2.0  (khong phai 2.5!)

Numeric promotion — tại sao 'a' + 1 là int?

Khi tính toán, byte, short, char đều được nâng lên int trước rồi mới tính. Nên 'a' + 1 cho ra 98 (int), muốn ra ký tự phải ép ngược (char).

Bẫy compound assignment (+=, -=, *=...)

b += 5; chạy được, nhưng b = b + 5; thì không. Vì += có ngầm ép kiểu — tương đương b = (byte) (b + 5):

b = b + 5;
      ^
error: incompatible types: possible lossy conversion from int to byte

9. Tràn số Hay hỏi phỏng vấn Production

Số nguyên vượt quá giới hạn sẽ quay vòng (wraparound) chứ không báo lỗi — nguồn bug cực kỳ khó tìm:

int max = Integer.MAX_VALUE;                  // 2147483647
IO.println("max          : " + max);          // 2147483647
IO.println("max + 1      : " + (max + 1));    // -2147483648

IO.println("1e6 * 1e6    : " + (1_000_000 * 1_000_000)); // -727379968

long x = 1 * 1000 * 1000 * 1000 * 5;          // int * int -> tran
IO.println("int * int    : " + x);             // 705032704

long y = 1L * 1000 * 1000 * 1000 * 5;         // 1L keo ca bieu thuc sang long
IO.println("1L bat dau   : " + y);             // 5000000000

try {
    IO.println(Math.addExact(max, 1));
} catch (ArithmeticException e) {
    IO.println("addExact nem : " + e.getMessage()); // integer overflow
}
  • 1000 * 60 * 60 * 24 * 365 (số milli giây một năm) là bug kinh điển — tràn thành 1471228928, phải viết 1000L * ... để ra 31536000000.
  • Math.addExact, multiplyExact... ném ArithmeticException thay vì tràn âm thầm — dùng khi cần chắc chắn đúng.
  • Đây là lý do production luôn dùng long cho ID và timestamp.

10. final chuyên sâu Hay hỏi phỏng vấn

final khoá việc gán lại biến, tương đương const bên JS. Nhưng có 3 điều phải nhớ:

1. final chỉ khoá biến, không khoá nội dung object:

final List<String> list = new ArrayList<>();
list.add("java");                          // OK - noi dung doi duoc
list.add("spring");
IO.println("final List add duoc: " + list); // [java, spring]

final int[] arr = {1, 2, 3};
arr[0] = 99;                               // OK - phan tu doi duoc
IO.println("final int[] sua duoc: " + Arrays.toString(arr)); // [99, 2, 3]

// list = new ArrayList<>();  // LOI compile:
// cannot assign a value to final variable list

2. Blank final — final không gán ngay, gán một lần trong constructor. Mỗi object một giá trị nhưng bất biến sau đó:

public class Connection {
    private final String url;      // blank final

    Connection(String url) {
        this.url = url;            // gan dung 1 lan
    }
}

3. Effectively final — biến local gán đúng một lần (không gán lại) thì được coi như final, dùng được trong lambda. Gán lại là lỗi:

int count = 0;
count++;
Runnable r = () -> IO.println(count);
                    ^
error: local variables referenced from a lambda expression must be final or effectively final
Java không có từ khóa const (nó là từ khóa dự trữ, không dùng được) — dân JS mới sang hay viết nhầm. Muốn bất biến thật sự, dùng immutable object và List.copyOf() / List.of().

11. var (Java 10+) Production

var để compiler tự suy kiểu cho biến local — giống let nhìn bề ngoài, nhưng vẫn là static typing: kiểu được chốt lúc compile, không đổi được như JS.

var name = "An";                        // String
var count = 10;                         // int
var list = new ArrayList<String>();     // ArrayList<String>
list.add("java");

IO.println(name.getClass().getSimpleName());  // String
IO.println(count);                            // 10
IO.println(list);                             // [java]

// var field = 10;   // LOI: 'var' is not allowed here (chi dung cho local)
// var x;            // LOI: cannot infer type for local variable x
//                   //      (cannot use 'var' on variable without initializer)
  • Chỉ dùng cho biến local (trong method). Không dùng cho field, tham số, kiểu trả về.
  • Phải có giá trị khởi tạo ngay — vì compiler cần suy kiểu.
  • Production dùng nhiều vì đỡ lặp tên kiểu dài: var mapper = new ObjectMapper();.

12. Wrapper & autoboxing chuyên sâu Hay hỏi phỏng vấn Junior+

Mỗi primitive có bản object hoá: int → Integer, long → Long, double → Double... Cần wrapper vì collections chỉ chứa object, và vì wrapper cho phép null (cột DB nullable).

Autoboxing là tự động bọc primitive thành wrapper, unboxing là ngược lại:

Integer a = 127, b = 127;
Integer c = 128, d = 128;
IO.println("127 == 127 : " + (a == b));   // true  - trung cache
IO.println("128 == 128 : " + (c == d));   // false - ngoai cache!
IO.println("128 equals : " + c.equals(d)); // true

Integer e = null;
try {
    int f = e;                            // unbox null -> NPE
} catch (NullPointerException ex) {
    IO.println("unbox null -> NullPointerException");
}

List<Integer> nums = new ArrayList<>();
nums.add(1000);                           // autobox
int first = nums.get(0);                  // unbox
IO.println("autobox/unbox: " + first);    // 1000
  • Cache: Integer.valueOf() cache sẵn -128 đến 127. Trong khoảng này hai biến cùng giá trị trỏ cùng object (== true); ngoài khoảng tạo object mới (== false). Vì vậy luôn so sánh wrapper bằng .equals().
  • NPE ngầm: unbox null nổ ngay tại dòng đó — lỗi rất hay gặp khi đọc cột DB nullable.
  • Hiệu năng: autobox trong vòng lặp lớn tạo hàng triệu object rác. Ví dụ xấu: Long sum = 0L; for (...) sum += i; — mỗi vòng lặp box/unbox. Dùng primitive long sum.
  • Quy tắc chọn: cần null hoặc vào collection → wrapper; còn lại → primitive.

13. BigDecimal chuyên sâu Hay hỏi phỏng vấn Production

Không bao giờ dùng double/float cho tiền. Số thập phân nhị phân không biểu diễn chính xác:

IO.println(0.1 + 0.2);   // 0.30000000000000004

IO.println(new BigDecimal(0.1));
// 0.1000000000000000055511151231257827021181583404541015625  <- dung double la sai luon tu dau

BigDecimal a = new BigDecimal("1.0");
BigDecimal b = new BigDecimal("1.00");
IO.println("equals 1.0 vs 1.00 : " + a.equals(b));            // false - khac scale
IO.println("compareTo == 0     : " + (a.compareTo(b) == 0));   // true  - cung gia tri

try {
    IO.println(new BigDecimal("1").divide(new BigDecimal("3")));
} catch (ArithmeticException e) {
    IO.println("divide nem         : " + e.getMessage());
    // Non-terminating decimal expansion; no exact representable decimal result.
}

IO.println("divide scale 2     : " + new BigDecimal("1").divide(new BigDecimal("3"), 2, RoundingMode.HALF_UP)); // 0.33

BigDecimal gia = new BigDecimal("199000.50");
BigDecimal thue = gia.multiply(new BigDecimal("0.08")).setScale(2, RoundingMode.HALF_UP);
IO.println("thue 8%            : " + thue);   // 15920.04
  • Tạo bằng chuỗi: new BigDecimal("199000"). Truyền double vào là mang sẵn sai số.
  • Cộng trừ nhân chia bằng method: .add(), .subtract(), .multiply(), .divide().
  • divide() không chia hết mà không truyền scale/RoundingMode sẽ ném ArithmeticException.
  • So sánh bằng .compareTo() — equals() so cả scale nên 1.0 ≠ 1.00.
  • Tiền tệ production: setScale(2, RoundingMode.HALF_UP) trước khi lưu/trả API.

14. String & biến Hay hỏi phỏng vấn

String không phải primitive mà là object bất biến. Java có String pool — vùng nhớ chứa các chuỗi literal dùng lại:

String s1 = "java";
String s2 = "java";
String s3 = new String("java");
String s4 = s3.intern();          // dua ve pool

IO.println("s1 == s2        : " + (s1 == s2));      // true  - cung o trong pool
IO.println("s1 == s3        : " + (s1 == s3));      // false - new tao object moi
IO.println("s1 == s4        : " + (s1 == s4));      // true
IO.println("s1.equals(s3)   : " + s1.equals(s3));  // true  - so noi dung
  • Quy tắc bất di bất dịch: so sánh chuỗi luôn dùng .equals(), không dùng ==.
  • String bất biến nên nối chuỗi trong vòng lặp tạo rác — dùng StringBuilder:
StringBuilder sb = new StringBuilder();
for (int i = 1; i <= 3; i++) {
    sb.append("dong ").append(i).append("\n");
}
IO.println(sb.toString());
Chủ đề String còn rất nhiều (StringBuilder vs StringBuffer, các method, format, text blocks, regex...) — đã có doc riêng: Strings chuyên sâu (1.7).

Production không viết cứng URL, port, mật khẩu trong code. Đọc từ biến môi trường hoặc file cấu hình với giá trị mặc định:

Chạy thử: APP_PORT=9090 java ProductionDemo.java → in ra Port: 9090. Spring Boot sẽ gói phần này lại thành application.properties + @Value/@ConfigurationProperties.

15.3 Thread-safety: static mutable là bẫy lớn Junior+

Node.js chạy một luồng nên ít gặp. Java đa luồng thật, và count++ không phải một phép tính — nó là đọc → cộng → ghi, nên hai thread có thể ghi đè nhau:

public class RaceDemo {
    static int count = 0;                            // NGUY HIEM
    static final AtomicLong atomicCount = new AtomicLong();

    static void tang() {
        for (int i = 0; i < 200_000; i++) {
            count++;                                 // race condition
            atomicCount.incrementAndGet();           // an toan
        }
    }

    public static void main() throws InterruptedException {
        Thread t1 = new Thread(RaceDemo::tang);
        Thread t2 = new Thread(RaceDemo::tang);
        t1.start();
        t2.start();
        t1.join();
        t2.join();
        IO.println("int    : " + count + " (ky vong 400000)");
        IO.println("atomic : " + atomicCount + " (luon dung 400000)");
    }
}

Một lần chạy thật:

int    : 298949 (ky vong 400000)
atomic : 400000 (luon dung 400000)
  • int cho kết quả sai và mỗi lần chạy một khác — đó là race condition.
  • AtomicLong dùng cơ chế CAS (compare-and-swap) nên luôn đúng, hiệu năng tốt hơn synchronized cho counter.
  • volatile chỉ đảm bảo các thread nhìn thấy giá trị mới nhất, không đảm bảo ++ an toàn. Câu chốt phỏng vấn: volatile cho visibility, atomic cho cả visibility lẫn atomicity.
  • Nguyên tắc: hạn chế tối đa static mutable; cần đếm thì dùng AtomicLong.

17. Shallow copy vs deep copy Hay hỏi phỏng vấn Production

Mục 7 đã chốt: Java luôn pass-by-value, với object thì giá trị truyền đi là bản sao địa chỉ — hai biến cùng trỏ một object. Hệ quả thực tế là hai câu hỏi đi làm hằng ngày: thao tác nào ảnh hưởng object gốc? và làm sao copy cho thật sự độc lập?

Thao tác nào ảnh hưởng gốc?

Thao tácẢnh hưởng gốc?Vì sao

order.getItems().add(...)CóGetter trả reference, không copy

Alias và shallow copy

List<String> a = new ArrayList<>(List.of("A"));
List<String> b = a;              // alias, KHONG copy
b.add("B");
IO.println("alias        : " + a);                  // [A, B]

List<String> shallow = new ArrayList<>(a);       // copy nong
shallow.add("C");
IO.println("shallow add  : " + a + " | " + shallow); // [A, B] | [A, B, C]

List<List<String>> outer = new ArrayList<>();
outer.add(new ArrayList<>(List.of("x")));
List<List<String>> outerCopy = new ArrayList<>(outer);
outerCopy.get(0).add("y");                        // list con van dung chung!
IO.println("nested share : " + outer);            // [[x, y]]

new ArrayList<>(list), List.copyOf(list), Arrays.copyOf(arr, n), arr.clone() đều là shallow: tạo vỏ mới nhưng phần tử bên trong vẫn là các reference cũ. Với cấu trúc lồng nhau, sửa list con là sửa cả hai bên.

Deep copy — copy thật sự độc lập

Java không có hàm deep copy dựng sẵn kiểu structuredClone() của JS. Cách production hay dùng nhất là copy constructor / factory tự viết — rõ ràng và kiểm soát được từng field:

static class Order {
    String code;
    List<String> items;

    Order(String code, List<String> items) {
        this.code = code;
        this.items = items;
    }

    Order(Order other) {                       // copy constructor: deep
        this.code = other.code;
        this.items = new ArrayList<>(other.items);
    }
}

Order o1 = new Order("DH1", new ArrayList<>(List.of("Ao")));
Order o2 = new Order(o1);
o2.items.add("Quan");
IO.println("deep copy    : o1=" + o1.items + " | o2=" + o2.items);
// deep copy    : o1=[Ao] | o2=[Ao, Quan]
Cách copySâu?Ghi chú
Copy constructor / factory tự viếtCóKhuyến nghị — kiểm soát từng field, dễ test
Object.clone()Không (mặc định)Phải override và tự copy field object; Cloneable là thiết kế lỗi thời, ít dùng
new ArrayList<>(list), Arrays.copyOf, List.copyOfKhôngCopy vỏ; phần tử vẫn share
Serialization round-tripCóChậm, cần Serializable, không giữ identity — chỉ dùng khi bất đắc dĩ
JSON round-trip (Jackson)CóTiện khi đã có DTO; mất kiểu đặc biệt (Date, Map, identity)
Thiết kế immutable (record + List.copyOf)Không cần copyCách được khuyến nghị nhất trong production

Bẫy: bất biến của record chỉ là nông

record OrderRecord(String code, List<String> items) {}

OrderRecord r1 = new OrderRecord("DH2", new ArrayList<>(List.of("Giay")));
r1.items().add("Dep");                    // record KHONG bao ve list ben trong!
IO.println("record       : " + r1.items());   // [Giay, Dep]

int[][] grid = {{1, 2}, {3, 4}};
int[][] gridClone = grid.clone();         // clone() cung la shallow
gridClone[0][0] = 99;
IO.println("clone 2D     : " + Arrays.deepToString(grid)); // [[99, 2], [3, 4]]
Muốn immutable thật: class/record phải copy phòng thủ khi nhận và khi trả field mutable — constructor làm this.items = List.copyOf(items), getter trả List.copyOf(items). Chi tiết defensive copy sẽ gặp lại ở doc Encapsulation & Immutability (mục 2.2).

Góc Node.js

  • {...obj}, [...arr], Object.assign của JS là shallow — giống new ArrayList<>(list).
  • structuredClone() là deep copy dựng sẵn (trừ function/class method) — Java không có tương đương, phải viết copy constructor hoặc dùng round-trip.
  • JSON.parse(JSON.stringify(obj)) là deep "giả": mất Date, Map, Set, undefined — giống hạn chế của JSON round-trip bên Java.

18. Interview Q&A Hay hỏi phỏng vấn

Cơ bản

Câu 1. Kể tên 8 kiểu nguyên thủy của Java.
byte (8-bit), short (16-bit), int (32-bit), long (64-bit), float (32-bit), double (64-bit), char (16-bit UTF-16), boolean. Mọi thứ khác là reference type. Java không phải pure OOP chính vì còn 8 primitive.
Câu 2. Biến local khác field thế nào về giá trị mặc định?
Field được gán mặc định (0, 0.0, false, '\u0000', null). Biến local không có mặc định — dùng khi chưa gán bị lỗi compile "variable might not have been initialized".
Câu 3. int và Integer khác nhau thế nào?
int là primitive, luôn có giá trị, không null, nhanh và nhẹ. Integer là wrapper object: cho phép null, dùng được trong collections/generics. So sánh Integer bằng == là so địa chỉ — phải dùng .equals().
Câu 4. final dùng để làm gì? Có giống const của JS không?
Giống ở chỗ khoá gán lại. Khác: final chỉ khoá biến trỏ tới object, nội dung object vẫn sửa được (final List vẫn add() được). Java không có từ khóa const.
Câu 5. == và equals() khác nhau thế nào?
== so giá trị với primitive, so địa chỉ (cùng object hay không) với reference. equals() so nội dung, với điều kiện class đó override (String, wrapper, record... đều override sẵn). So sánh String/wrapper luôn dùng .equals().
Câu 6. char và String khác nhau thế nào?
char là primitive 16-bit, bản chất là một con số Unicode, viết nháy đơn 'a', tham gia tính toán như số. String là object bất biến, viết nháy kép "a", là chuỗi ký tự.
Câu 7. Autoboxing / unboxing là gì? Cho ví dụ.
Autoboxing là tự động bọc primitive thành wrapper (Integer x = 5), unboxing là ngược lại (int y = x). Compiler chèn Integer.valueOf()/intValue(). Cần vì collections như List<Integer> chỉ chứa object.
Câu 8. Vì sao không nên dùng double/float cho tiền?
Số thực nhị phân IEEE 754 không biểu diễn chính xác số thập phân: 0.1 + 0.2 = 0.30000000000000004. Sai số tích lũy qua nhiều giao dịch. Tiền tệ luôn dùng BigDecimal và tạo bằng chuỗi.
Câu 9. Khi nào dùng long thay int?
Khi giá trị có thể vượt ~2,1 tỷ: ID auto-increment lớn, snowflake ID, timestamp milli/micro giây, kích thước file. Production mặc định ID và timestamp là long.
Câu 10. var là gì? Nó có biến Java thành ngôn ngữ kiểu động không?
Không. var (Java 10) chỉ là suy luận kiểu local — compiler chốt kiểu ngay lúc compile, sau đó không đổi được. Chỉ dùng cho biến local và bắt buộc có giá trị khởi tạo.

Nâng cao (Junior+)

Câu 11. Integer cache là gì? Vì sao 128 == 128 là false?
Autoboxing gọi Integer.valueOf(), method này cache sẵn các giá trị -128 → 127. Trong khoảng đó hai biến trỏ cùng object nên == true; ngoài khoảng tạo object mới nên == false. Long, Short... cũng có cache tương tự.
Câu 12. Unboxing một Integer đang null thì xảy ra gì?
NullPointerException ngay tại dòng đó, vì compiler chèn x.intValue() — gọi method trên null. Rất hay gặp khi đọc cột DB nullable; phải kiểm tra null trước hoặc dùng Optional.
Câu 13. Stack và Heap khác nhau thế nào? Biến được lưu ở đâu?
Stack: mỗi thread một cái, chứa biến local primitive và địa chỉ object, LIFO, nhanh, tràn thì StackOverflowError. Heap: dùng chung, chứa object thật, do GC quản lý, hết thì OutOfMemoryError. Biến static gắn với class, không thuộc object.
Câu 14. Java pass-by-value hay pass-by-reference?
Luôn pass-by-value. Với object, giá trị được copy là địa chỉ, nên method sửa được nội dung object (add vào list) nhưng gán lại reference (new list) thì bên ngoài không đổi.
Câu 15. String pool / intern là gì?
Pool là vùng nhớ chứa các String literal để tái sử dụng. "java" == "java" là true vì cùng nằm trong pool. new String("java") tạo object mới ngoài pool nên == false; intern() đưa chuỗi về pool.
Câu 16. Numeric promotion là gì? Vì sao 'a' + 1 trả về int?
Khi tính toán, byte/short/char được nâng lên int trước, kết quả cũng là int. Nên 'a' + 1 = 98 (int), muốn thành ký tự 'b' phải ép (char).
Câu 17. Vì sao byte b = 10; b += 5; chạy được mà b = b + 5; không?
Compound assignment (+=) có ngầm ép kiểu do JLS quy định — tương đương b = (byte)(b + 5). Còn b + 5 là int, gán vào byte cần ép tường minh, nếu không compiler báo possible lossy conversion from int to byte.
Câu 18. Tràn số nguyên là gì? Math.addExact để làm gì?
Vượt giới hạn kiểu thì giá trị quay vòng (wraparound) và không có exception: Integer.MAX_VALUE + 1 = -2147483648. Math.addExact/multiplyExact ném ArithmeticException (message integer overflow) để phát hiện sớm.
Câu 19. Blank final là gì?
Biến final khai báo không có giá trị, được gán đúng một lần trong constructor. Mỗi object có giá trị riêng nhưng bất biến sau khi tạo — dùng cho dependency injection, config của object.
Câu 20. final với một List — nội dung có sửa được không?
Được. final chỉ khoá việc gán lại biến, còn list.add() sửa nội dung object vẫn bình thường. Muốn bất biến thật dùng List.of()/List.copyOf() hoặc immutable object.
Câu 21. Effectively final là gì?
Biến local không khai báo final nhưng chỉ được gán đúng một lần — compiler coi như final, cho phép dùng trong lambda/anonymous class. Gán lại lần nữa là lỗi "must be final or effectively final".
Câu 22. volatile khác AtomicLong thế nào?
volatile đảm bảo visibility (thread khác thấy giá trị mới) nhưng ++ vẫn là read-modify-write nên không atomic. AtomicLong dùng CAS đảm bảo cả visibility lẫn atomicity — đúng cho counter.
Câu 23. Vì sao biến static mutable nguy hiểm trong đa luồng?
Static mutable là state dùng chung giữa mọi thread. count++ gồm đọc → cộng → ghi, hai thread xen kẽ sẽ mất cập nhật (race condition) — kết quả mỗi lần chạy một khác. Cách xử lý: tránh static mutable, dùng AtomicLong, synchronized, hoặc chỉ dùng static final immutable.
Câu 24. BigDecimal.equals() khác compareTo()? divide() có thể ném gì?
equals() so cả giá trị lẫn scale nên 1.0 ≠ 1.00; compareTo() so giá trị, trả 0 khi bằng. divide() với phép chia vô hạn (1/3) mà không truyền scale + RoundingMode sẽ ném ArithmeticException: Non-terminating decimal expansion.
Câu 25. Enum có field/method để làm gì? Sao không dùng String constant?
Enum giới hạn đúng tập giá trị hợp lệ (type-safe), gõ sai là lỗi compile; có thể gắn nhãn, giá trị, method riêng cho từng hằng. String constant không giới hạn giá trị, dễ typo, so sánh phải equals — không nên dùng cho trạng thái nghiệp vụ.
Câu 26. Vì sao 1000 * 60 * 60 * 24 * 365 cho kết quả sai? Sửa thế nào?
Vì là phép nhân int: 1000 * 60 * 60 * 24 * 365 = 31.536.000.000, vượt 2,1 tỷ nên tràn trước khi gán vào biến long (nếu có) — kết quả sai là 1471228928. Sửa: 1000L * 60 * 60 * 24 * 365 — bắt đầu bằng long để cả biểu thức tính theo long, ra 31536000000.
Câu 27. static final field khác final field thế nào?
final field: mỗi object một bản, không đổi sau khi tạo. static final: một bản duy nhất dùng chung cho cả class — đây mới là "hằng số" theo đúng nghĩa, tên viết UPPER_SNAKE_CASE.
Câu 28. Shallow copy và deep copy khác nhau thế nào?
Shallow copy tạo object vỏ mới nhưng các field reference vẫn trỏ object cũ (new ArrayList<>(list)). Deep copy tạo luôn object con mới, sửa bản copy không ảnh hưởng gốc (copy constructor tự viết). Mọi cách copy có sẵn trong JDK (clone, Arrays.copyOf, List.copyOf) đều là shallow.
Câu 29. Java có sẵn hàm deep copy như structuredClone() của JS không? Làm sao deep copy?
Không có. Cách production: viết copy constructor/factory method copy từng field (khuyến nghị); hoặc serialization/JSON round-trip (chậm, mất kiểu, không giữ identity). Object.clone() mặc định chỉ shallow. Cách tốt nhất vẫn là thiết kế bất biến để không cần deep copy.
Câu 30. Record có bất biến sâu không?
Không. Record chỉ khoá việc gán lại field; nếu record chứa List, Map hay object mutable thì nội dung đó vẫn sửa được (r.items().add(...) chạy bình thường). Muốn bất biến thật phải copy phòng thủ trong constructor và getter: List.copyOf(items).

Quy tắc: tự đoán kết quả rồi mới mở đáp án. Tất cả bài dưới đây đã được chạy thật bằng JDK 25.

Bài 1 
IO.println(1 + 2 + "3" + 4 + 5);
In ra 3345. Vì 1 + 2 = 3 (còn là int), gặp chuỗi "3" thì từ đó về sau là nối chuỗi: "3" + 4 + 5 → "345", ghép lại thành 3345.
Bài 2 
char c = 'a';
c++;
IO.println(c);
IO.println(c + 1);
In ra b rồi 99. c++ tăng ký tự lên 'b'; dòng sau c + 1 là phép cộng số nên ra 98 + 1 = 99 (int), không phải ký tự.
Bài 3 
Integer a = 127, b = 127;
Integer d = 128, e = 128;
IO.println((a == b) + " " + (d == e));
In ra true false. 127 nằm trong cache -128..127 nên cùng object; 128 ngoài cache nên hai object khác nhau, == false.
Bài 4 
IO.println(0.1 + 0.2 == 0.3);
In ra false. 0.1 + 0.2 ra 0.30000000000000004 do sai số IEEE 754. Đây là lý do tiền phải dùng BigDecimal.
Bài 5 
byte by = 10;
by += 5;
IO.println(by);
In ra 15. += có ngầm ép kiểu về byte nên chạy được (nếu viết by = by + 5; sẽ lỗi compile).
Bài 6 
IO.println(5 / 2);
IO.println(5 / 2.0);
IO.println(5 % 2);
In ra 2, 2.5, 1. Chia hai số nguyên là chia nguyên (cắt phần thập phân); có một số double thì ra double; % là chia lấy dư.
Bài 7 
int x = Integer.MAX_VALUE;
IO.println(x + 1);
In ra -2147483648 — tràn số quay vòng, không có exception.
Bài 8 
long x = 1 * 1000 * 1000 * 1000 * 5;
IO.println(x);
In ra 705032704. Cả biểu thức tính bằng int nên tràn trước khi gán vào long. Sửa: 1L * ....
Bài 9 
Integer n = null;
IO.println(n + 1);
Ném NullPointerException khi unbox n để cộng. Cách sửa: kiểm tra null trước hoặc dùng giá trị mặc định.
Bài 10 
final List<String> list = new ArrayList<>();
list.add("a");
IO.println(list);
In ra [a] — chạy bình thường. final khoá gán lại biến, không khoá sửa nội dung list.
Bài 11 
IO.println('a' + 1);
IO.println("" + 'a' + 1);
In ra 98 rồi a1. Dòng đầu là cộng số (char nâng lên int). Dòng sau có chuỗi "" nên thành nối chuỗi.
Bài 12 
String s1 = "java";
String s2 = new String("java");
IO.println(s1 == s2);
IO.println(s1.equals(s2));
In ra false rồi true. new String tạo object ngoài pool nên == false; equals so nội dung nên true.
Bài 13 
int octal = 010;
IO.println(octal);
In ra 8. Số bắt đầu bằng 0 là hệ 8 (octal): 010 = 0*64 + 1*8 + 0 = 8.
Bài 14 
BigDecimal a = new BigDecimal("1.0");
BigDecimal b = new BigDecimal("1.00");
IO.println(a.equals(b));
IO.println(a.compareTo(b) == 0);
In ra false rồi true. equals so cả scale (1.0 khác 1.00), compareTo so giá trị nên bằng nhau.
Bài 15 
List<List<Integer>> outer = new ArrayList<>();
outer.add(new ArrayList<>(List.of(1)));
List<List<Integer>> copy = new ArrayList<>(outer);
copy.get(0).add(2);
copy.add(new ArrayList<>(List.of(9)));
IO.println(outer);
IO.println(copy);
In ra [[1, 2]] rồi [[1, 2], [9]]. new ArrayList<>(outer) chỉ copy lớp ngoài: thêm phần tử vào copy không ảnh hưởng outer, nhưng sửa list con (copy.get(0).add(2)) thì ảnh hưởng vì list con dùng chung.
Bài 16 
int[][] x = {{1}, {2}};
int[][] y = Arrays.copyOf(x, x.length);
y[0][0] = 9;
y[1] = new int[]{7};
IO.println(Arrays.deepToString(x));
IO.println(Arrays.deepToString(y));
In ra [[9], [2]] rồi [[9], [7]]. copyOf là shallow: hàng 0 dùng chung nên y[0][0] = 9 sửa luôn x; còn y[1] = new int[]{7} chỉ thay reference ở mảng copy (gán lại) nên x[1] vẫn là 2.

20. Cheat sheet & checklist

Cheat sheet

Việc cần làmCách viết
Khai báo thườngint x = 5; · String s = "a";
Hằng sốpublic static final int MAX = 10;
Giá trị mặc địnhField: 0 / false / null · Local: không có, phải gán
Chọn kiểu theo mục đíchID: long · Tiền: BigDecimal · Thời gian: Instant · Trạng thái: enum

Checklist tự đánh giá trước phỏng vấn

  • Kể vanh vách 8 primitive + size + default value.
  • Giải thích được vì sao biến local không có default.
  • Phân biệt == vs equals và lấy ví dụ String / Integer cache.
  • Giải thích được 'a' + 1 là 98 và b += 5 khác b = b + 5 thế nào.
  • Kể được 3 bẫy tràn số và cách phòng.
  • Giải thích final reference, blank final, effectively final.
  • Phân biệt stack vs heap, pass-by-value với object.
  • Trình bày được vì sao không dùng double cho tiền, BigDecimal dùng thế nào.
  • Giải thích race condition của static counter và cách dùng AtomicLong.
  • Biết map các kiểu DB thường gặp sang Java.
  • Phân biệt alias, shallow copy, deep copy và biết cách deep copy an toàn.
