Giai đoạn 4 — Production essentials

Góc Node.js: JavaScript thông thường chạy trên thread của event loop, còn Node.js có thêm worker pool cho một số tác vụ như file I/O, crypto và nén (tác vụ tính toán nặng trong JS không tự chuyển sang pool); trong Java nhiều request chạy song song trên nhiều thread và cùng truy cập object, nên phải học bảo vệ shared state. Promise + chuỗi xử lý bất đồng bộ tương ứng CompletableFuture (callback hell là vấn đề tổ chức code, không có API tương ứng). Virtual threads cho phép viết code blocking mà vẫn scale. npm scripts/CI tương ứng Maven lifecycle + GitHub Actions.

  • Scoped Values (final ở JDK 25) và Structured Concurrency (vẫn preview) mức nhận biết

Giai đoạn 5 — Backend stack (đích công việc)

Góc Node.js: Express router ↔ Spring controller; middleware ↔ filter/interceptor (khác về thứ tự và scope); JSON.parse ↔ Jackson; ORM kiểu Mongoose/Prisma ↔ JPA/Hibernate (khác ở transaction và lazy loading). Đừng mang tư duy "mọi thứ async" sang Java — ở đây luồng chạy tuần tự trong một request cho tới khi bạn chủ động tách thread.
5.1 HTTP & RESTTiếp theo
Phỏng vấn: cao · Production: bắt buộc
  • Request/response, methods, status codes, headers, cookies
  • REST conventions: resource, versioning, pagination, idempotency
  • JSON; test API bằng curl/Postman
5.2 JSON & JacksonChưa học
Phỏng vấn: cao · Production: bắt buộc — nền Spring Boot 4.1 dùng Jackson 3 (tools.jackson, JsonMapper bất biến); Boot 3.5 vẫn là Jackson 2 (com.fasterxml.jackson, ObjectMapper)
  • Đọc/ghi JSON: Jackson 3 dùng JsonMapper bất biến (Jackson 2: ObjectMapper); cấu hình fail-on-unknown
  • Map record/DTO ↔ JSON: @JsonProperty, @JsonIgnore (annotation vẫn ở com.fasterxml.jackson.annotation), snake_case vs camelCase
  • Ngày giờ: Jackson 3 mặc định ISO-8601 (java.time hỗ trợ sẵn); BigDecimal trong JSON — bẫy mất precision
  • JSON lồng nhau, generic TypeReference; cây JSON với JsonNode
  • Bẫy: field thiếu/null, vòng lặp tham chiếu khi serialize entity, JSON injection
5.3 SQL & PostgreSQLChưa học
Phỏng vấn: rất cao · Production: bắt buộc

  • JOIN các loại; subquery; UNION
  • Index (B-tree), khi nào index không được dùng; EXPLAIN mức nhận biết
  • Transaction & ACID; isolation levels mức nhận biết; lock cơ bản
  • Normalization; thiết kế schema; migration với Flyway/Liquibase
5.4 Spring CoreChưa học

5.5 Spring Boot & REST API (nền: Boot 4.1)Chưa học
Phỏng vấn: rất cao · Production: bắt buộc · Ví dụ dùng Spring Boot 4.1 + Java 25; Boot 3.5 dùng Jackson 2, HTTP Interface Client phải cấu hình thủ công; Boot 4 bổ sung auto-configuration cho HTTP Service Clients và API versioning tích hợp
  • Auto-configuration và điều kiện (@ConditionalOnMissingBean) mức hiểu cơ chế
  • Kiến trúc 3 lớp: Controller → Service → Repository; DTO mapping (MapStruct mức nhận biết)
  • REST API: @RestController, @RequestMapping, DTO, ResponseEntity; API versioning
  • Validation (Bean Validation); xử lý lỗi tập trung @ControllerAdvice
  • Config: @ConfigurationProperties vs @Value; profiles; application.yml; actuator
  • Gọi service khác: RestClient/WebClient; HTTP Interface Client (@HttpExchange) — Boot 3.5 cấu hình thủ công qua HttpServiceProxyFactory, Boot 4 auto-config; timeout, retry
  • Lombok mức nhận biết — bẫy @Data trên JPA entity
  • Testing Spring: @SpringBootTest vs slice test (@WebMvcTest, @DataJpaTest); MockMvc
  • API docs: springdoc-openapi/Swagger mức nhận biết
5.6 JDBC → JPA/Hibernate → Spring Data JPAChưa học
Phỏng vấn: cao · Production: bắt buộc · Học sau Spring Core để hiểu bean, proxy và @Transactional

  • ORM concept; entity mapping & entity lifecycle; quan hệ 1-1/1-N/N-N
  • Repository; JPQL; derived query; phân trang với Pageable/Specification mức nhận biết
  • N+1 problem (câu hỏi phỏng vấn rất hay); fetch type; cascade; @EntityGraph
  • @Transactional: rollback, transaction trong service layer, propagation/isolation mức nhận biết
  • Dirty checking, first/second-level cache; optimistic locking @Version vs pessimistic lock

5.9 Nâng cao (chỉ cần biết để phỏng vấn không "trắng")Tùy chọn

  • Redis cache; message broker Kafka/RabbitMQ (khái niệm, use case)
  • Microservices: service discovery, API gateway, resilience (khái niệm)
  • WebFlux / reactive (khác gì Spring MVC); cloud cơ bản (AWS/GCP)
Milestone giai đoạn 5: REST API CRUD hoàn chỉnh (Spring Boot + PostgreSQL + JWT + validation + test + Docker + README), deploy được, có Postman collection. Phải xử lý được 5 tình huống kiểm chứng năng lực:
  • Tạo đơn hàng thất bại giữa chừng — dữ liệu có rollback đúng không?
  • Hai request cùng mua sản phẩm cuối cùng — có bán vượt tồn kho không?
  • Client gửi lại request tạo đơn — có tạo đơn trùng không (idempotency)?
  • Người dùng A truy cập đơn của B — có chặn đúng không (authorization)?
  • API chậm — có tìm được nguyên nhân từ log và query SQL (EXPLAIN) không?

6.6 System design cơ bảnTùy chọn
Mức Junior+: hiểu khái niệm, không cần vẽ kiến trúc phức tạp
  • Load balancing, caching, database replication (khái niệm)
  • Bài tập quen thuộc: URL shortener, rate limiting, pagination, idempotency

Tiêu chí sẵn sàng phỏng vấn Junior+

  • Giải thích được 4 tính chất OOP kèm ví dụ code tự viết.
  • Phân biệt abstract class vs interface và chọn đúng trong tình huống cụ thể.
  • Trình bày HashMap hoạt động thế nào, equals/hashCode liên quan ra sao.
  • So sánh ArrayList vs LinkedList, HashSet vs TreeSet kèm Big-O.
  • Viết được Stream pipeline có groupingBy mà không cần tra Google.
  • Phân biệt checked/unchecked exception và cách xử lý đúng.
  • Giải thích race condition, synchronized vs volatile vs Atomic.
  • Viết unit test JUnit + Mockito cho service cơ bản.
  • Viết được REST API Spring Boot có validation và xử lý lỗi tập trung.
  • Viết được query SQL có JOIN + GROUP BY; giải thích index dùng để làm gì.
  • Kể được 1 project có DB, test, Docker — nêu được 2-3 trade-off.
  • Giải LeetCode medium trong 30–40 phút, nói được độ phức tạp.

Các mốc trên là định hướng tham khảo, không phải chuẩn chung — mỗi vị trí và thị trường hỏi khác nhau. Điều nhà tuyển dụng chấm là project thật và khả năng giải thích trade-off, không phải số bài LeetCode.
